# PLAN — V0.2 总计划（里程碑 E~K）

> 当前进度看 `PROGRESS.md`。这份文件只描述**要做什么、怎么验收**，不记录状态。
> 里程碑编号接着 V0.1 的 A~D 往下排。

**总目标**：把 V0.1 的 localhost 假服务端改造成**真正的多人服务端**，
同一套代码既能当单机假服务器（客户端包自带）、又能部署到阿里云 / AWS。
玩家在原版登录界面自己选「单机游玩」还是「联机」。

**最终产物是两个包**：

| 包 | 给谁 | 内容 |
|---|---|---|
| 客户端包 | 普通玩家 | 客户端 + 假服务器 + `server.config`，启停脚本仍是 3 个 |
| 服务端包 | 开服的人 | 只有服务端 + `start.bat`/`start.sh`/`stop.bat`/`stop.sh` + 两份独立 Python 运行时 |

**已定的三个前置选择**（与用户确认，见 D061/D062/D063）：

| 问题 | 结论 |
|---|---|
| 战斗内同步走 P2P UDP 还是服务端中继 | **先探查（J1），拿实测结论回来找用户拍板（J2）** |
| 服务端包的 Python 运行时 | **Windows / Linux 两边都自带独立运行时** |
| 客户端包里「单机游玩」的本地服务端监听地址 | **和云端一样监听 `::`** |

## 里程碑 J — 战斗内联机（先探查，再定方案）

### J.1 探查

查清「多个客户端在同一局里怎么互相看到对方的位置和动作」。已知线索：

```text
re/packets.txt      Packet_gcpStartTcpRelay / Packet_gspJoinRelay
re/rtti_types.txt   RelayConnection / RelayAuthData / UDPBinder / UdpPacket
                    Packet_gspToggleUdpClientCommunication / Packet_gspToggleSendReplay
                    Packet_rcpRegister / Packet_rcpRepPing
V0.1 §45            0x00xx 段 = RelayConnection 用（0x0000/0x0001/0x0003）
V0.1 PROGRESS       「真正的角色位置同步包还没找到」—— 因为它根本不在 gcp/gsp 里
V0.1 §44            gcpReqLogin 载荷里带着客户端的**内网 IP** → 强烈暗示 P2P
```

手段：`re/rtti_types.txt` 搜类名 → `re/vftables.json` 拿 vftable →
`tools/re_bs.py xref` 找发送点 → 紧跟的 `push <opcode>` 就是包号；
`bshook` 加 `sendto`/`recvfrom`/`WSASendTo`/`bind` hook 实测有没有 UDP 流量。

**产出**：写进 `FINDINGS.md` 的结论 + 各方案要实现哪些包。

### J.2 决策点 ⛳ 停下来问用户

给出「服务端实现 TCP 中继」和「只保证局域网 P2P」的实测代价对比，由用户拍板。

### J.3 实现

无论走哪条路都要做：

- 开局链多人化：房间里所有人各自走 `0x0402 → 0x0401 / 0x0400 → 0x0403 → 0x0402`，
  **所有人加载完成才放行**
- 战斗回显改成房间广播：死亡 `0x0408→0x0406`、重生 `0x0413→0x0419`、
  掉落 `0x0406→0x0404`、拾取 `0x0407→0x0405`（一件东西只能被一个人捡到，**服务端仲裁**）、
  分数 `0x0410→0x0415`、换图 `0x0411→0x0417` + `0x0412→0x0418`（等所有人加载完）
- 结算 `0x040f → 0x0309 + 0x0411`：每个座位一份数值
- 对战模式（session type 1）的胜负判定与 `gspRepQuestRecordInPvp`
- 战斗中的聊天走同一条 `0x0305`

⚠ 全程盯 `0x0106 gcpReportHack`（V0.1 §88：免费的正确性检查器，比截图快、比「没崩」严格）。

**⏳ 用户操作**：两台电脑同一个房间，任务模式合作打完一关 + 对战模式打完一局。
