## 踩到的坑（都写进 §163）

1. **MSYS 的 `tar` 把 `D:\...` 当远程主机**（`Cannot connect to D: resolve failed`）。
   `Get-Command tar` 在装了 Git 的机器上拿到的是它。改成写死
   `%SystemRoot%\System32\tar.exe`。
2. **`.bat` 的真正约束是「纯 ASCII」，不是「不许 `chcp 65001`」**。
   一开始照抄旧 `build-portable.bat` 的注释没加 `chcp`，结果管道里的中文
   全是乱码。`start.bat` 三兄弟一直都带着 `chcp 65001` 且工作正常。
3. **「共用服务端代码」哈希第一版把 `relay.py` 也算进去了**，导致两个包的
   哈希永远对不上（服务端包没有 `relay.py`）—— `BUILD.txt` 上那句
   「两边这一行要一模一样」当场就是假的。改成算哈希时排除它。
4. 冒烟自检跑完会在包里留下 `__pycache__`，加了清理。
5. **★ `-LinuxRuntime download` 第一次跑就炸了**（用户实测报回来的）：报
   「SHA256SUMS 里没有 xxx 这一条」，看着像上游漏发校验和，其实是
   `Invoke-WebRequest -UseBasicParsing` 对 `application/octet-stream` 返回的
   `.Content` 是 **`Byte[]` 不是字符串**，`-split "`n"` 在逐字节切（§164）。
   顺带暴露另外三条：挑资产时会选中 **3.15.0rc1 预发布版**；校验失败的 35 MiB
   文件**留在了缓存里**（下次 `auto` 会把没验过的东西打进包）；
   `Sort-Object { $Matches[1] }` 拿到的是上一次 match 的结果。四条全修了。

## 追加：Linux 运行时改存进项目 + `.gitignore`（同一会话，用户要求）

### 1. 「下载一次存进项目」

用户：「不要每次打包都联网重新下载，只需要下载一次保存到本项目里，
每次打包就 copy 之前下好的就可以，就像以前的 runtime 目录一样。」

- 新建 **`runtime-linux\`**（和 `runtime\` 同构）：`.tar.gz` + `.sha256` 旁证
  + `README.md`（版本 / 来源 / 哈希 / 为什么不解压 / 怎么换版本）；
- 打包脚本从 `tools\_dl\` 改成从 `runtime-linux\` 取；`download` 变成
  「项目里没有才下，下完存进项目」。记为 **D090**。
- 实测：`auto` 和 `download` 两条路都直接用项目里那份，**一次网都没联**
  （`download` 连「查询最新发布」那行都不打了）。

### 2. `.gitignore`

用户拍板（**D091**）：`game_patched` 要传；`game_org` / `原版安装包` /
`Pack_decrypt` 已在别的分支保存，不并进 main；`game_patched` 里每次运行会变的
东西要排掉。仓库体积从约 1.9 GB 降到约 700 MB。

**踩到 §165**：给规则写了行尾中文注释，**五条 `game_patched` 规则全废** ——
gitignore 只认整行注释。而且 `Dump/` 那条**看起来是生效的**，因为 `*.mdmp`
另有一条通用规则兜着 —— 只验一条就会得出错误结论。
改法：说明全部挪到单独的行；并用 scratchpad 里的镜像 repo +
`git check-ignore` 把 60 条路径逐条问了一遍（忽略 14 条 / 提交 46 条，全部符合预期）。

### 3. 顺带补的一个洞

根目录 `server.config` 不进仓库（玩家自己填的地址），但
`build-portable.ps1` 原本**要求**它存在 —— 新 clone 下来会直接打包失败。
改成「不在就照 `server\config.py` 的 `DEFAULT_CONFIG_TEXT` 现生成」，
并把本机那份临时改名实测了一遍。

### 4. ★ 用户凭 V0.1 的印象逼出的一个错误：`UserConfig.ini` 不能忽略

用户问「UserConfig.ini 没有的话初次运行是否会报错？我印象中 v0.1 时有过这个问题」。
查 V0.1 §49 / D021 —— **印象是对的，而且比「报错」更糟**：

> 文件不在 -> 用内置默认值（全屏 + 16 位色）-> 现代 N 卡不报告任何 16 位色模式
> -> `GetAdapterModeCount` 返回 0 -> `dec eax` 下溢成 0xFFFFFFFF ->
> 循环上界 42.9 亿，每轮还调一次 D3D API -> **要跑 40 多分钟，表现就是开局卡死**。

V0.1 的 PROGRESS 里甚至有一句直接针对这次操作的话：
「这个文件是客户端登录成功时才生成的，**删掉它就会退回全屏默认值再次中招**」。

我把它当成「每次运行都会变的本机杂项」排掉了 —— **判据用错了**。
正确的判据是「缺了它构建产物还对不对」，而它就是 V0.1 §49 的修复本身。

改了三处：
1. `.gitignore` 去掉那条，并写了一整段说明为什么**不能**忽略；
2. `build-portable.ps1` 加**打包闸**：文件不在 -> 中止并给出补救步骤；
   `ColorDepth≠1` -> 中止；`FullScreen≠1` -> 只警告（§49 说两条各自都能避开）。
   三种情况都实测过，且确认还原后的 `UserConfig.ini` 与成品包里那份**逐字节一致**；
3. D091 修正 + FINDINGS §165 补了这条判据。
