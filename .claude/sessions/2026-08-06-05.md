# 会话 05 — 2026-08-06

## 起点

接会话 04：认证服（47611 / NMCO）已跑通，客户端会连下一跳 `222.73.209.12:27799`
并发来 4 字节 `53 72 8f 7f` 然后停住。交接结论是「27799 = gcp/gsp + SnowCipher，
缺密钥来源，得回到 BigShot.exe 上动态 hook」。

## 做了什么

### 1. ★★★ 答案本来就在会话 04 自己的日志里

翻 `logs/bshook_20260806_134427_pid24392.log` 时看到，`connect 27799` 的下一行就是：

```
SNOW ★Simple::Encrypt#1 this=1F974D2C dst=0019F908 src=0019F908 len=4
SNOW 入 (4 bytes)   37 01 00 00
```

**是 SimpleCipher，不是 SnowCipher**；明文 `37 01 00 00` = 311 = 版本号。
会话 04 只看到「连上 27799 抓到 4 字节」就收工了，往下再看四行就是答案。

**教训**：日志抓了就要看完，尤其是「我以为这次没抓到有用东西」的那份。

### 2. 反解 SimpleCipher 的初始状态

`53 72 8f 7f` 减 `37 01 00 00` 的差，在 tblA(49) × tblB(24) 里暴搜起始下标，
**唯一解 (i1=0, i2=1)**。回头去看 `TcpConnection` 构造函数 `0x5bc798`，
两个 cipher 的初值明明白白写着：发送 `(0,1)` / 接收 `(5,3)`。
—— 先暴搜拿到答案，再回静态代码确认，两边对上（D015 的老套路）。

### 3. 帧格式 + opcode 表

顺着接收循环 `0x5bcb19` 读出**两种帧**（`0xFE` 4 字节头 / `0xFF` 10 字节头），
opcode 在包缓冲 `+8`。

然后发现 `RawPacket::SetType(u16) = 0x5bba0a` 被 109 处调用 ——
每处往前找 `push imm` 就是 opcode，往附近找 vftable 就是类名。
**一次扫描拿到 94 个 opcode、45 个类名**（`tools/gcp_opcodes.py`）。
这跟会话 04 在 nmconew.dll 里枚举 `CNMFunc` 构造是同一个套路。

### 4. ★★★ gameserver.py 跑通登录

只回两包：`0xFE {int32 0}` 和 `0x0100 gspRepLogin{字段全 0}`，客户端就：
发 `gcpReqLogin` → 收下应答 → **把 `LastLoginId=testuser` 写进 `UserConfig.ini`**。
D019「全填 0 先让结构对上」第三次奏效。

### 5. ★★★ 卡了最久的一段：登录成功但主窗口不显示

现象很像「还缺某个包」：登录框消失、主窗口 `MoleWnd` 存在但不可见、
CPU 占满一个核、磁盘读为 0、客户端不再发任何包。

一开始往协议方向查了不少（读 `0x54e036` 分发表、找 `[conn+0x894]` 的置位点、
读 `0x410950` 那个 `Sleep(50)` 等待循环的四个退出条件）——
**方向错了，那些条件其实早就满足了**。

转折点是写了 `tools/thread_stacks.py`：64 位 Python 用 `Wow64GetThreadContext`
从外部采样 32 位进程的 EIP + EBP 链。一次就看到主线程栈固定是

```
d3d9.dll <- BigShot+0x1bfb85 <- BigShot+0xd4c9 <- ...
```

即在反复调 `IDirect3D9::EnumAdapterModes`。再写个小脚本直接读那一帧的局部变量：

```
i = 228,007,655 -> 232,518,464     总数 = 4294967295     目标 = 1024x768
```

**`GetAdapterModeCount` 返回 0（现代驱动没有 16 位色模式），
客户端 `dec eax` 下溢成 0xFFFFFFFF，于是要跑 42 亿次。**

这不是协议问题，是客户端在现代显卡上的兼容 bug。

### 6. 修复：改两行 ini，不打补丁

`UserConfig.ini` 是客户端**登录成功那一刻才写出来的** ——
所以首次运行用的是内置默认值（全屏 + 16 位色），必然中招。
现在文件有了，改成 `FullScreen=0` + `ColorDepth=1` 再跑：

**主窗口 1024x768 显示、D3D 设备创建成功、大厅完整渲染。**

### 7. ★★★★ 大厅 → 训练场

大厅弹「新手向导：欢迎来到炮炮火枪手的世界！我们已经为你准备了射击教学课程」。
UI 是 D3D 自绘的，`gui_probe.py` 点不了，写了 `tools/click.py`（真鼠标）。

点「确认」→ **客户端直接开始加载训练场**（「正在载入 26%」）→ 加载完成 →
角色带血条站在训练场地图上，NPC 教官讲解、WASD + 鼠标键位教学、教到哪个键哪个键高亮。

**服务端全程只回了那两包。**这坐实了 FINDINGS §12：闯关/训练场内容在客户端本地。

进大厅后客户端每 10 秒轮询 `0x0200 gcpReqListSession` / `0x020d gcpReqUserList` / `0x0700`，
全被我们忽略也不影响。
