## ① 延迟：链路上已经没有可优化的空间了（§187）

数据源 = 用户 14:47~14:57 那一整局（`logs/server.out` 2.1 MB 逐包 + `online.log`）。
连接 #1 = `testuser1`@127.0.0.1（服务器本机，「本机服务器」直连）；
#2 = `testuser2`@192.168.11.253（局域网另一台，「远程服务器」，过它自己的 relay.py）。
对战局 121.9 秒。

| 项 | 数字 |
|---|---|
| 服务端 `recv → sendall` | p95 **0.5 ms**（debug）/ **0.1 ms**（精简），max 2.4 ms |
| 同步到达间隔 | #1 p50 **128 ms**（p95 130，**0 次 >150 ms**）/ #2 p50 **114 ms**（8 次 >150，max 330）|
| 我们能碰的那几段 | **加起来 < 1 ms** |

**结论：99% 的预算是客户端自己那发 100 ms 心跳，链路只占 0.5%。**

三条新查明的事：

1. ★ **整局 2192 发 `0x040e` 里，内层 opcode `5` 一发都没有** ——
   §181「位置/速度是内层 5」那条**在玩家角色这条路上不成立**。
   位置就在 `0x4001` 心跳的 body 里（逐发比对相邻心跳，三处 u16 平滑变化；
   站着不动时整包字节完全相同）。⇒ 对方位置每 100~130 ms 才刷新一次，
   而开火判定在开火者那台机器上做 ⇒「看着躲过子弹还是被打中」的全部来源。
2. ★ **心跳实际周期 = ceil(100 ms / 帧时间) × 帧时间**。#2 跑 60 FPS ⇒ 100 ms；
   #1 只有 ~31 FPS ⇒ **128 ms**。把 #1 拉到 60 FPS 白捡 28 ms，**零协议改动**。
3. ★ 那一局**原版 TCP 中继一次都没建起来**（`0x0310` 每座位节流 10 秒，
   而他们进房 4.4 秒后就开局）⇒ ⏳ 第 21 条要的 `中继 RTT` 一行都没有，
   **不是代码坏了**。要量必须先在房里待够 10 秒。

顺手把热路径上两处白算的日志字符串改成惰性（`send()` 的 hexdump **18.4 µs/发**、
`on_game_packet` 的试解 1.4 µs/发）。⚠ 占端到端预算 0.015%，**不当成优化报**。

⇒ 再往下动就要改原版行为了，登记成 ⏳ 第 23 条让用户拍板（A：查 31 FPS；
B：改心跳 100 ms 常量）。

## ② 注册页防批量注册（§188 / D107）

- `server.config` 加 `register_cooldown_seconds`（默认 60，`0` = 关）。
  ★ 端口和秒数**合法区间不同**，`_INT_KEYS` 拆成 `_PORT_KEYS` / `_SECOND_KEYS`。
- `RegisterRateLimiter`：`{IP: 解禁时刻}` + 锁 + 每次访问顺手 prune，**只在内存**。
  `clock` 可注入 ⇒ 测试用假时钟，不 sleep。
- ★ **限流查询排在 `_api_register` 最前面** —— 放在重名判断之后的话，
  「已存在」和「频率超限」两种回话不一样 ⇒ 变成免费的账号枚举接口。
- ★ **只有成功才计时**：打错一个字罚等一分钟，损失全在好人这边。
- 前台：`localStorage` 存绝对解禁时刻、250 ms 一跳、**读回来时要夹上限**
  （配置调小 / 系统时间被拨过 ⇒ 否则永远解不开）。
- 真浏览器验过五条（成功锁 / F5 后仍锁 / 清 localStorage 也绕不开 /
  失败立刻解锁 / 到点自动解锁），控制台 0 报错。

## ③ 反向代理下的客户端 IP（§189 / D108）—— 用户追问后补的

`self.client_address` 是**上一跳**的地址。**实测复现**（二十行假 nginx + 真注册页）：
两个不同玩家先后注册，第二个被「这个 IP 刚注册过」冤枉挡住，
限流表里只有一个键 `127.0.0.1` ⇒ ② 那条限制退化成
**「整台服务器 60 秒一个号」，比没有限制更糟**。

agent 先做了一版 `register_trusted_proxies` 可信名单，**用户明确否掉配置项**。
改成零配置的固定优先级：

```text
1. X-Forwarded-For   ┐ 只有 TCP 对端是环回/私网/链路本地时才看
2. X-Real-IP         ┘
3. TCP 对端
```

判据成立的依据是一个物理事实：**公网上的客户端不可能以内网地址连到我们**。
`X-Forwarded-For` 内部**从右往左**找第一个公网地址（每跳代理是把「它看到的对端」
追加到链尾；从左往右取 = 直接采信客户端塞进来的伪造值）。

⚠⚠ **踩到一个大坑**：`203.0.113.x` / `198.51.100.x` / `192.0.2.x` 这三段 RFC 文档
示例地址，在 Python 的 `ipaddress` 里 **`is_private == True`**。拿它们当「公网客户端」
写用例，测出来全是反的 —— **一次红了 5 条**。已改用 `9.9.9.9` / `8.8.4.4`，
并在测试类里写了注释钉住。

已知代价（写进 README，没藏）：同机 / 同局域网的人可以伪造那个头绕过冷却
（实测确认）；公网 CDN 在最前面时不生效；游戏那三个裸 TCP 端口没有这种头。
