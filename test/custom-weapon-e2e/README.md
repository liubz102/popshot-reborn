# `test/custom-weapon-e2e/` —— 18 把自定义武器的参数端到端验证

**这不是单元测试，`test/run_tests.py` 不会跑它，只在需要时手动跑。**

`run_tests.all_modules()` 是「现扫 `test/` 顶层的 `test_*.py`」得到名单的
（`test/run_tests.py:98`）—— 这个目录既不以 `test_` 开头也不是 `.py`，
所以天然进不了全量，**不用改 `run_tests.py`，也不要给这里的文件起 `test_` 开头的名字**。

---

## 它在验什么

自定义武器的数值链是：

```text
weapons.json → weaponcfg.effective() → 0x0F01 → bshook 写进客户端内存
```

前三跳单测都盖得住，**最后一跳盖不住** —— 而它恰恰是最容易出错的一段：
`weapon.ini` 每次进图都重读、闯关还有第二条合并路径（§44）、模式由服务端在
开局握手里说（§42 / D32）、mask 为 0 的格 hook 会写回自己缓存的原值。

所以这里**批量设参数 → 真开一局 → 从外部 `ReadProcessMemory` 逐格核对**。
判据是那条 596 字节记录里的每一格字节，不是「看起来对不对」。

> ⚠ 光看 `logs/bshook_*.log` 验不了：它的「回读」只有**第一条记录的 2 格**
> （`Damage` / `MagazineCount`），另外 12 格一个字都没说。

## 怎么跑

前提：`start.bat` 已经把服务端和客户端起起来了；客户端停在登录框或已登录都行。

```powershell
# 只跑离线部分（不碰客户端，几秒钟）
C:\Python314\python.exe test\custom-weapon-e2e\run.py --selftest

# 跑全量（★ 独占这台机器 20~30 分钟，游戏窗口必须保持前台）
C:\Python314\python.exe test\custom-weapon-e2e\run.py

# 只跑其中几条
C:\Python314\python.exe test\custom-weapon-e2e\run.py --only T1 T2

# 只把用户原来的 weapons.json 放回去
C:\Python314\python.exe test\custom-weapon-e2e\run.py --restore
```

★ **跑的时候别动鼠标键盘、别切窗口。** 大厅和房间是 D3D 自绘的，只能真挪鼠标去点；
`keybd_event` 打到的是**当前前台窗口**，焦点一被抢走按键就悄悄丢了。
脚本每次发按键前都会核一遍前台窗口，抢不回来会当场失败而不是装作成功。

产物：

| 东西 | 在哪 |
|---|---|
| 报告（逐格不一致明细）| `logs/e2e-report-<时刻>.md` |
| 每次开局后的整表快照 | `logs/e2e-dumps/*.json` |
| 每一步的截图（失败取证）| `logs/e2e-shots/*.png` |
| 跑之前的数据备份 | `logs/e2e-backup-<时刻>/` |

## 文件

| 文件 | 干什么 |
|---|---|
| `wtab.py` | **从外部读客户端的武器表**。遍历 `0x72E788` 那棵哈希表，按 14 格偏移/类型解出来；另含「持枪器」弹匣快照。可以单独当探针跑：`python wtab.py --holders` |
| `params.py` | 四套测试参数集的**生成器**（按 `weaponcfg.FIELDS` 的 min/max 现算）。`python params.py A` 看一套长什么样，`--check` 自检 |
| `adminapi.py` | 管理页 `/admin/api/weapon` 的脚本客户端。`--show <物品id>` 看现状，`--apply A` 推一套 |
| `drive.py` | 驱动真客户端：登录 → 建房 → 开局 → 收局。也能单步用：`python drive.py stage` / `shot 名字` / `room pvp` |
| `run.py` | 编排全部用例、出报告、收工还原 |

★ 字段表、偏移表、取值范围**全部现读** `server/weaponcfg.py` 和 `hook/bshook.c`，
这里**一个常量都没有第二份**。以后加第 15 格，对不上会当场抛错，
而不是静默少测一格。

## 用例

| # | 验什么 |
|---|---|
| **T0** | 基线：18 把全部清空 → 开一局 → 内存里凡是 `weapon.ini` 写过的键，必须等于 `bot_weapons.json` 的参考值。**这一条是地基**，它不依赖 hook 也不依赖 `effective()` |
| **T1** | PVE 全格：18 把 × 14 格全填（SET-A），逐格 == 设定值 |
| **T2** | PVE→PVP：同一套的 PVP 那半边，**没有 PVE 残留** |
| **T3** | PVP→PVE 回切，仍是 PVE 那套 |
| **T4a** | **局内**改参数（推 SET-B），这一局**一格都不许变** |
| **T4b** | 回房再开一局，全部变成 SET-B（「下一局生效」，D32）|
| **T5** | 留空回退：一半格留空、两模式互补，填了的 == 设定值、留空的 == 参考值/基线 |
| **T6** | 边界：PVE 全取下界、PVP 全取上界（含负重力、`homing_angle=0` 关追踪）|
| **T7** | 原版那 100 多把武器的这 14 格 == 基线，一个字节不许变 |
| **T8** | 弹匣容量进图时快照进「持枪器」（§42 链末端）|
| **T9** | 离线：`build_hook_frame()` → `parse_hook_frame()` == 设定值。**把「服务端算错」和「hook 写错」分开定位** |
| **T10** | **组队战** PVP（1v1）—— 个人战和组队战判据同源，这条是加固 |

期望值是**三层**的，别搞混：

| 情况 | 期望值 |
|---|---|
| 这一格填了 | 就是填进去的那个数（**不经过 `effective()`**，否则成了自己验自己）|
| 留空、`weapon.ini` 里有 | 参考值（`weaponcfg.reference()`）|
| 留空、`weapon.ini` 里也没有 | T0 基线（mask=0 ⇒ hook 写回缓存的 ini 原值）|

## 本会话踩过的坑（改这套东西之前先看）

1. **对战房单人开不了局**：客户端要求「半数以上玩家处于准备状态」。
   解法是聊天框敲 `/a` 叫一个 bot 进来、`/r` 让它准备
   （bot 的「加载完成」由服务端代报，`gameserver.py:10261`）。
2. **准备状态每局开始时会被清掉**（`gameserver.py:10312 room.clear_ready()`）
   ⇒ **每一局开打前都要重新 `/r`**。`/r` 是**开关**，所以先读
   `[座位+0x2e]` 确认到底准备了没有，别盲发。
3. ★★ **房里人员一有变动，客户端锁「游戏开始」3 秒**，这 3 秒**写死在客户端里**
   （用户 2026-09-20 指出）。锁着的时候 F5 被静默吞掉：按钮照样亮、bot 的准备
   照样在、服务端照样 `wait_start` —— **三侧都看不出来，没有任何事件可等**。
   这是铁律 10 的那个例外，只能睡（`drive.ROSTER_SETTLE_S`）。
   ⚠ **千万别改成「没反应就再按一次」**：多按不会让它提前解锁，只会把真人的键盘刷爆。
4. **不要用 `gs_ctl back-to-room` 收局**：它只把客户端切回 stage 5，客户端因此
   再也不会发 `0x0405`「结算看完了」，服务端那边房间**永远停在「游戏中」**，
   下一次 F5 被静默拒掉。正确做法是 `clear`/`endgame` 之后让客户端自己走完结算。
5. **点开聊天框后的第一发回车会被吞掉**，字还留在输入框里，画面和服务端都一声不吭
   ⇒ `type_chat` 必须带 `confirm`，没生效就补一发回车，再不行带截图失败。
6. **截图像素 ≠ 点击坐标**：截的是整个窗口矩形，`click.py` 用客户区坐标。
   偏移是**算出来**的（`drive.client_origin()`），这台机器上是 (3, 26) ——
   V0.1 记的 (3, 29) 已经不对了，写死会差 3 个像素。
7. 坐标表是按 **1024×768** 量的，`drive.check_resolution()` 会先核一遍。
8. ★ **游戏聊天框走输入法**：中文 IME 开着时空格会被 IME 当「上屏」吃掉
   （实测 `/t 2` 变成 `/t/他2`）⇒ **带空格的 bot 命令（`/t N` / `/c N M` / `/d N`）
   在自动化里发不出去**。好在组队战**默认就把前两个座位分在两队**，不用换队；
   队伍号在 `[座位+0x08]`（房主 1、bot 2；个人战都是 0），`create_room("pvp_team")` 会核它。
9. **`keybd_event` 打的是当前前台窗口** —— 真人切一下窗口，后半截按键就丢了，
   而聊天框里看不出少了什么。`ensure_foreground()` 每次发键前都核一遍。
