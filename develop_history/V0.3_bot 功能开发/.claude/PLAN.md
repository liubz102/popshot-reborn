## M1 · 房间内的 bot（不进游戏）

新文件 `server/bot.py`。纪律和 `lobby.py` 一样：**模型和策略在这里，组包发包留在
`gameserver.py`** —— 这样它能脱离 socket 单独测。

### 要写的东西

- **`BotConn`** —— 假连接。继承 `Conn` 但**不调 `Conn.__init__`**（那里面全是 socket、
  密码流、文件句柄），自己的 `__init__` 只设必要字段；覆盖 `send()` / `send_batch()` /
  `close_now()` / `kill_stream()` 为无副作用版本。
  ★ **继承是为了兜底**：任何没覆盖到的方法被调到时不会 `AttributeError` 炸掉真人那条线程。
- **`BotManager`** —— 房间级。座位表、昵称、角色、队伍、难度。
- **命令层** —— `Conn.on_chat()` 解析出 `text` 之后、广播之前插一层
  `bot.handle_command(conn, text)`，返回 `True` = 已消费（不再广播原文）。

### 命令表（★ 只有房主有效；别人发的原样当聊天广播出去，不要吞）

| 命令 | 行为 |
|---|---|
| `/bot` | 最小空座加一个 bot，昵称 `bot N`（N = **服务端座位号 0..5**，和日志、协议一致） |
| `/char N M` | N = 座位号，M = **人物选择面板序号 1..14**（1/2/3 → 角色 id 0/1/2；4..14 → 100..110） |
| `/tm N` | 切换 bot 队伍（1↔2）。个人战 / 闯关房无效，提示原因。★ **不能叫 `/team`**，那个前缀被客户端自己吃掉（§19 / D12） |
| `/del N` | 删除 bot |
| `/ready` | 所有 bot 置 ready |
| `/h` `/help` `/?` | 回显命令表。★ **最多 3 行、每行 ≤ 50 半角宽**：聊天框一次只看得见 4 行（§20）。★ 战斗中给的是**另一套**（见下）|

★ **M3b 追加的两条（战斗中可用，D31）** —— 它们是**测试手段**，不是玩法：

| 命令 | 行为 |
|---|---|
| `/hold [N]` | 让 bot **站在原地不动**（再敲一次恢复跟随）。不给 N 就是全部。★ bot 平时走的是真人趟过的路（D16），不让它站住就永远验不到「隔着墙打不打得到」 |
| `/gun N [M]` | 换 bot 的武器（M = 槽位 1/2/3）；不给 M 就列出可用的。★ 只放行 `weapondata` 认可的（句柄步进确定 + 直射 + 有伤害）|

这两条**不在 `MUTATING_COMMANDS` 里** —— 战斗中必须能用。
战斗中的 `/h` 只列这两条（`BATTLE_HELP_LINES`）。

失败时**必须说清具体原因**（满座 / 不是房主 / 不在房间 / 游戏中 / 座位上不是 bot /
序号越界），用 `broadcast_system_chat()` 那条无前缀的系统提示行发给房主。

### 要改的现成代码

- `lobby._leave_unlocked()` 的房主迁移循环 → **跳过 bot 座**（D2）。
- `Lobby.leave()` 之后判「房里还有没有真人」→ 没有就摘掉所有 bot、房间照常解散。
  ★ 这条**在房间里和游戏中都要生效**。

### 验收（实机）

真人建房 → `/bot` → 客户端房间里出现新座位、有 3D 模型、昵称 `bot 1`；
`/char 1 7` 模型跟着变；`/tm 1` 在组队房里换边、在个人战房里给出提示；
`/del 1` 模型消失；真人退房后房间在服务端消失（`tools/gs_ctl.py` 查得到）。

## M2 · 开局链路（bot 进图，站着不动）

- **加载完成上报**：bot 在**收到房间广播的 `0x0400 gspPrepareGame` 那一刻**
  同步标记 loaded 并触发 `RoomStartGame.on_loaded(bot_conn, members)`。
  ★ **事件驱动，不许用「延迟 X 毫秒后上报」**（CLAUDE.md 铁律 10）。
- **控制者交接**（§4 坑 1）：进 stage 7 后立刻 `handover_controller_slots()`，
  把 bot 的控制格交给真人，否则闯关模式里一部分怪从开局就没人模拟。
- **死亡**（§5 坑 2）：`on_report_hp_zero()` 对 bot 座位放宽「只认本人上报」。
- **重生**：广播 `0x0406` 之后服务端主动发 `0x0419`，走
  `RoomQuest.arm_respawn_watchdog` / `respawn_point_for()` 那条现成的路。
- ~~**同步开关**（§6 坑 3）~~ —— ✅ **已作废**：D1 选了假连接，
  `Room.members()` 天然把 bot 数成一个会动的座位（§13）。一行都不用改。
- ~~**结算**~~ —— ✅ **已查实不用改**：`send_end_game()` 本来就对
  `account is None` 全程有守卫（§21 第 1 条）。bot 照常拿到自己那一行。
- **重生**：★ 用 `BOT_RESPAWN_DELAY_S` = 5 秒（抄客户端 `0x5019a8` 自己那个
  倒计时），**不是**真人那 8 秒兜底，也不发秒复活（D13）。
- **换图**（闯关）：bot 在**广播 `0x0417` 那一刻**就算新图加载完（同 D4）。
- ~~中途真人掉线、房主掉线、游戏中最后一个真人掉线~~ —— ✅ 现成的路都通
  （§21 第 2 条），只补单测。
- ★ **控制格的接管者池要收紧成真人座位**（D14 / §22）——
  否则「有人中途掉线」那个入口会把控制格交给一个 bot，等于没交。

### 验收（实机）

真人 + 1 bot 开一局：bot 站在出生点，能被打死、几秒后复活、结算表里有它、
看完结算能回房间再开一局（局号换代正确、房间不黑）。

## M5 · bot AI

### ⛔ 两条**凭空造的规则，都删了**：口径见 **D50**

bot 的行为规则只能来自 ① 原版真实存在的机制、② 语料量得出来的真人打法。
「这么做会吃亏 ⇒ 所以不许这么做」这种推理**不算**：照做，把代价如实结算，
权衡留给以后真正的 AI（D50）。已经删掉的两条：**「保持交战距离」**（D47，下面）、
**「不往自己爆炸半径开炮」**（D50，会话 20 删）。

#### **「保持交战距离」不做**（D47）

会话 16~18 一直把它当 M5 的第一件事。**用户 2026-08-27 明确否掉**：
「不要擅自增加真实游戏里没有的设定 …… 跟真人对战的时候可没有『保持距离』
的说法。」它当初是从「贴脸 ⇒ 弹体没有可见行程」倒推出来的补偿手段，
而那个根因在 §62 已经修掉了（枪口位置填错）。

⚠ **贴脸本身仍然是个问题**，但它的名字叫「bot 没有自己的走位」——
`trail_point()` 只回放真人的轨迹（D16 的固有缺陷），真人不动时它就站到人
身上。那是**寻路**要解的，不是加一条「离远点」的规则。

### ✅ 会话 19 已经做掉的（原本挂在 M5 名下）

- **真正的命中判定**（§65 / D43）：逐 tick 跑真弹道，撞人 / 撞地形 /
  飞出图外才炸，炸在真的撞上的那一点；三个碰撞圆 × 三档伤害（§66 / D44）。
- **碰撞排除组**（§63 / D42）：`rpFire body+1` 填对，队友不互撞。
- **抛物线武器按「刚好够得着」的力气扔**（§68 / D45）。
- **近身冲刺攻击**（§64 / D46）：`rpDash` + 体力 + `rpSplashDamaged`。

### 还剩的

- ~~★★ **身体朝向必须改成「面朝准星」**~~ —— ✅ **M3b-1 顺手做掉了**。

  没有目标时仍然退回 `aim_point()` 摆在正前方。

- **难度**：反应延迟、瞄准角误差、开火间隔**三个连续量**，默认「中等」。
  ★ 不许用「每 N 次故意打偏」这种计数阈值（铁律 10）。
- 可选：`server.config` 加 bot 难度项（沿用 `config.py` 的宽容解析 + fail-open）。
