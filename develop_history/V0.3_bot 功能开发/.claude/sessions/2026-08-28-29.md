### 真因：§92 那一步没错，坏在**下一步**

`_knock_back_seat()` 确实把击退写进了 `machine.body`（单测一直是绿的），
可下一帧 `_own_step()` 一推，`botmove._air_tick()` 就把它抹了：

```python
if direction:                       # ← 朝着最近的敌人
    speed = walk_speed(...) * AIR_KEY_FACTOR
    vx = speed if direction > 0 else -speed
```

击退刚把 `vx` 设成 `+12`（往右顶开），`_move_intent()` 返回「朝真人走」
= −1，这一句就把它改写成 `−11.25` ⇒ **bot 朝开枪的人飘过去**。
玩家看到的「原地跳一下」= 垂直分量还在（跳起来了），水平分量被反转。

拿实机那一发（`ch02-03` 水平命中、push `(+12.3, −8.6)`）模拟落点位移：
**改之前 −157.5 / 改之后 +172.2**。

### 那句 `× 1.5` 是怎么来的：抄了一段**永远不会执行**的代码

出处是 §71 表里的「空中按方向键 -> 水平速度 × 1.5」（`0x507473`
`fmul [0x69375c]=1.5`）。可那一段挂在 `0x493d00()` 为真的分支下面：

```asm
0050739f  cmp byte [edi+0x128], 0     ; 踩在地上吗
005073a6  jne 0x5073c2                ;   在地上 -> 读键 / 算方向 / 按走速挪
005073b5  call 0x493d00 ; je 0x50767e ; ★ 腾空 + 模式关着 -> 那三件事整段跳过
005073f5  call 0x493d00 ; je 0x507495 ; ★ 键->速度（含 ×1.5）同一道门
00507615  call 0x493d00 ; je 0x507660 ; ★ 按速度移动 同一道门
```

`0x493d00` 读 `[world+0x394]` 的 `[+0x54]`。同一个判据还管着「上下键当
移动键」（`0x515e08`）和「**挨打不结算击退**」（`0x50f80d`）—— 是个
**自由飞行 / 无重力**类的特殊模式，正常对局里是假的。

## 改了什么

* `server/botmove.py`：`_air_tick()` 不再读方向键（参数删掉）；
  `jump(body, vx)` 带上**起跳那一刻的走速**；`AIR_KEY_FACTOR` 删掉；
  `tick()` 的 `direction` 只在踩地时有意义。
* `server/bot.py`：`_knock_back_seat()` 按 `0x50f7ca` 的**真实控制流**重排
  —— 「伤害 < 10 且腾空中」走的是甲档，而甲档里「<= 10」那一路要求
  「在地上且 v.x == 0」⇒ **腾空中挨小伤害速度一点不动**（§92 原来写的
  「照加速度」是错的）；`_move_intent()` 的注释改掉。
* `server/test_botmove.py` / `test_botsync.py`：换掉两条按旧模型写的用例，
  新增「起跳带走走速 / 站着起跳是竖直的」和一条**端到端**的
  `test_the_bot_really_flies_away_over_the_next_frames`
  （挨打之后连走 4 帧，位置必须**远离**射手 100 个单位以上）。
* `re/packet_api.md` §5.6 那句「`0x507402` 会拿按键覆写空中速度 × 1.5」
  勘误；`+11..12` 的说明跟着改。
* `FINDINGS.md` 新增 **§93**，并改掉 §71 表里那一行、§92 的乙档那一句。

## 顺手记两条方法

1. **「这个效果没生效」要顺着数据流一路走到头**：`_knock_back_seat()` 的
   单测一直是绿的，因为它只验到「写进 `machine.body`」为止。真正该验的是
   **下一帧之后 bot 报出去的坐标**。新加的那条端到端用例就是补这个口子。
2. **抄反汇编要先看它挂在哪道 `if` 下面**（和 D57 同一个型）。
   `0x507473` 本身写得清清楚楚，错在没往上翻三十行看那道 `call 0x493d00`。
   判据是：**这一段在正常对局里到底进不进得来？** 拿语料对一下最省事 ——
   126131 对样本一比就出来了。
