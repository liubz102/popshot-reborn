# 会话 44 —— 2026-08-30

用户第四轮实机反馈 4 条（全任务模式）+ 一次中途的关键反问。

1. 「还是有 bot 经常在最左边卡进度，要等一会儿才能跟上，查查根本原因」
2. 「3/4 屏的距离计算有没有考虑窗口大小 / 全屏？没有的话把窗口大小考虑进去」
3. 「bot 进入 boss 房后不会打 boss，基本没有开枪」
4. 「boss 房内不需要推进进度，只需要打 boss」
5. ★ 中途反问：「真人是可以合作打 boss 的，所有人都能同步看到 boss 的
   状态和招式，既然真人能合作，那一定有某种 boss 状态同步机制」——
   **这句把 ③ 从『命中采样凑合』推向了把机制查到底**（和 §125 那次
   同一个形状的纠错）。

## 查到了什么

### ① 的根因：极速相同 ⇒ 差距冻结 ⇒ 钉在门槛上（§141 ①）

`logs/server.out` 18:36 段：三个 bot 落后量全程 **749~828**，
掉队/归队每 **130ms** 翻转（50+ 次）。bot 和真人极速相同（冲刺 1.5×），
差距一旦在打怪时拉开、双方都跑时就**冻结**，只能等真人停。触发线 768
恰好是镜头钉死位。会话 41~43 修的是「走不过去」，这轮的病根是
「追不上」——旧两条瞬移判据（A\* 回空 / 一步没挪）在两边都动时
永远不成立。

### ② 视口 1024 不用改（§141 ②）

`ViewPort::Init` 唯一调用点传**立即数** 1024×768、zoom=1.0；
`UserConfig.ini` 只有 FullScreen 开关没有分辨率；§89 语料实证。
窗口/全屏只影响呈现缩放，不影响可见世界宽度。

### ③ boss 同步机制（§141 ③，用户反问推动）

* 招式/阶段：`rpAiMsg` `setState` 的 `phase`/`state` 广播，客户端锁步演播；
* 位置两族：Quest02 吊车 boss（语料 0x10c8e2）62 发 setState 23 发带
  posX；**载具族**（语料 0x10ca80/0x10ca4a、实机 Quest03 1100275）
  从不带 posX——但**控制者替它发的 rpFire（source=20）每一发带部件
  世界坐标**（实机 35 发，机关枪 (871.7,430)/炮 (765.9,517.9)，间距 106）。
* boss 武器表在 `Data/Quest/QuestNN/weapon-N.ini`（CP949）：2003xxx /
  3003xxx 全套，主表没有 ⇒ `note_peer_fire` 以前整包丢（枪口流 +
  躲 boss 子弹全丢）。
* 句柄差一：AI 流 1100275，rpExplode 命中 / HP 归零 1100276（AI+1）。
* 顺带修了一个潜伏 bug：`note_mob_hit` 的 `if not table` 把空表当没表，
  「凭命中建表」根本进不来。

## 改了什么

| 文件 | 改动 |
|---|---|
| `server/bot.py` | 牵引绳滞回（`BOT_COOP_LEASH_RELEASE`=512）+ `leash_anchor` + 第三条瞬移判据「他跑满一整屏还掉队」；`_boss_room` / `_nearest_mob` / `_boss_fight_intent`（打得到站住、打不到过去、boss_gun 兜底）；`note_ai_message` 认 `fileName=…boss.ini`；`note_mob_hit(create=True)` 命中建表（`_is_breakable_handle` 分流箱子）；`note_mob_gun_muzzle` 枪口采样（`MOB_GUN_REACH`=300）排在武器解析**前面**；`note_peer_hit` 两处 create=True |
| `server/gameserver.py` | `RoomQuest.boss_room` / `boss_gun`（换图跟着清） |
| `tools/weapondata.py` | `find_quest_weapon_inis` 并入每关武器表（CP949 探测）；FORMAT 9 |
| `server/weapondata.py` | FORMAT 9 |
| `server/bot_weapons.json` | 重提取：272 把（44 把关卡怪/boss 的，永不进 usable） |
| `server/test_weapondata.py` | quest 武器在表且不进 usable 的钉子 |
| `server/test_botsync.py` | `BotCoopLeashTests` +3（滞回/追不上瞬移/一屏闸门）；`BotBossRoomTests` 新类 6 条；`BotQuestCombatTests` +5（命中建表/破坏物分流/枪口刷新/boss script 标志）；删掉被新语义取代的「未知句柄不建表」 |

新硬事实：**§141**；新决定：**D101**。

## 复审轮（另一个 agent review 出 3 条，全部成立、全部改掉）

1. **boss 房站住判据 ≠ 开火判据**：第一版「距离 + 屏幕内」就站住，

   ⇒ `_boss_fight_intent` 改用 `_fire_target` 的结果判站走。
   新测试：`test_a_boss_behind_cover_is_not_stood_at`。
2. **普通房间未知世界对象会被建成怪**：`create=True` 不分房间，过滤器
   只挡了可破坏物。⇒ 建表只限 `quest.boss_room`。
   新测试：`test_a_hit_outside_a_boss_room_invents_nothing`。
3. **quest 武器表丢了关卡 / 难度维度**：数据实测 —— id 是关卡内局部的
   （2003010 在 Quest02..07 是不同的枪），难度间连弹速都不同
   （Boss-HeadFire 14→17、Boss-Jiksa 12→23）。⇒ 产物 `quest_weapons`
   按 `(关卡, 难度, id)` 三维存（FORMAT 10），`bot._quest_weapon` 带
   房间上下文查。新测试：`test_boss_bullets_are_rebuilt_with_the_rooms_difficulty`。
