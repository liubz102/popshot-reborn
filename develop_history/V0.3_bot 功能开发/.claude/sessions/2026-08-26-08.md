## 结论先行：三条全是**协议字段读错**，而且三条都拿到了逐指令实锤

会话 07 的 §31 是这一轮最大的教训 —— 它**拿相关当了因果**。

### §35 ★★★ `bit2` 是「我踩在地面上」，速度两格是「离地时的抛体速度」

会话 07 统计的是「速度全 0 ↔ bit2=1」，相关性 99%+，**没引入「位置变没变」
这第三个变量**。引入之后语料 67186 发分成四格，反例立刻现形：

| 位置变了 | bit2 | 速度全 0 | 发数 |
|---|---|---|---|
| 否 | 1 | 是 | 28267（站着） |
| **是** | **1** | **是** | **20341（★ 在地上走）** |
| 是 | 0 | 否 | 18070（腾空） |
| 是 | 1 | 否 | **9**（≈ 不存在） |

逐指令实锤在 `0x507610`：`cmp byte [edi+0x128], 0 / jne` —— **在地面就整段
速度积分都不走**；离地才 `dt × [0x124]` / `dt × [0x120]` 做位移 + 碰撞，
撞到地面 `mov byte [edi+0x128], 1`。

⇒ 会话 07 那版让 bot 每一发都说「我在空中、速度 (9,0)」，收方一边按速度推、
心跳一边插值拉回 —— **这就是「走一下停一下、像在抽搐」**。

### §36 / §37 准星是**世界坐标**，朝向位和角度都跟着它

§25 只看了 `0x4295cb` 的第一步（`0x429569` 取光标屏幕坐标），
**漏了紧接着那一发 `0x5cc42f`（this = `[0x6e9b94]` 视口）的坐标变换**。
语料佐证：`cx` 的 p95 = 5056（远超屏幕宽度）、和角色世界 x 相关 0.47、
`|准星 − 角色|` 中位数 529。

顺手把朝向位从「🤔 68% 的倾向」升级成实证（97.8%）：换了对穿量 ——
拿**同一发包里的准星**比，而不是拿紧跟着的 `rpFire` 发射角比。
角度则是**相对面朝方向**的仰角（朝左时 x 分量取反，中位误差 6.9° / 7.4°）。

### §38 客户端每 **1000 ms** 才广播一发加载进度

`0x46fe53: add ecx, 0x3e8`。1v1 时唯一的真人一两秒读完图 ⇒ 统共报一两发 ⇒
bot 照抄就几乎没画过东西。多人要等最慢的那个，报的发数多，条才看得见。
**和局号 / 跨代 / 转发路都无关**（这几条我按怀疑顺序都查过了，全是好的）。

### ★ 用户拍板：别演了，**bot 一进加载界面就直接报 100**（D26）

我本来做的是「两头用服务端的事件钉住、中间仍旧跟真人画」。用户看完直接指出：

> bot 没有真正的客户端资源需要加载，bot 一定是加载最快的，
> 那么它应该一开始就是加载完成的状态。

—— 而这正是 **D4** 早就定下的事（广播出去那一刻就算 bot 加载完），
进度条只是把那个事实画出来。D23 当初否掉这个选项的理由写的是
「用户看到的还是没有进度条，只是从空条变成满条」—— **那是臆测**。
★ 教训：「用户会觉得难看」这类判断不该由我替用户下。
