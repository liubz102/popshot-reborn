# 会话 60（2026-09-04）—— 冰塔尖尖死锁 + 「一卡一卡」定量

## 用户报的两条

> * 2026/9/4 0:10 左右的对局，我试了下感觉 bot 的动作还是一卡一卡的，
>   很像网络卡顿的感觉。以前反复修这个问题，怎么现在还是有呢。
> * bot 3 从 00:08:52 到 00:09:37 被卡在地图的冰塔尖尖处。

语料：`logs/server.out`（00:04:03 起那次启动），`Iceria03:NewPvp` 第 2 代
（00:08:25.534 ~ 00:11:09.567）。

## 做了什么

### ① 冰塔尖尖 —— 定位 → 复现 → 修 → 变异验证（§177 / D140-1、2）

* 从 `→ 发出` 的十六进制解 bot 心跳，量出 bot 3 在 (1213, 858) 恒定
  45.8 秒，且 **`on_ground` 恒 0 / `v=(7,0)` 恒定**（§172 那张「bot 不动」
  表里没有这一行 —— 新形状）。
* 拉 `bot_mapdata/Iceria03.json` 打地形：列 1214 是
  `857 实心 / 858 空 / 859 实心 / 860 空`，净空 1 像素。
* 离线逐 tick 复现（从实机那一发心跳 (1244,902) v=(−10,−14) 起飞）：
  5 tick 后落在 (1214,859)，之后 2 tick 一个周期，24 格一模一样。
* 改 `botmove._walk_tick()`（落点撞墙时逐列扫崖边）+
  `bot._unstick_intent()`（第三条出路：走出崖边掉下去，落点过 `_landing_ok`）。
* 量了改动面：8 张真图受影响走位 ≤0.4%，**可达图落脚点数 8 张全部 ±0**。

### ② 「一卡一卡」—— 拆成三条，全部落地

1. **投递整条排掉**（循环 5126 格不落 / 心跳中位 128 ms / 转发 0.1 ms /
   积压 ≤12 / `落后` 0）。
2. **掩码口径改了**：自己走位时报 `press_dir`（自己按着的键），
   不再从位移反推。「反着挪」5.5% → 3.9%。
3. **走停颗粒度**：`打得到·就地打 +0` 占决策时长 25%~40%，1409 次翻转里
   34% 只握了 64 ms。站的总量对（33~42% vs 语料 39%），一段走的长度差一倍
   （270 ms vs 同一局真人 525 ms）。
   ⇒ 把三条候选（A / B / C）摆给用户，用户选了 **A + C**：
   「换弹的时候别站着。另外，换枪的抖动也修好。」**当场实现了**（D141）。

### ③ D141：A + C

* **A**：`_reloading()`（`rounds_left is None and now < next_fire_at`）——
  `CoolingTime` 那一档照旧站着，`ReloadTime` / `LoadingTime` 那 720~2500 ms
  改成继续走位。量化依据：`打得到·就地打` 的 235.1 秒里 **124.1 秒（53%）**
  落在换弹窗口里（拿线上 `rpFire` + 原版武器表复原的）。
  代价（用户已接受）：站着的占比会掉到 13%~22%，低于语料真人的 39%。
* **C**：换枪那句「手上这把不在候选表里 ⇒ 无余量直接换」（996 次换枪决定里占
  **47%**）加一道门：**这会儿真能扣扳机**才换。过了 1.25 倍余量的那 53% 没动。

## 走过的弯路（别再走）

* **一开始把「一卡一卡」全归给掩码口径**，以为「一发心跳盖 4 格、反推只看
  最后一格」就是全部病因。拿 `◆走位来自` 重建 intent 时间线之后被自己的
  数据否掉了：**两种口径下「站却挪了」都是 119 / 123 次** —— 心跳那一格的
  意图本来就是 0。⇒ 口径只治「反着挪」，颗粒度得治意图。
* 用「掩码 vs 下一窗净位移」这个单一指标比两种口径会**得出反的结论**
  （19.9% vs 22.7%，旧的赢）。必须**按错法拆开**才看得出真相：
  「走却没挪」在报真键的口径下不是错 —— 真人顶墙角就是这样，
  收方同一张地形照样走不动。
* **拿日志行当次数用也错过一回**：`开火:` 按 `(武器, 飞行 tick)` 去重，
  `换枪:` 是「决定」不是线上包。真数字要从 `rpFire` / `rpChangeWeapon`
  那两类包里数（115~206 发 / 23~58 发）—— 所以**屏幕上并没有武器闪烁**。

## 结果

* 回归 **2265 项全绿** ×2（CPython 3.14.3 / Win7 3.8.10），新增 16 项用例、
  改写 3 项（老断言里编码的是「打得到就站住」这个旧行为）。
* 四处修法各做过变异验证：`_ledge_within_step` 恒回 None / 关掉「走出崖边」/
  掩码改回位移反推 / `_reloading()` 恒假 / 换枪那道扳机门恒真 —— 相关断言全红。
* 没碰客户端、协议、地图格式、武器数据。
* `re/packet_api.md` 的心跳掩码那一节补了一段：**它要填的是「键按着没有」
  这个因，不是「刚才挪了没有」这个果**，并写明「键按着而坐标没动」是合法组合。

## 遗留

1. **等实机验收**（清单在 `PROGRESS.md`）。★ A 之后 bot 会明显比以前爱动，
   要是觉得动得太多，杠杆是 `_reloading()` 只算长的那几档 —— **别动决策频率**。
2. 换枪那 53%（过了 1.25 倍余量的那一支）没动；B（站住打握到这一枪打出去）
   记在 `DECISIONS D141` 末尾当下一个杠杆。
3. `_ceiling_between()` 那个「同一像素上行透明、下行实心」的不对称**没动**
   —— bot 仍然进得去 1 像素夹层，只是现在出得来。要动它得先把 §95 / §169
   两轮的实机现场重跑一遍。
4. 「贴到墙根」那一半逐列扫没做（会动 `Iceria03` 3.7% / `CamelCulvert04`
   8.9% 的走位 + 可达图，单独一轮）。
