# 2026-08-26 会话 14 —— 弹道模型全解开；射程 / 三把武器 / 延后爆炸

## 开场

用户实机：

> 「hold 住以后，距离远了 bot 就不开枪了，站在身边才开枪。
>  刚才 bot 用 2 号角色，用 /gun 命令切换武器，只有 3 号武器能用，1 和 2 都不能用，
>  无法切换。所有角色应该都有 3 个武器能用才对。（并且，绝大多数角色 2 号武器是
>  抛物线发射，比如有些是手雷，鼠标长按蓄力，松开按抛物线扔出）」

两条报的东西看着无关，**根其实是同一个** —— §44 挂了两个会话的那个 ❓：
**`Velocity` 的尺度不明**。射程因此只能拿 `LockonRange` 凑合；
抛物线武器因此不敢放行（算不出弹道）。所以这一轮先去把它解开。

## 做了什么

### 1. ★★★ 弹道模型（§47）—— 这一轮真正的产出

两条线同时查：

* **反汇编**：`0x4920a1` 的三岔口（`PowerControl` 三种初速公式）、
  `0x4921c9`（重力项）、`0x47f603`（弹体 `vft+0x158`，所有弹体类共用的
  每 tick 递推 `v.y += dt×g; pos += v`）。顺带把武器结构体的**字段名 → 偏移**
  整张表映射了（解析函数 `0x488c00`~`0x489900` 每个字段 push 一个 UTF-16 键名）。
* **语料回归**：把 `rpFire → rpExplode` 按**几何**配对（爆炸点必须落在开火
  射线上，误差 < 0.02 rad），4529 对。算 `距离 / 时间 / Velocity` 的**上包络**
  （dt 只会被延迟拉大，所以看上沿不看中位）⇒ **31.25 = 1000/32**。

⇒ **tick = 32 ms，`Velocity` 的单位是「世界单位 / tick」。**
`Velocity = 100` 是 3125 单位/秒，不是 100 —— §44 那个「弹速比人走路还慢」
的悖论到此为止。

重力也对上了：拿 `PowerControl=2` 的手雷反解每 tick 加速度 ÷ `GravityFactor`
= 1.1972 / 1.1546 / 1.1967 / **1.2000**，和 `0x40a04f` 里那个 `fmul 1.2` 一字不差。

★ 顺带解开 **`Acceleration`**（§49，`BulletObj` 的 `vft+0x24`，7 把武器边飞边
加速）—— 不建模的话 `ch100-03` 飞 600 单位算出来要 6.4 秒（实际 0.7 秒）。

### 2. 「只有 3 号武器能用」= 两个 bug 叠在一起

* ★★ **§45：正则区分大小写。** `weapon.ini` 里 46 个节是小写，
  **偏偏 `[CH01-01]` / `[CH03-01]` 是大写** ⇒ 角色 1 和角色 3 的 1 号枪
  **整个不在表里**。用户用的「2 号角色」= 面板序号 2 = **角色 id 1**，正中这条。
* **2 号槽全是抛物线**，会话 12 的 `_is_usable()` 一律排除。

⇒ `re.IGNORECASE` + 弹道模型放行抛物线 / 散射（D35）
⇒ **14 个玩家角色三个槽位全齐**（单测钉住了）。

### 3. §46：`rpFire +22` 的 `count` 必须 = `SpreadFrags`

读 `OnFire` 的循环读出来的：外层轮数是 `count / SpreadFrags` 的**整数除法**，
填 1 打 3 散弹的枪 = 0 轮 = 一颗子弹都造不出来。
**语料 65/65 全部 `count == SpreadFrags`**，0 例外。

顺带把句柄步进量准了：`SpreadFrags × (2 if 溅射 else 1)`。
拿「一局只打一种枪」的干净片段直接量：`1001010` 4 发 → **11 个连号句柄**；
`1002030` 207 发 → 句柄跨度 **427**。

### 4. §48 / D33：射程改成语料量出来的 1000

原版**没有**射程字段（`LifeTime` 玩家武器一把没填），所以从「真人怎么打」里量：
247 发「打中了角色」的开火距离 p99 = **1015** ⇒ 取 1000。
对照原来那个 `LockonRange` 80~120 —— 地图宽 1500~2848，那只有小半屏，
用户看到的「站在身边才开枪」就是它。

### 5. D34：延后爆炸 + 溅射武器的顺序闸门

`rpExplode` 不再紧跟着 `rpFire`，改成排队等飞行时间到。两条硬约束写进代码注释：
**一发都不能漏**（`_flush_explosions()` 排在 `_tick_bot()` 最前面，bot 躺着也发）、
**带溅射的武器要等上一发炸完再开下一枪**（溅射那个句柄在开火时还是爆炸时分配，
语料分不出来；「炸完再开」时两种假设同解）。

## 这一轮的方法论

★ **两条报的 bug 根在同一个未知量上时，先去解那个未知量，别分别打补丁。**
会话 12 / 13 各拿 `LockonRange` 凑过一次射程，两次都没往下追一步；
这一轮把 `Velocity` 解开之后，射程、抛物线武器、延后爆炸、M5 的自动换枪
四件事**同时**解锁。

★ **语料能量的东西就别推。** tick 长度、重力系数、句柄步进、交战距离
四个数全是从 41 个真人语料里量出来的，每一个都有 n 和分位数。
「上包络而不是中位」这个口径尤其要记住 —— 延迟只会让测出来的速度偏小。
