# 后半场：M3 的逆向（→ §23 / §24，`re/packet_api.md` §5 已同步）

M2 交给用户实机验证之后，接着做**不依赖那轮结论**的 M3 逆向部分。

## 突破口：`UdpPacket` 的构造函数是 `0x5bbe1b`，内层 opcode 是它前面那个 `push`

全镜像扫一遍 `call 0x5bbe1b`（27 处），**一次拿到全部 24 个内层 opcode 的组包点**。
再认出序列化的**写原语**（`0x5d5901`=1 / `0x5d5910`=2 / `0x5d591f`=4 /
`0x5d592e`=8 / `0x5d593d`=裸 N 字节，都是「追加 N 字节」，没有任何编码）——
于是 **body 布局 = 组包点后面那串 `call 写原语` 的顺序**，一个字段都不用猜。

自检：逆出来的 body 长度和 §2 抓包实测的**逐个吻合**
（rpFire 26、rpExplode 28、rpJump 2、rpChangeWeapon 5、`0x0013` 8）——
5/5，是一次独立的交叉验证。

## 字段语义拿实包对穿

- `rpFire +0` = **`10 + 座位号`**（怪 = 20）：7040 发和 `UdpPacket` 头 `+1` 的
  发送方**100% 一致、0 例外**；
- `rpExplode +4` 出现的值是 `100001 / 200001 / 300001 / 400001` ——
  正好是 §11 的「座位 × 100000 + 100001」，⇒ 它是**命中目标的句柄**，`0` = 没命中；
- `rpJump +0` / `rpChangeWeapon +0` = 座位号，同样 100% 一致。

## ★★ 心跳 `0x4001`：全部解开，并**推翻了 §3 的位置字段**

心跳的 body 不是一串写原语 —— 它是 `u16 N` + `i32 1` + `u8 座位号` +
**一个虚函数整块序列化的 24 字节角色状态**（发侧 `0x5040b0`，收侧 `0x5041e1`，
走裸写 `0x5d593d(ptr, 0x18)`）。所以按「写原语簇」扫是扫不到它的，得顺着
`[0x72e2dc]` 的 `vf+0xc0` / `vf+0xbc` 找。

**真正的角色位置是 body `+7..8` / `+9..10`，不是 §3 说的 `+25..28`。** 两条独立证据：

1. 反序列化器 `0x5041e1` 读 struct `+0`/`+2` 两个 i16 → `fstp [char+0x34]` / `[+0x38]`
   —— 那两个 float 就是角色坐标；
2. 拿 3815 发 `rpFire` 的精确开火坐标比同座位上一发心跳的每个 i16 槽位：
   X 在 `+7` 命中 27.8%（`+25` 约 1%），Y 在 `+9` 命中 24.5%（`+27` 11.9%）。

顺带把 67186 发心跳逐字节统计了一遍，`+6 = 座位号`（100% 一致）、
`+16` 和 `+29..30` 是**序列化器从没写过的栈残留填充**（§3 说「恒 0x39」「恒 0x001a」
是抽样偏差），`+23` 是那个 6 位掩码。**§3 已在原处标注作废，以 §24 为准。**

★ 填错位置的症状是「bot 在别人屏幕上一动不动」，和「包压根没发出去」
长得一模一样 —— 这条勘误值一整轮排查。
