# 会话 07 · 2026-08-26 —— M2/M3a 第一轮实机反馈的 4 个问题全修掉

## 用户给的输入

第一轮实机跑完了。**主线全通**（进游戏 / 跟着走跳落点正确 / 打得死 / 能复活 /
任务模式换房不卡墙 / 房主迁移 / 闯关怪正常刷 / 结算有 bot 收益 / 第二局照常），
报了 4 个问题：

1. bot 没有进度条（但能顺利进游戏）；
2. 没有走路动画，看起来是平移；而且平移一卡一卡的，跳在空中尤其一顿一顿；
3. **每次复活都会换一个角色**；
4. 任务模式 bot **3 条命死完了还能继续复活**。

## 结论先行：4 个问题 = 4 条新的硬事实（§30 ~ §34）

一条都不是「参数没调好」，全是协议字段读错 / 判据选错。

### §30 内层 `0x4005` 是加载进度（0..100）

拿 41 个语料文件按流的先后顺序打了一遍：每一轮开局都是
`0x0402 / 0x0402` → `0x4005: 0→34→50→62→72→81→90→98→100` → `0x0403`，
618 发**全部**以 100 结尾且紧接 `0x0403`。§2 里那个叫「读图心跳」的东西
就是进度条的数据源。bot 一发都没发 ⇒ 那一格空着。

### §31 ★ 心跳位域 bit2 = 「我静止着」——**这是「没有走路动画」的根因**

67186 发逐发对穿：**速度两格全 0 → bit2=1 占 99.13%；速度非 0 → bit2=0 占 99.95%**。
会话 05 那版把 bit2 **恒填 1**（当时按 §25 的「插值是常态」理解的），
等于每一发都在说「我站着没动」而坐标又一直在变。

配上 §25 的收侧分支，正确的语义是：**走的时候插值、停下的那一发精确归位**。

### §32 帧率限流 0.125 s 和驱动它的心跳同频 ⇒ 拍频丢帧

`BOT_FRAME_INTERVAL_S` = 0.125 s，而真人心跳也是 ~8 Hz。同频的两个东西撞在
一起，链路一抖就有一半的帧落进阈值里被丢掉 —— 实际帧率 4~6 Hz 且忽快忽慢。
**这正是铁律 10 要防的那类常量**（拿观测值当真理，掩盖而不是消除竞态），
只是这次它伪装成「采样率限流」混过了会话 05 的自我审查。

第二条：落脚点**吸附到采样点**，「往回 120」落在哪个点是跳变的 ⇒
真人速度不匀时 bot 每帧走 0 / 一步 / 两步。

### §33 ★ `0x0413`/`0x0419` 的 `+0x0c` 是**角色 id**，不是「重生点索引」

`0x4931c2` 拿它和 `[char+0x2b0]` 比，不一样就卸掉角色重建 + 播一行
`%s님이 [ %s ] 캐릭터로 변경하였습니다`。而看门狗补包时填的是
`last_respawn_hint` 的第三个值 = **这张图上最近一个人报的**，也就是别人的角色 id。

★ 这个洞对**真人**也在（他被看门狗补重生时也会被换成别人的角色），
只是真人极少走到看门狗那条路，所以一直没露头。

### §34 闯关模式每人也是 3 条命，**硬编码**

`QuestVictoryCondition` 构造函数 `0x55e073` 三条指令 `push 6/pop ecx ;
push 3/pop eax ; rep stosd` —— 六个座位一律 3。V0.2 会话 51 记的
「闯关的最大生命来自关卡脚本、服务端拿不到」**是错的**（那是从「vf_0c 读
`[vc+座位*4+0x198]`」倒推的，没去看谁写的它）。
