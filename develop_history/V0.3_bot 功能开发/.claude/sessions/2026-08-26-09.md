## 结论先行：动画的开关是**方向键掩码**，和坐标 / 速度都没关系（§39）

心跳 body `+23..24` 那个「6 位掩码」（会话 05 起一直当 `buff_mask` 填 0）
是**方向键有没有按下**：bit0 = ←、bit1 = ↑、bit2 = →、bit3 = ↓。

收方一条链走到底，**坐标在不在变根本不参与**：

```asm
005042fe  lea eax, [esi+0x2b8]        ; 反序列化：6 个位摊回键位数组（0x41 / 0x10）
005073c2  test byte [edi+0x2b8], 1    ; 左键 -> 走路方向 [char+0x4b4] = -1
005073d4  test byte [edi+0x2c0], 1    ; 右键 -> +1；都没按 -> 0
00507fc3  mov eax, [esi+0x4b4]        ; ★ 动画选择（前提：踩在地面上）
00507fcb  je  -> "Stand%02d"          ;   方向 0
00507fd1  cmp eax, [esi+0x2d0]        ;   == 朝向 -> "Run-F%02d" / != -> "Run-B%02d"
00507660  call [eax+0x128] ; fimul [edi+0x4b4] ; fmul dt ; call 0x50d9a7
                                      ; ★ 踩地时收方**自己**把角色走过去
```

⇒ bot 填 0 = 收方画一个**站着**的人，而且**不替它走** ——
位置只被每发心跳的 0.6/0.4 插值拉一格。**这就是「一格一格的平移」。**

语料 67186 发对穿：在地上往右走 bit2 置起 9070 : 掩码全 0 1010；
往左走 bit0 7330 : 931；站着不动掩码全 0 26744 : 2122。

## 为什么按键不抄真人的（D27）

D25 说「运动状态整套抄真人轨迹点上的」，按键**故意不照办**：
轨迹总长还不到 `BOT_FOLLOW_DISTANCE` 时落脚点固定在最老那个采样点 ——
真人已经在走、**bot 线上的坐标一动没动**，抄来的按键却说「我在走」，
收方会按走路速度把它往前推、下一发心跳再拉回来，正是 §35 那种抽搐。

「我这一帧往哪边挪了」是 bot 自己最清楚的事；而「这一段是踩地还是腾空」
服务端没有地图几何就算不出来，只能抄真人。两者的判据不一样。
