## 结果

三条全部查到根因、全部改了，**没有实机复验**。1571 个单测在 3.14 和 3.8
上都全绿。

### 1 + 2 是同一件事（§89 / D63）

`logs/server.out` 那一局（18:48，Forest_b:NewPvp，args=(1,3,0)）里，
真人自己那发苹果弹的包直接给出了答案：

```text
★真人rpExplode: … hit 0 flags 4 伤害 30      ← 20 × 2 × 0.75
bot 1 爆炸: … 目标 座位0 的head 伤害 30       ← 碎片 15 × 2，一点没减
```

`rpExplode +20` 那一格**不是**「❓未知的位标志」，是**射手一路 `or` 出来的
「这一发打了哪些折」**。`0x47e618`（`Projectile` 虚表槽 `+0x128`）里那两条：

* `bit3 (0x08)`：射手和目标的原点距离 > `[视口+0x30]` = **1024** → `int(×0.75)`
* `bit2 (0x04)`：目标 `[char+0x128]` ≠ 0 = **踩在地上** → `int(×0.75)`

两个数都不是新东西：1024 是 `ViewPort::Init(0,0,0x400,0x300)` 的宽度
（全镜像唯一构造点），`[char+0x128]` 是心跳位域 bit2（V0.3 §35 早就实测过）。

**关键在于「哪个虚表槽」**：这两条只挂在**弹体类**的 `+0x128` 上。
`SplashDamage` / `Flame` 的 `+0x128` 直接指 `0x4806bf`（只有 ×2），
`DashDamage` 指 `0x481dfd`。§87 当时把 `0x4806bf` 认成「所有伤害的必经之路」
—— 那句话本身没错，错在**由此以为四条路的修正是同一套**。D63 把口径写死了。

语料验证（380 份 `.dec.bin`，68 个夺分局的 5625 发直接命中）：

* `bit3` ⇔ 距离 > 1024：**只错分 35 发（0.62%）**，扫 800~1400 的最优门槛
  是 1040（用爆点近似目标原点，差得开的只有这点噪声）；
* `bit2` ⇔ 伤害正好 `int(×0.75)`：单武器干净局逐发对得死
  （`ch01-03` 18/腿15 → 27/22，`ch02-02` 16/腿12 → 24/18）。

### 2 的「还有没有别的不对」：溅射衰减整个是猜的（§90 / D64）

原来那版的注释老实写着「按线性衰减 —— 没有更细的出处」。逆 `0x4857aa`：

```text
r = 距离 / (SplashRange + 35)          ← 35 是目标自己的溅射半径，写死
r > 1 -> 0
伤害 = int((1 − r) × (SplashDamage − 1) + 1)   ← 截断，边缘是 1 不是 0
     -> 再乘模式倍率（乘在截断之后）
```

四处和旧式不一样，方向全是「旧的偏低」。验证只用**自伤**样本（受害者就是
射手本人，位置有他自己的心跳；`rpSplashDamaged +0` = 弹体句柄 **+1**）：
`ch02-03` 5/5、`ch105-02` 3/3 一位不差，合计误差 268 → 32。

★ 顺手核过没问题的：火墙（`Flame::+0x134` 返回 `[this+0x2fc]`，无衰减，
恒 10 —— §85 结论不变）、近身（`DashDamage::+0x134` 同样是平的）、
直接命中的三档部位伤害（语料里 27/22 那组数就是它）。

### 3（§91）

**进图**是完全确定的（`0x405e1c` → `0x473cb2`），服务端能算出和客户端
一模一样的点：

```text
表   = 组队 ? (队伍1 -> type 101 / 队伍2 -> type 102) : 101+102 拼起来
名次 = 同队里座位号比我小、且有人的座位数
点   = 表[名次 % 表长]，再掉到地面
```

**重生**反过来是**全表随机**（`0x4fe832` → `0x473d2f` 传的队伍号是 0）。
语料佐证：1360 发真人 `0x0413` 里 x 中位差 0、y 低 55（掉到地面），
而且「同一条连接 + 同一张图 + 同一座位」的 126 组里有 **68 组 101 和 102
两类点都落过」—— 队伍过滤在这条路上确实不存在。

「瞬移 + 抽搐」的根因是 `_own_step()` 的第一句
`if not _hostile_targets(): return None`：真人一死敌人表就空了，
bot 当场退回 `trail_point(真人轨迹)`。「场上没有敌人」是很正常的一刻，
该做的是站着不动，不是回去跟人。

重生这条路**必须两边一起改**：新钩子 `gameserver.BOT_RESPAWN_POINT` 让
看门狗补的 `0x0419` 填地图出生点（原来走 `respawn_point_for()`，那本账里
**只有真人客户端自报过的点**），同一个点记进 `BotConn.pending_spawn`，
`_tick_bot()` 下一帧把身体搬过去 —— 少做后一半就是「客户端把模型放在 A、
心跳报 B」。

## 顺手记一条方法

**「某一档伤害不对」先问「它走的是哪个类的哪个虚表槽」**，别按「都是伤害」
去找共同的必经之路 —— 这一轮两条 bug（×0.75 漏了、溅射衰减是猜的）都藏在
`+0x128` / `+0x134` 这两格的**多态**里。
语料这边配套的手法是：**只挑「一个文件里只有一把带溅射的武器」的干净局**，
再**只看自伤**（受害者位置有他自己的心跳），一下就把公式钉死了。
