# 会话 11 · 2026-08-26 —— 蹲下（`rpCrouch`）

## 用户给的输入

> 类似的还有一个问题，角色在地面上按下键，可以下蹲并加快体力恢复速度，
> 这一点有没有实装好

## 结论先行：**没实装**，而且它和前面几格都不一样（§41）

蹲下**在心跳里一个位都没有** —— 它是一个**单独的事件包** `rpCrouch`(0x000b)，
按下和松开那两下各发一发：

```
组包点 0x492f13：两发 0x5d5901（各写 1 字节）
   +0  u8  座位号            ← 语料 394 发和头 +1 的发送方 100% 一致
   +1  u8  1 = 蹲下 / 0 = 起立   ← 213 : 181
收方 0x492f5f -> 0x5026e1：设 [char+0x2b5]，播 "Crouch-Start"
```

`[char+0x2b5]` 在收方管三件事，全在「所有角色都跑」的那个更新函数里：

| 地址 | 干什么 |
|---|---|
| `0x507250` | `fadd st(0), st(0)` —— **体力恢复 × 2**（用户说的那一条）|
| `0x507607` | `fmul [0x69387c]` = **`dt × 1/3`** —— 蹲着走只有 1/3 速度 |
| `0x507fdd` / `0x508061` / `0x508111` | 姿势 `Crouch-B` / `Crouch-F` / `Crouch` |

★★ 所以这不只是「好看」：那个 `× 1/3` 是收方**自己**替这个角色算位移用的
（§39 那条链）。真人蹲着走时坐标是 1/3 步长，bot 抄了坐标却说自己站着，
收方就会按 3 倍速度替它走 —— 和 §40 的冲刺是同一个坑，方向相反。

## 两处容易再踩的地方

1. **换图 / 新一局必须两边一起清**：客户端那时把角色重建、`[0x2b5]` 归零
   （`0x4ffc4a`）。服务端这边不清的话，bot 以为自己还蹲着，于是**不发**
   新图上那一发蹲下的 `rpCrouch` —— 姿势从此一直错。已有用例钉着。
2. **去重必须按状态翻转**（铁律 10），不能每帧都补：`rpCrouch` 是**事件包**，
   每发吃掉一个可靠序号，而那本账和心跳里的 N 是同一本（D5）。

3. ★ **死亡也会清**（当场查掉了，没留给下一轮）：死亡处理器 `0x4ffbb7`
   （虚槽，`Character` / `MyCharacter` 同一格，`mov byte [ebx+0x2b4], 1`
   就是那个「我死了」标志）里有一句 `mov byte [ebx+0x2b5], 0`。
   所以 `_tick_bot` 在「躺着」那条早退路上也把 `crouched` 清掉，
   否则真人一直蹲着时 bot 重生后看不到翻转、**不会再蹲**。
