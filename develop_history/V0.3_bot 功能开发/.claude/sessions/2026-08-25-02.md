# 会话 02 · 2026-08-25 —— M1：房间里的 bot

## 做了什么

把 M1 从零写完：房主在聊天窗口敲命令就能加 / 删 / 改 bot，bot 在房间里占座、
有昵称和 3D 模型。

**新增 `server/bot.py`**：

- `BotConn` —— 继承 `gameserver.Conn` 但不调它的 `__init__`（D1）。
  `__init__` 是 `Conn.__init__` 的**镜像**，把纯内存字段一个个补上，
  只跳过 socket / 流密码 / 逐连接日志文件 / `register_conn()`。
  覆盖 `send` / `send_batch` / `close_now` / `kill_stream` / `log` / `online` /
  `refresh_seat` / `seat_snapshot` / `my_nickname`。
  ★ `refresh_seat` **必须**覆盖：原版会拿 `display_name(None)` 把昵称刷成空串，
  而它的调用方 `send_session_members()` 是每个房间成员都会被调到的。
- 命令层 `handle_command(conn, text)`：`/bot` `/del N` `/char N M` `/team N`
  `/ready` `/help`（`/h` `/?`）。所有组包发包都走 `Conn` 的现成方法，
  这个文件里一个 `struct.pack` 都没有。
- 面板序号 1..14 ↔ 原始角色 id 的换算（D6）。

**改 `server/lobby.py`**：`Seat.is_bot`；`Room.bot_seats/human_seats/
human_count/human_members`；`Lobby.add_bot/remove_bot`；
`_leave_unlocked()` 的房主迁移跳过 bot 座（D2）；最后一个**真人**走时把
bot 全摘掉、房间跟着解散（`LeaveResult.dropped_bots`）。

**改 `server/gameserver.py`**：加 `send_system_chat`（只发自己）/
`room_system_chat`（含自己）/ `broadcast_seat_leave`（action 1）；
`on_chat()` 里插命令层（惰性 `import bot`）；`after_someone_left()` 里
`check_pvp_finished()` 改由 `room.human_members()[0]` 发起 —— 原来的
`members[0]` 可能是 bot。

**测试**：`server/test_bot.py` 40 个用例（连接夹具从 `test_room.py` 借，
不复制一份）；`test_lobby.py` 加 `BotSeatTests` 11 个纯模型用例。
`run_tests.py` 挂上 `test_bot`。

## 顺带的两个发现

1. **§7 那个坑不存在了。** D1 选了假连接，`Room.members()` 天然把 bot 数成
   一个成员，`sync_peer_relay()` 的 `>= 2` 判据自动就是「会动的座位数」。
   M2 的清单里划掉这一条（写进 FINDINGS §13）。
2. **客户端自带的「踢出」按钮对 bot 天然可用**，`on_kick_out` 整条链在
   `BotConn` 上跑得通，单测钉住了。不用写第二条删除路径。

## 偏离 PLAN 的地方（都记进 DECISIONS）

- **D9** 没做 `BotManager` —— 会造出两个真相源（manager 一份、`Seat` 一份），
  而广播只读 `Seat` 那份。改成 `Seat.is_bot` + 扫座位。
- **D10** 非房主敲命令：**不吞**这行聊天（照常广播），但私下回一句原因。
  PLAN 的两条要求（「不要吞」和「说清原因」）其实不冲突，两件事都做。
- **D11** `BotConn` 不进 `_conns` —— 否则 `latest_conn()` 会让
  `tools\gs_ctl.py` 对着一个 bot 发命令，而 bot 的 `send()` 是空操作，

## 踩到的坑

`Conn.broadcast_system_chat()` 和 `Conn.announce_join()` 用的都是
`broadcast()`（**排除自己**）。房主敲完 `/bot`，他自己既看不到系统提示、
座位上也不会建出 3D 模型。加 bot 必须走 `broadcast_seat_slot()`（含自己）。
写进 FINDINGS §15。

## 顺手做的 M4 第一步（纯离线侦察，不依赖 M1 的实机结论）

把 174 张 `.map` 的头部批量解了一遍，**推翻了会话 01 的一个结论**：
版本号不是「8 和 18 两种」，而是 **7 种**（v7/8/9/13/15/16/18，其中 v18 87 张、
v15 41 张、v16 23 张）。会话 01 只抽了 3 张样本。照旧结论写「两个分支」的
解析器会让 155 张图走错分支。已勘误进 FINDINGS §9，并附上各版本体部开头的
共同形状（16 个 0 起头；v13 起多插 2 字节）。

另外确认 ini 段 174 张**只含 11 个背景渲染键**，和地形无关，M4 可整段跳过。

## 然后把 M4 的格式整个逆完了

用户选了「继续 M4」。这一轮把 `.map` 从头逆到能用：

1. **找到解析器** `World::LoadMapData`(`0x47429e`)，逆出读流原语和整体布局：
   头部 + ini + **19 类循环**（`[ebp-0x14]=0x13`），每类 `i32 count` + count 条记录；
   v>=13 是「type + blob」，v<13 是内联 7 个 float。
   **174 张实测逐字段读下来 0 张抛异常**（FINDINGS §17）。
2. **给 type 号起了名字**：从工厂 `0x513278` 的跳表走到构造函数，
   再用 `re/vftables.json` 查 vftable -> 类名。得到完整对照表，其中
   **type 200 = `TerrainObj`**（铁证：它的 `GetType()` 就是 `mov eax,0xc8; ret`）、
   201 = `HidingObj`、108 = `RespawnPointObj`（M2 也用得上）。
3. ★★ **发现地形的形状根本不在 `.map` 里** —— `TerrainObj` 的 blob 解完只剩 4 字节，
   内容是「位置 + 缩放（负数=镜像）+ 旋转 + **贴图路径**」。
   **实心区域 = 那些 PNG 的 alpha 并集**（FINDINGS §18）。
   把 `Camel00` 的 19 块按中心贴出来，得到一座结构完全正确的宫殿 ——
   柱子顶着平台、地面在最下方，一眼就能确认锚点是**中心**不是左上角。

⇒ **M4 原计划里「逆 `.map` 的碰撞段」这件事不存在**，改成「解 `.map` 拿贴图变换
→ 合成 alpha 位图 → 抽站立面」。PLAN 的 M4 描述要跟着改。

顺手修了 `tools/re_bs.py` 里写死的 `D:\work\popshot\...` 绝对路径（那份文件恰好
还在且 sha256 一致，所以一直没暴露），改成仓库相对路径 + 老位置兜底。
