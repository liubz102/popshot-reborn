# 会话 37（2026-08-29）—— 道具刷在白线上、捡来的枪不还原

用户又打了一局道具赛，报了两条：

1. 「有一把特殊枪掉落在平台下方的地面上，而 bot 站在上方平台，bot 走到道具枪的
   正上方时，枪被 bot 捡起来了。正常不应该捡起来，bot 只是横坐标走过去了，
   纵坐标还不对呢。」
2. 「bot 捡到道具枪后，过一段时间后，道具枪应该恢复成正常枪的，但是 bot 从此
   以后一直拿着道具枪，不会自动恢复。」

两条都**逆到底了**，没有猜的成分。

## 一、掉落物穿过单向平台（§114 / D72）

第一反应是「拾取判定漏了 y」—— 不是。`_item_pickups()` 用的是三个碰撞圆的
二维相交，纵向差一层平台根本够不着。问题在**它拿来比的那个坐标**。

逆出来的四件事：

* `Item::Tick`（主虚表 `+0x24` = `0x51f37a`）没被捡就 `jmp 0x50d404` ——
  和弹体走**同一条**物理流水线（§110 那条）；
* 重力 `[vft+0x9c]` = `0x4abd7f` → **1.0**，阻尼 `[vft+0xa0]` → **0.0**；
* 扫掠 `0x50e759` 的 `0x50ea99` 那段：`cell==2`/`3` 恒挡，**`cell==1` 要
  `[vft+0x100]` 点头**，而 `Item` 那一格是 `0x46e188` = `xor al,al ; ret`
  —— 和 19 个弹体类同一个 ⇒ **单向平台不挡掉落物**。
  ★ 对照组把这条钉死了：`Character` 的同一格是 `0x501b65` =
  「没按 ↓ **且** vy ≤ 0」，正是「站得上去、往上跳穿得过去」。
* 落地分支 `0x50f0cc` 用 `坐标 + [vft+0x104]` 探地形，而掉落物类
  （ItemBox / 17 件 PvP 道具 / 三把枪）**一律**是 `0x51fab6`，写死
  `(0.0, 20.0)` ⇒ **静止时坐标 = 地面 − 20**。

⇒ `ground_item_spawn()` 挑的「站立面」含白线，东西刷上去就穿过去掉到下面那层
地面；服务端却一直按白线的高度记在 `quest.items_at` 里。bot 走在白线平台上、
横坐标一对上，就和那个**过期坐标**相交了。

**改**：新增 `mapdata.MapTerrain.first_solid(x)`（第 x 列最上面那块 cell ≥ 2
的格子）；`ground_item_spawn()` 改用它，`ITEM_SPAWN_LIFT` **24 → 20**
（20 就是上面那个探地偏移，不是估的）。

## 二、捡来的枪是限时 / 限发数的（§115 / D73）

`weapon.ini` 全表只有四把有额度：

```text
[ch-nuke]      ForceCount=3        3 发
[ch-flamer]    ForceTime=15000     15 秒
[ch-water]     ForceTime=10000     10 秒
[ch-powershot] ForceCount=14       教学关，PvP 刷不到
```

链路：`XxxItem::vf_11c` → `0x517121(角色, 武器id, 0)` 且 eax=0（那两个 0 就是
「用这把枪自己的额度」）→ `0x48ba5f` 写进持枪器 `[+0x30/0x34/0x38]`；
开火 `0x5151dd → 0x517383 → 0x48bac2` 减发数；每次刷新武器 `0x48be09` 判
「两个都到头 ⇒ `[+0x2c] = −1` 换回去」。

这本账记在**持枪那台机器**上 ⇒ bot 没有本机 ⇒ 没人替它数；而
`rpChangeWeapon` **不带额度** ⇒ 收方也不会自己换回来。两头都没人管，
所以它一辈子举着。

**改**：`bot_weapons.json` FORMAT 7 → 8（新增 `force_ms` / `force_count`，
`tools/weapondata.py` 和 `server/weapondata.py` 一起动）；
`BotConn.item_weapon_shots` / `item_weapon_until` 两格额度，和 `item_weapon`
一起由新的 `drop_item_weapon()` 清；`_spend_item_weapon_shot()` 挂在开火那一刻；
`_expire_item_weapon()` 每帧按原版判据结算，到头了清掉 + 补一发
`rpChangeWeapon`（挂在 `_advance_*` 那一组里 —— 「15 秒到了」是时间决定的
事实，和有没有新位置点无关）。

## 三、反弹之后落点和炸点差 264 个单位（§116）

用户 16:20 又报一条：「bot 扔了一个苹果弹，从平台上面扔到下层地面，
反弹过后落点和炸点位置不一致。」这是 §98 挂了四个会话的那一半。

### 取证的路子（下次照这条走，很快）

1. `logs/server.out` 的 `开火` / `爆炸` 行**是按状态翻转去重的**，
   一局只有两行 —— **别指望从它找具体某一发**。
2. 客户端 `bshook` 日志才是真值，两类行：
   * `FIRE>` = 收到的 `rpFire`（发射点 / 角度 / 力度 / 武器）；
   * `PROJ.` = 那颗弹体**逐帧**的位置和速度。
3. ★★ **爆炸点也能从客户端日志读**：爆炸那一刻收方会造 4 个 `1000500`
   （`SplashDamage`）对象，那四行 `FIRE>` 的发射点就是服务端给的爆炸点。
4. 拿 `FIRE>` 的参数造一个 `bot.Shell` 用服务端代码复算 —— 那一发复算的
   第 45 tick 落在 `(24.76, 814.86)`，实机爆炸点 `(24.75, 814.86)`，
   **一位不差**，复算可信。

### 真因

复算和客户端逐帧对到第 6 tick 完全重合，**第 7 tick 服务端说撞地形、
当场往左弹开**，客户端那颗一路自由落体到第 16 tick 才真落地。
那一格：圆心 `(145.3, 634.0)`，最近的实心格在**右边 6.7 个单位**（斜坡左沿），
正下方是空的。

⇒ §83 把碰撞形状拟合成半径 `Size` 的**实心圆盘**，圆盘各向同性，
「贴着侧面飞过去」就被误判成撞上。

原版的采样点组（`0x50e759` 每走一格拿它去查）：

```text
offset[0] = ftol([vft+0x104])                   ← 弹体类一律 (0, 半径)
offset[n] = ftol(形状中心 + 半径 × 单位速度矢量)  ← 0x50e98c 那五句
```

**朝前一个点 + 正下方一个点。** 5312 个客户端样本：圆盘误判 102 次，
新形状 2 次，两者都没漏判过真反弹。

### 顺带收口

* 反弹落点**取整**（收方逐整数格扫掠，日志里每次反弹落点都是整点）；
* 法线采样点改用**真正被挡住的那个探测点**，不再拿 `_nearest_solid` 猜。

21 条弹道末点误差：中位 **0.12 → 0.06**、最大 **263.89 → 65.21**，
那一发 **263.89 → 2.35**，14/16 条 ≤ 0.16。

**改**：`bot.shell_probe_offsets()` / `_probe_blocked()`（★ 保留 §83 那条
「图顶上面不算实心」）、`_terrain_contact()` / `_muzzle_blocked()` 共用；
`_bounce_shell()` 落点取整；`_block_facing()` 用被挡的探测点；
`_disc_offsets` / `_rim_offsets` / `_disc_blocked` 删掉。
新增 `BotShellProbeShapeTests` 五条。全量回归 **1652 项**双运行时通过。

### 这一条的遗留

⚠ 21 条里还有两条（55.8 / 65.2）没收干净，都是**接触格差 1 格 / 反弹早
1 个 tick** 的量化残差。试过把采样换成整数端点的 DDA 线，只从 65.21 降到
64.74 —— 要真消掉得逐位复现收方那条 Bresenham 线和 ftol 取整，**不划算**。
这就是 §98 剩下的那一半，先留着。

## 四、加强道具（强力射击）打完不恢复（§117）

用户 16:56：「bot 捡到加强道具后，苹果弹模型会变大，这个没问题，但是变大的
苹果弹应该打几次之后就恢复的，但是 bot 的苹果弹一直不恢复。一开始的修复
没起效吗」

★ **不是同一条链**。§115 修的是地上那三把**枪**（`weapon.ini` 的
`ForceTime` / `ForceCount`）；这一条是箱子道具挂的**状态**
（`Item.ini` 的 `CharAttr` → `Status.ini` 的 `Magazine`）。

```text
10307 PowerShotItem → Item.ini CharAttr=7 → Status.ini [7] 파워 샷
                      Magazine=3  DamageRatio=2.0  SizeRatio=2.0
```

`SizeRatio=2.0` 就是「模型变大」。这一族（还有 6 三重射击、10 毒弹）
**只有 `Magazine`、没有 `Time`** ⇒ 时长 −1（无限），结束条件是
「持有者打完 3 发」，只有他那台机器数得出来，数完发一发 `0x040d`（§200）。
bot 没有本机 ⇒ 一台都不数。实机日志钉死：16:55:06 bot 用了 10307，
此后到这一局结束**一发 `0x040d` 都没有**（真人座位 0 同一局有三发）。

**改**：`gameserver.MAGAZINE_STATUS` 三条数据；`BotConn.magazine_attrs`
（死亡 / 换图跟着清，那时客户端自己会拆，不用补包）；`_use_held_item()` 起算、
`_spend_magazine_shots()` 挂在开火那一刻、数完广播 `0x040d`；
★ 倍率也跟上 —— `Shell.damage_ratio` / `size_ratio` 在开火那一刻定死，
`Shell.radius = Size × SizeRatio`（`SizeRatio` 非跟不可：每台客户端都把
bot 那颗放大了，服务端还按原半径判就又不是同一颗，正是第三节刚修的那类）。

新增 `BotMagazineStatusTests` 八条。全量回归 **1660 项**双运行时通过。

### 这一条的遗留

* ⚠ **`OneMagazine`（毒弹独有的一格）含义没逆出来**，先当它不影响发数。
* ⚠ 「一发」按 `rpFire` 算（和 §115 的 `ForceCount` 同口径）。
  **三重射击一发出三颗**，两种读法会不一样 —— 苹果弹一发一颗，
  用户这一条碰不到，等有人报再查。

## 五、地上的道具永远不消失（§118）+ 反射护盾（§119）

用户 17:50 / 17:58 / 又一条，三件事：

1. 「地上有一个胶水道具，bot 走过去之后，它捡到后突然变成了特殊武器，
   道具识别是不是不对。」
2. 「地上掉了一个特殊武器，过了一会儿，武器闪烁消失，之后 bot 走过去却捡到
   了特殊武器。」
3. 「我捡了反射道具，我有反射效果时，bot 扔的苹果弹到我身上还是能直接炸掉。」

### 1 和 2 是同一个根因，而且 1 **不是识别错**

服务端日志直接把它摆出来了：

```text
[17:49:20.758] 刷道具 句柄=0x40000008 物件=10200 核弹发射器 @ (1396, 644)
[17:50:51.443] 刷道具 句柄=0x40000011 物件=10400 胶水       @ (1409, 630)
[17:50:55.928] bot 捡到 10200 -> 换成核弹发射器     ← 已经躺了 95 秒
[17:50:55.929] bot 捡到 10400 胶水
```

两件只差 **13 个单位**，bot 一步踩到两件；玩家看得见的只有胶水，
那把枪 82 秒前就从他屏幕上消失了。

寿命逆出来了（`Item` 构造函数 `0x51f2b7`）：`13000 ÷ [0x6dc528]`（=32）
喂给 `[item+0x2ac]` 的计时器 ⇒ **13 秒**；闪烁是最后 **2.6 秒**
（`0x51f39a` 的 600 / 2600 两道门，每 200 ms 明暗一次）。
★ 同一段还写死了**道具碰撞半径 18.0f**（`0x51f2e2`）—— §100 估的 20 收口。

**改**：`ITEM_LIFE_SECONDS=13`、`RoomQuest.items_born` + `expire_items()`，
`due_item_spawn()`（看配额之前）和 `_item_pickups()`（扫之前）各调一次；
`BOT_ITEM_RADIUS` 20 → 18。**不发任何包**（客户端自己删的）。

★ 用户问「还有没有别的道具有同样毛病」—— 服务端替 bot 记的四本账逐本查过：
`slow_mines` 有 3/15 秒（§108）、`smokes` 记的就是散掉时刻、`freeze_bursts`
是一次性待办，**只有 `items_at` / `items_on_map` 缺到期**，已修，
而且**所有**服务端刷的道具都受影响，不只特殊武器。

### 3 反射护盾

原版判定在弹体撞人那条路上（`0x47f07c` 起）：目标是「角色」这一类
（`vft+0x48() == 0x190`）且 `HasAttr(属性表, 3)` ⇒ **不算命中**，
把弹体从半径 **50** 的圆里沿 −v 退出来（最多 5 步）、对半径方向镜像速度、
接着飞，**速度只换方向不减半**（没有地形反弹那两个 ×0.5）。
`Status.ini [3] Time=8.0`。真人之间各机器各算，bot 的弹体归服务端 ⇒ 不记就照炸。

**改**：`REFLECT_ITEM_ID` / `REFLECT_SECONDS` / `REFLECT_RADIUS` +
`RoomQuest.reflect_until`（`note_area_item()` 里记，10314 记全队）；
`_reflect_shield_hit()` / `_reflect_off_shield()` 排在 `_shell_step()`
判人判地形**之前**（护盾圆半径 50，比谁的碰撞圆都大）。

新增 `ItemLifetimeTests` 五条、`BotGhostItemTests` 四条、
`BotReflectShieldTests` 六条。全量回归 **1693 项**双运行时通过。

### 这一节的遗留

* ⚠ 原版还有一条「`[char+0x2b0] == 2` 时护盾半径 70」——**那一格是什么没
  逆出来**（写它的地方按 byte / dword 两种都有，不是同一个类），一律按 50。
* ⚠ 道具寿命修好之后，**同时躺在地上的道具会明显变少**（以前是鬼占着 8 件
  的名额）：13 秒寿命 + 10 秒刷一件 ⇒ 常态 1~2 件。这是原版行为，
  觉得太少该调的是 `ITEM_SPAWN_INTERVAL`（我们定的，D109），不是寿命。
