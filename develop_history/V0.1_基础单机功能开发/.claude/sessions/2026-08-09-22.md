# 会话 22 —— 2026-08-09

**接手时的状态**：会话 21 刚把 11 个商城角色和 3 个隐藏关卡解锁。
用户实机玩下来报了两个后遗症：

1. 任务模式进房间后，**有小概率**只能看到初始 3 个角色，有时候又正常。
2. 除了一开始的 4 个地图，其他地图**只能在新建房间界面**选，
   一旦进了房间就换不过去。

**结论：又是两把完全不同的锁**（和 §119 一样，看起来同类其实无关）。

---

## 做了什么

### 1. 定位「有时候只有 3 个角色」（§120 A）

没用探针也没抓包，全靠静态 + 已有日志：

- `0x4698af` = 建「人物选择」头像按钮的地方，写 `[RoomStage+0xf4]`。
  **全镜像只有两个调用点**：RoomStage 构造函数 `0x466979` 里的 `0x466ea3`，
  和滚动条回调 `0x4698a4`。→ 按钮**只在房间构造时建一次**。
- `ChangeStage`(`0x40e47f`) 只写 `[app+0x58]`/`[app+0x5c]`，
  **下一帧**才真构造。→ `0x0201` 和 `0x030b` 必须落在同一次 recv。
- 翻会话 21 的日志：`0x0201` 和 `0x030b` 两行时间戳差 **~1 ms**，
  客户端一帧 16 ms → **约 6%**，正好是「小概率」。

修法 `Conn.send_batch()`：建房四连发合成一次 `sendall`（259 字节）。
「结算看完回房间」三连发同因同修（`0x0403` 也 `ChangeStage(5)`）。

### 2. 定位「新关卡进房间换不过去」（§120 B）

- 先按 §119 的思路找第三处 `OpenLocale` 判定 —— 扫出 6 处
  `mov ecx,[0x72e320] … shl … test`，其中 `0x4653a8` 是 **PvP** 的地图列表
  （vftable 槽 37 属于 `DlgSelectPvpMap`），不是任务房的。**这条是死路。**
- 换个方向：`DlgSelectQuestMap` 的 vftable `0x66a19c` 槽 30 = `0x466264`
  = `OnEvent`。里面 `stageLBtn`/`stageRBtn` 用的是**当场按地区写死**的
  关卡 id 环，和 map.ini / OpenLocale 一点关系都没有：
  韩/日 `[3,2,1,4,5,6,7,3]`、中国 `[3,2,1,4,3]`。
- 会话 21 的日志直接印证：房间按 ◀▶ 发出的 `0x0302` 正好循环
  `Quest03_1 → Quest02_1 → Boss00 → Quest04 → Quest03_1`。

修法：`bshook` 地区 patch 组加第 4 处，`0x46631d` `74 45` → `EB 45`。

### 3. A/B 把因果钉死

新开关 `gameserver.py --room-burst-delay <毫秒>`（同 D047 的思路）：

```text
--room-burst-delay 30  ->  3 个头像、无滚动条、角色被打回 0 泰尔
                           logs/shot_s22_ab_broken.png   ← 用户报的原始现象
默认（合并成一次写）    ->  6 个头像 + 滚动条 + 存档里的布洛克
                           logs/shot_s22_ab_fixed.png
```

## 遗留

1. **第 4 档难度（극한）没开**，故意的（D059）。同一个函数 `0x466264` 里
   `0x466309` 和 `0x46649c` 两处把中国版压成 3 档。要开就得连
   `#Extreme.map` 是否齐、`0x468176` 的准入上限（§118）一起验，是独立一摊。
2. **真通关一次做终验**（打到关底，不是死出去）—— 从会话 17 欠到现在。
   `quest_unlock_all=false` 的原版逐级解锁路径仍然只有单元测试覆盖。
3. **干净机器上的便携包终验**仍未做（无系统 Python、Defender 开启）。
4. 会话 21 的「防御性重发 `0x030b`」现在多了一层意义：它和 `0x0403`
   在同一批里发，正好也解决了回房间那一侧的同一个竞态。
