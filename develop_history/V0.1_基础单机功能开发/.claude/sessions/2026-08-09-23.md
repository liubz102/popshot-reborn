# 会话 23 — GameGuard 绕过从定时内存 patch 改为 DR0 + VEH

日期：2026-08-09

## 起因

便携包发到另一台电脑后，启动脚本显示服务端和 `bsloader` 已启动，但登录框没有出现。
远端没有带回日志，无法断言根因；用户特别关注旧版 GameGuard patch 固定等待 +2.5 秒
是否会随机器性能漂移，并要求改成事件驱动。

## 实现

- 新增 `hook/gg_bypass.h`，集中保存 `0x54b0fc`、成功码 `0x755`、握手环境变量和
  DR0 控制位，保证 loader/DLL 同源构建。
- `bsloader` 创建唯一命名事件，通过 `BSHOOK_READY_EVENT` 传给客户端；APC 注入后
  同时等待“DR0 已武装”或客户端退出，10 秒只作为初始化失败超时。
- `bshook` 在 DllMain 注册优先 VEH、记录主线程 id；专用线程等主线程 EIP 离开
  `ntdll/kernel32/kernelbase/bshook` 后，暂停该线程并设置执行断点
  `DR0=0x54b0fc`，再发握手。
- VEH 命中时先核对 `E8 CF 60 01 00`，然后撤掉 DR0，设置
  `EAX=0x755 / EIP+=5`。不再写 `0x54b0fc`，旧 `try_patch_gameguard` 已删除。
- +2.5 秒改名为 `CODE_PATCH_DELAY_MS`，只保留给地区锁、挂机计时器、
  SnowCipher/RendererInit 等仍会改代码的逻辑。

## 一次失败及其结论

第一版让 DllMain 装完 VEH 后立刻通知 loader，由 loader 写 DR0。API 返回成功但断点没命中：
`LoadLibraryA` 仍处于 APC 内，返回时 `KiUserApcDispatcher/NtContinue` 恢复旧 CONTEXT，
把刚写的 DR0 清零。`logs/bshook_20260809_022348_pid32164.log` 随后记录 GameGuard
失败并 exit code 1。

最终版把武装动作移进 DLL 线程，握手语义改为“APC 已离开且 DR0 已武装”。这次失败已写进
FINDINGS §121 和 D060，避免以后重新踩。

## 验证

- 有效实机启动 5 次，5/5 均为：VEH 安装 → 主线程离开 APC → DR0 武装 →
  `0x54b0fc` 命中 → 可见 `#32770 "PopShot"` 登录框。
- 5 次均无 `Protection Error` / GameGuard 错误框。
- 一次上个实例尚未退出时的重叠启动被单实例互斥体挡掉，按 FINDINGS §9 排除，
  不计入 5 次。
- `C:\Python314\python.exe -m unittest test_account_store test_gameserver`：228 项全过。
- 便携目录内再次启动通过；重新生成 ZIP 后 `7z t` 为 `Everything is Ok`。
