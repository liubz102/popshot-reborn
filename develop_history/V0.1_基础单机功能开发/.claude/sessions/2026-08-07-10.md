## 做了什么

### 1. 先把会话 09 留的两条线索查了，结果**都是错的**（→ FINDINGS §89、§90）

PROGRESS 留的下一步是「查 `0x0408` 的服务端方向处理器 `0x551e44`，
看能不能反推出伤害/血量结构，让服务端自己算死亡」。

- **`0x551e44` 不是伤害包处理器**。地址没记错（跳表 `@0x54e5ae` 确实指向它），
  但它里面根本没有反序列化调用，做的是遍历 6 个座位 + 播一条
  `!! %s 님과의 네트워크 상태가 좋지 않습니다 !!`（「与 %s 的网络状态不佳」）。
  **是延迟告警，服务端千万不要发。**
- 顺手发现客户端**有** `Packet_gcpRespawnCharacter`，opcode 是 **`0x0413`**
  （发送点 `0x553e48`，`push 0x413`），结构和服务端方向的 `0x0419` 完全一样。
  但它的调用者 `0x4fe78f` 在闯关模式下走的是**什么都不做**的分支：
  `[ebp-8]`（重生点索引）初值 -1，只有 `0x4fe70e` 会填它，
  而闯关那条路径根本不调它 → `0x4fe81a: cmp [ebp-8],-1 / je <ret>` 必然跳走。

  **所以「死亡时客户端什么包都不发」是客户端代码写死的**，
  §87 那句「真服务器按 0x0408 的伤害自己算血量」两头都不成立。

### 2. 造了个调试控制通道，绕开「必须打完关卡」这个死结（→ §91、D037）

`gameserver.py --control-port 27800`（默认开）+ `tools/gs_ctl.py`：
一行一命令的纯文本 TCP，服务端把命令翻成真正的游戏包推给当前客户端。

```text
status / endgame / endgame-probe / respawn / back-to-room / raw <op> <hex>
```

实现上唯一要小心的地方：**`Conn.send` 必须加锁** ——
SimpleCipher 是逐字节推进的流密码，控制线程和收包线程交错加密会让整条流
永久错位，客户端从此再也解不回来。

### 3. 实机：一次就把 `0x0411` 验完了（→ §93）

走完整流程（登录 → 大厅 → 任务频道 → 建闯关房 → F5 → 关卡加载 → 剧情 → 战斗），
在「神秘岛 简单」计时器 12:59 的时候推一发 `endgame-probe`（12 个业务值 = 101..112）：

- **客户端立刻撤掉全部战斗 HUD**（计时器、战绩栏、角色 HP/SP、武器栏），
  光标变沙漏，关卡场景还在，**不崩**（`logs/shot_s10f_endgame.png`）
- 新工具 `tools/probe_endgame.py` 读客户端内存，四个全局
  `105 / 102 / 104 / 103` 与 §87 的字段表**一个不差**

  ★ 探针基址一开始找错了：`0x4a4096` 开头的 `mov ecx,[0x72e29c]` 只是拿
  LobbyStage 去做座位校验，真正的基址是 `[esp+8]`，来自调用方
  `0x5518a7: push eax`，而那个 eax 是 `dynamic_cast<GameContextQuest*>`。

### 4. `0x0403` 切回房间 —— 顺带把四个字段的语义捡了回来（→ §94）

按 §87 末的推测发 `back-to-room`（服务端方向的 `0x0403`）：
**客户端干净地回到「待机房间」**，房间面板全正常。
关卡 → 结算 → 回房间这条链打通了。

而且右上角玩家数据栏把答案直接写在脸上 —— 发的是 101..112，显示：

```text
Lv.1  [经验条金黄满格] 200%
经验值: -2 / -1        金币: 105
```

对着 §93 读到的全局一算，当场闭合：

```text
102 - 104 = -2   ✓    103 - 104 = -1   ✓    -2/-1 = 200%   ✓    105 = 金币   ✓
```

| 包字段 | `values[]` | 语义 |
|---|---|---|
| `pkt+0x10` | `[1]` | 玩家总经验值 |
| `pkt+0x14` | `[2]` | 下一级所需总经验 |
| `pkt+0x18` | `[3]` | 本级起始总经验 |
| `pkt+0x1c` | `[4]` | **金币**（客户端 `+=`，发的是本局所得） |

三个经验字段都是**绝对累计值**，UI 自己做减法。

### 5. 把结算接到存档上

`Conn.send_end_game()`：按 `0x0410` 报的累计分数发经验 + 金币，
先写 `accounts.json` 再下发（客户端拿到的必须是已入账的总额，
否则重登一次就退回去了）。`AccountStore.add_quest_reward()` 负责累加 + 推等级。

经验曲线 `EXPERIENCE_PER_LEVEL = 100` **是本地自定的，不是逆出来的** ——
客户端只按三个绝对值做减法，不知道也不关心曲线长什么样。

顺带 `0x0406` 位置同步也解析了，重生坐标改用客户端自报的最后位置。

测试 45 → **65 项全通过**。
