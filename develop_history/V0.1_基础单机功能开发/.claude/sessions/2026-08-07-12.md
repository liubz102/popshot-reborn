# 会话 12 — 2026-08-07

修用户报的两个现象：**任务退出回房间就弹「90秒无任何动作，返回至游戏大厅。」**、
**提示框点确认关不掉**。查明是同一条链上的两截，服务端 + 客户端各改一处，实机跑通。

## 用户报的现象

1. 任务退出返回房间后，似乎每次都会立即弹出「90秒无任何动作，返回至游戏大厅。」
2. 上述提示框点击确认没有任何反应，关不掉

## 查的过程

### 1. 按韩文原串定位（D034）

中文「90秒无任何动作」在镜像里搜不到，改扫 UTF-16 的韩文串：

```text
0x0066a9e0  '1분 30초 이상 동작이 없어 로비로 돌아갑니다.'
```

唯一引用点 `0x46767a`，在 `RoomStage::Update` 里（`RoomStage` 的 RTTI 从
vtable `0x66a38c` 前面的 COL `0x698e24` 认出来）。

### 2. 顺着判定链读出整个机制（§101）

```text
[0x72e29c] = LobbyStage
  +0x3e8 = Timer{vptr, duration, start, deadline}
  0x4082ae LobbyStage::ResetIdleTimer(): Timer::Start(90000)
  0x46761c RoomStage::Update 里 Timer::IsExpired() -> 弹框
                                                  -> 0x4676cb 重置计时器
                                                  -> 0x467303 发 gcpLeaveSession(0x0203)
```

两个关键认知：

- **计时器只有四个重置点，没有一个是收包触发的**（窗口过程的鼠标/键盘弹起、
  `LobbyStage::ResetSession`、弹完框自己重置、战斗内 `0x4906ac`）。
  服务端够不着 → 现象 1 只能改客户端。
- **`0x0203` 的服务端方向 `0x54fffe` 一直没实现**：客户端发完就干等，
  于是留在房间里，每 90 秒再叠一个一模一样的框 → 现象 2。

### 3. 顺手推翻 §100 末尾一条错记

「点提示框的确认也点不掉」其实是**坐标算错**：
`screenshot.py` 抓窗口矩形（1030x797，含标题栏），`click.py` 用客户区坐标
（1024x768），差 **(x-3, y-29)**。按截图像素直接点会低 29 像素。
拿一个挂了 35 分钟的旧客户端连点 25 次「确认」，整摞框全点没了
（`shot_s12_ok25.png`）—— 坐实了「是堆了一摞」而不是「点不动」。

## 顺带发现

- **在这之前玩家其实根本没法退出房间** —— 退出/ESC 和挂机踢出发的是同一个
  `0x0203`，服务端两边都没应答。修 `0x0203` 不是「顺带」，是补一个缺失功能。
- 战斗内那条重置（`0x4906ac`）的判据是 `GameContextQuest` vf `+0xa4`，转发给
  `[this+0x384]` 的 vf `+0x10`（座位号为参数），**返回值 <= 0 才重置**。
  实测分数为 0 的一局，关卡里不按键也会被重置；有分数之后大概就不会了。
  但**结算 → 回房间这一整段肯定不重置**。

## 踩的坑

- `hook/build.bat` 在游戏还开着时会 `LNK1104: 无法打开文件 bshook.dll` ——
  编译前先 `Stop-Process BigShot`。
- PowerShell 的 here-string 喂给 `python -` 会掉进 REPL 并刷屏报错，
  仍然只能用 Bash 的 heredoc（FINDINGS §8 那条依旧有效）。
- `screenshot.py` 偶尔抓到全黑：窗口没真正拿到前台。**发现内容不对就重抓**，
  或者先 `click.py --move` 把它顶上来。
