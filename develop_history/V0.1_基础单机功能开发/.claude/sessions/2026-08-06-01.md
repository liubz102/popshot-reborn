## 做了什么

### 1. 全量静态侦察（本会话主要产出）

用 Python（Bash heredoc 喂 stdin）手写 PE 解析器，把 `game_org\Popshot\` 下
所有 exe/dll 的节表、导入导出、熵值、时间戳过了一遍，另外：

- 解析了 `BigShot.exe` 的资源目录树（发现资源语言 ID = 1042 韩语，内容极少）
- 用 7-Zip 列了 NSIS 安装包的 156 个文件，确认 `game_org` 完整
- hexdump 了 `BigShotCN.ini` 和 4 个 `.pkn` 的头尾，识别出加密容器格式
- 查了本机环境：编译器、Python、7-Zip、VC++ 运行库、d3d9、注册表、VM 软件

**全部结论已写入 `.claude/FINDINGS.md`，此处不重复。**

三个最关键的发现：

1. `BigShot.exe` 是 **ASProtect 2.x 加壳**（`.adata` 节 + 空节名 + 熵 8.0 +
   `push 0x7B2001 / call $+5 / ret / ret` 壳入口）→ 静态改不动，只能运行时处理
2. **本机已有 MSVC x86 工具链**（BuildTools 2017/18）→ 写注入 DLL 不用额外装编译器
3. 用户报的失败是 **GameGuard 错误框** → 这反过来证明**壳在 Win10 上解得开、
   游戏代码已经在跑**，启动的拦路虎只有反作弊。这个信息大幅收窄了阶段 1-2 的范围。

### 2. 与用户确认了 4 个方向性问题

## 踩到的坑

- **PowerShell 传 python `-c` 脚本会被搅乱**：`r"D:\..."` 里的引号被吃掉，
  报 `SyntaxError: invalid syntax`。改用 **Bash 工具的 heredoc**（`python - <<'PYEOF'`）后正常。
- **PowerShell 输出含非 GBK 字符会抛 UnicodeEncodeError**：
  打印韩文/生僻 Unicode 时 python 的 stdout 编码是 gbk。需要时先 `encode('utf-8','replace')`
  或只打 repr。
- robocopy 退出码 1 会被 harness 当成失败，看 output 文件确认即可。

### 脱壳（阶段 1）—— 一次成功，且是整个工程的转折点
- 自写 `tools\dump_process.py`：客户端停在 GameGuard 错误框时 ReadProcessMemory 转储 + PE 化。
- 产出 `re\BigShot_22524.exe`，熵 8.0→6.48，879 个 RTTI 名可读。
- **重大情报**（详见 FINDINGS §9-§20）：120 个带名字的网络包、闯关/训练逻辑在客户端、

### 关键实测结论
1. 启动只卡 GameGuard，D3D9/音频/资源全 OK（bshook 日志时间线）
2. 单实例互斥体 `BigShot_Assa`（曾误判为注入被检测）
3. GameGuard.des 改名与否对错误框无影响（错误来自静态链接的 NPGameLib）
4. **点掉错误框「确定」进程立即退出 → 硬阻断，阶段 2 必须真正让校验通过**
5. 注入完全没被 ASProtect 检测
