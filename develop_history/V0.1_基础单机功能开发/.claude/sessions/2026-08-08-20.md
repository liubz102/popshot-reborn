# 会话 20 —— 难度解锁（2026-08-08）

## 用户带来的问题

> 任务模式下只能选简单难度，无法选择普通或者困难，选择后点开始就提示
> 「无法进行的难度，请降低难度」。

## 做了什么

### 1. 定位（全程静态，没用探针）

* D034 的老套路：把中文提示翻回韩文 → `플레이할 수 없는 난이도 입니다.
  난이도를 낮춰주세요` → `0x66a758` → 唯一引用在准入校验 `0x468176` 里，
  是它的**错误码 5**。
* 这个函数 §77 解过一半（错误码 3 = 「等级太低」）。当时那句
  「所以难度『简单』(1) 永远过」**已经把判定链写出来了**，
  只是没有人回头问「那别的难度靠什么过」。
* 闯关分支 `0x4683ba`：上限 = `min(map[关卡 id] + 1, 4)`，
  map 是 `[0x72e328 + 0x34]` = `[0x72e35c]`。
  （§77 记 `0x72e328`、会话 07 死路清单记 `0x72e35c`，
  **是同一张表**，差一个 `+0x34` 的成员偏移 —— 这次对上了。）
* 反查那张 map 的写入点：全镜像只有 `0x5539e2` / `0x553a63` 两处，
  分别是 `0x020c gspQuestReachedDifficulty` 和 `0x0416 gspUpdateQuestDifficulty`
  的处理器。**客户端自己永远不写**，我们两个都没发过 → map 恒空 → 上限恒 1。

### 2. 修

* 存档新增 `quest_difficulty`（`{关卡 id: 已通关的最高难度}`）和
  `quest_unlock_all`（默认 `true`）。
* 登录后、`sync-account` 时、通关记账后各发一发 `0x020c` 全量快照。
* 通关信号复用 D051 已有的 `0x0417`：`send_end_game(success=True)` 时把
  `(房间关卡 id, 房间难度)` 记进存档，只往上记。
* **只用 `0x020c` 不用 `0x0416`**：后者在「旧值 0 → 新值非 0」时会弹一个
  没读过的通知窗（`0x424b96`）。理由记在 D056。
* 新控制命令 `gs_ctl.py quest-difficulty [id 难度 ...]`。

### 3. 实机 A/B 对照

```text
存档全开        -> 「神秘岛 / 困难」F5 -> 直接进加载 -> 战斗画面顶部写「困难」
ctl 推 {3: 0}   -> 同一房间同一难度 F5 -> 复现出用户报的那个弹框
ctl 推回存档    -> 同一房间 F5 -> 又能进
```

三张截图在 `logs/shot_s20_*.png`。全程 0 个 `0x0106`。

### 4. 顺带

* 重新生成便携包（会话 19 那份是改 `server/` 之前打的，已经过期）。
* 测试 176 → **200 项**，开发 Python 和内置便携运行时各跑一遍都过。

## 结果

* ★★★★★ 三个难度都能开局了，`logs/shot_s20_battle_hard.png` 是困难难度的战斗画面。
* 存档里真的记进度；`quest_unlock_all: false` 一置就是原版逐级解锁。

## 遗留

* **`quest_unlock_all=false` 的逐级解锁路径实机没走过**（只有单元测试）。
  要验它得先真通关一次 —— 和「真通关终验」那条欠账是同一件事。
* `0x0416` 的通知窗 `0x424b96` 没读，暂时不发这个包。
* 会话 19 欠的「干净 Win10/11 上的便携包终验」仍未做。

## 一条可复用的操作手法

★ **这个客户端的下拉框只在按住左键时展开，松开就收。**
建房对话框里换难度/换关卡必须「按住箭头 → 拖到条目 → 松开」，
连点两次是选不中的。会话 07 记的「点箭头只高亮不展开」有一半是这个原因。
