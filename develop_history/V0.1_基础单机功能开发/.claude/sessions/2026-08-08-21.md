# 会话 21 —— 解锁隐藏角色与隐藏关卡（2026-08-08）

## 用户带来的问题

> 我把解包后的资源放在了 `Pack_decrypt` 里，资源里似乎已经包含了十几个角色
> 以及 6 个 boss，但实际在待机房间里时可以选择的角色只有 3 个，
> 地图/boss 也只有 4 个。请调查有没有代码实装，有的话默认全部解锁
> （记忆中有些角色要在商店里花钱买，但目前不打算做商店）。

## 结论：不是资源缺失，是**两把完全独立的锁**

| 缺什么 | 锁在哪 | 谁能开 |
|---|---|---|
| 11 个角色（id 100~110）| 背包物品判定（客户端等服务端下发清单）| 服务端发 `0x030b` |
| 4 个关卡（QuestId 5/6/7/8）| `map.ini` 的 `OpenLocale` 地区掩码 | 客户端 patch |

**只修一边都只能解决一半。** 细节见 FINDINGS §119、决策 D057。

## 做了什么

### 1. 角色：顺着「谁在数按钮」往下挖

`re/rtti_types.txt` 里搜到 `CharacterChanger` / `UiChrChangeBtn`
→ `vftables.json` 拿 vftable → `re_bs.py xref` 找到构造点
→ 建按钮的循环 `0x4f586c`：

```text
0x40713a(LobbyStage, 0)  数按钮个数
    for id in 100..110:  0x4070c2(id) 为真就 +1
    return 计数 + 3      ★ 0/1/2 白送 —— 这就是「永远只有 3 个」的来源
0x4070c2(id) = 我的座位已占用 且 [LobbyStage+座位*4+0x250] 非空 且 0x55853c(清单,id)
0x55853c(清单, id) = id<3 -> true；否则在 vector<int32> 里找
                     [(id+1)*1e6, (id+2)*1e6) 区间内的物品
```

再反查那份清单谁写：`0x406e4e`（构造时建空的）+ **`0x406ea1`**，
后者是跳表 `@0x406332` 索引 0x0b 的处理器 = **`0x030b gspSlotEquippedList`**。
客户端自己永远不写一个字节。

物品 id 用 `ShopItem.ini` 的真实商城条目对上了：
`[Item-101400001]`…`[Item-111400001]` = `(角色 id+1)*1000000 + 400001`。

### 2. 关卡：`map.ini` 的 `OpenLocale`

`Pack_decrypt/Data/map.ini`（UTF-16LE）里每张图一行 `OpenLocale`，
文件自己的注释就写着 `1 - 한국, 2 - 일본, 4 - 중국`。
QuestId 5/6/7 是 `OpenLocale=3`（只对韩日开放），中国版当年没上线。

客户端两处 test 这个掩码（`0x40b419` 启动读 map.ini、`0x4368cf` 建房下拉框），
**前者不匹配直接 `delete` 记录** —— 任何包都补不回来，只能改客户端。

§63 记的「目录里共 32 条记录」和 map.ini 里「`OpenLocale & 4` 的正好 32 条」
一对上，这条链就闭合了。

### 3. 修

* **服务端**：`build_slot_equipped_list()` + `Conn.send_slot_equipped_list()`，
  建房时排在 `0x0300` **之后**发。存档新增
  `character_unlock_all`（默认 `true`）/ `owned_characters`。
* **客户端**：`bshook.c` 加一组「地区差异 patch」，三处、都等长：
  - `0x40b41e` `8B 08` → `33 C9`（地图目录加载按韩国区算）
  - `0x4368d5` `8B 09` → `33 C9`（建房「任务」下拉框同上）
  - `0x4f67d9` `6A 18 58 6A 19` → `6A 10 58 6A 11`（见下）
  `BSHOOK_KEEP_REGION_LOCK=1` 整组退回原版。

### 4. 中途踩的坑：只解锁角色 → **进关卡必崩**

第一次实机验证时，房间里 14 个头像全出来了、关卡也能选，
但 F5 进关卡瞬间 `C0000005 @ 0x430857`。

崩溃报告的调用栈直接给出答案：`0x40bd40`(stage 7 工厂) → `0x477bab`
→ `0x4f5970` → `0x4f682a` → `0x430857`。也就是**战斗内**的
`CharacterChanger` 建按钮时炸的（房间里那个是另一套 UI，所以先看到的是成功画面）。

`0x4f676e` 起的 switch 按角色 id 硬编码图标下标，角色 110 是 0x18/0x19；
而这张图集**按地区换**（`0x558916` → `Images/Chinese/BigChrIcons_CN.smf`），
中国版只有 **24 帧**（韩国版 28 帧）。`.smf` 头就是
`int32 版本 + int32 帧数 + 帧数×32 字节`，一算就实锤。**图是真没有。**

修法：让 110 借用 106 시리아 的 (0x10,0x11)，5 字节等长替换。
战斗内换人条上它显示成 시리아 的头像，模型/名字/数值都不受影响。

### 5. 新工具

* `tools/probe_char_list.py <pid>` —— 把角色判定链每一格读出来。
* `tools/probe_quest_list.py` 现在会先看 `0x4368d5` 有没有被 patch，
  再决定「掩码通过」那一列按哪个地区序号算。
* `gs_ctl.py equipped [座位 物品id ...]`；`sync-account` 连带重发 `0x030b`。

## 遗留

1. QuestId 6「太阳齿轮」只验到「下拉框里能选」，没实机进过关卡
   （5 和 7 都进了，同一条代码路径，地图文件也齐）。
2. QuestId 8「푸른 하늘」**打不开也不该打开**：`OpenLocale=0`（全区关闭）、
   `0x6dc52c` 的关卡 id 表里没有它、`Maps/` 里也没有 `Quest08.map`。
3. `leave_game_result` 里那发 `0x030b` 是**防御性**的：`0x406e4e`（把座位清单
   重建成空的）有三个调用点在切 stage 的路上，没有逐条读到底；
   实测走「关卡 → 结算 → 回房间」清单**没被清**。重发是幂等的整份替换，留着。
4. 角色 3 아이린 / 98 쉐도우 타이 / 99 랜덤 放不出来 ——
   被客户端的按钮循环显式跳过或需要另一个开关，不是我们挡的。
5. 「真通关一次做终验」仍然欠着（从会话 17 到现在）。现在多了 3 个关卡可选，
   建议就拿新解锁的关卡跑这条终验。
