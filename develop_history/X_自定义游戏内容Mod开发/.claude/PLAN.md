## X8 · 自定义武器开放「追踪」参数（用户 2026-09-20）

**需求**：原版只有个别武器带追踪（卡希尔 3 号 / 爱琳的蝴蝶 / 瓦尔基里），
用户要**任意一把自定义武器都能自己设追踪**。

**查明**（§50）：这是「12 格变 14 格」，不是新机制 —— 开关就是 `HomingAngle != 0`
（记录 `+0x78` i32 / `+0x7c` f32），而且 `Projectile::Homing` 挂在所有弹体类共用的
`BulletObj::Tick` 上 ⇒ 18 把（含 2 把手雷、2 把火瓶）全都能追。
`weapon.ini` 一个字节不用改、资源卷不用重打。

**做法**（D42）：`weaponcfg.FIELDS` 末尾加两格 + `bshook.c` 的 `WTAB_FIELD[]` 加两行，
`WIRE_FORMAT` 2→3（**必须重编 dll 并连客户端包一起发**）。范围 0~1300 / 0~1000（用户定）。
另加两样：每格「0 代表…」的灰字（只写核实过的五格）、和跨格判据「填了转向就要填距离」。

**明确不做**：子弹药（碎片 / 火墙）不单独开放；不加「开启追踪」勾选（填 0 就是关）；不抬版本号。

## X7 · 管理页「来源」筛选 + 批量多选添加（用户 2026-09-20）

**起因**：18 把自定义武器加完之后两个操作痛点 —— ① 800 多件能进背包的物品里找不到自己加的那批；
② 三页顶部的「添加」一次只能选一件，要批量上架就得重复 18 遍。

**做法**（D39 / D40 / D41）：**只动前端**（`server/web/admin.js` + `admin.html`），服务端一行不改
—— `custom` 标记早就随 catalog 下发了（§48），批量添加也只是往内存数组里多 push 几条。
① 判据 `sourceMatches()` 折进七处共用的 `dropdownsMatch()`，四页 + 三个弹窗 / 页面各挂一个下拉；
② `openPicker` 加 `max` / `chosen` / `ownedLabel` 三个选项，「添加」和配方材料格改多选，
单值字段那三处（换商品 / 换产物 / 换掉落材料）仍是单选；
③ 配方材料做成**整组编辑器**：4 格点哪个都开，当前几种自动勾上，取消勾选 = 移除。

**明确不做**：不给「0 元 + 已上架」和「空材料配方」加保存前护栏（用户拍板「什么都不加」）；
不为 X5 那 18 把补回的 3 级武器单开一档（它们就是原版）；不动 `tools/shopdata.py` 打标的位置
（等真有自定义防具 / 材料再提，§48 记着）。

## X5 · 开放中文版漏掉的 18 把 3 级武器（用户 2026-09-19）

**起因**：用户报「重机枪 爆裂3 游戏里没有、管理页物品库也看不见，可 agent 做自定义武器时
找得到它的完整模型」。查明（§45）：中文版客户端读的 `ShopItem-Chn.ini` 比韩版少 622 条，
其中武器差 **18 件** —— 1 号槽和 3 号槽的 `D3/R3/F3` × 3 角色（2 号槽的 3 级中文版有，
日版三档全没有）⇒ 各区上线时的取舍。**数据（`weapon.ini` 不重定向）和全部美术都在客户端里**，
缺的只是那 18 组目录条目。

**做法**（D35）：`tools/openweapons.py` 把韩版 `[Item-]` / `[Stock-]` **原样抄回**中文版表
（`weapon.ini` 一字不动、不编新 id、不造资源），插在自定义武器块之前；
名字 / 售价 18000 / 等级 18 全由既有设计表算出来，和 2 号槽那 9 把待遇一致。
顺带修掉 `tools/shopdata.py` 一个静默 bug：同一 id 的字段只认先遇到的那一节，
`[Stock-]` 在前就会丢掉 `Tag` / `PartFlag`（§45）。

**明确不做**：54 条期限售卖形态（只有 `[Stock-]`，物品库和商店都收不了）；
爱琳那 27 件和布洛克那 3 件「只有模型」的武器 —— 那是造新武器，成本同 X3，另立需求。

## X4 · 准星弹格补画 + 武器参数范围限制（用户 2026-09-19）

**起因**：用户报「弹匣 ≤14 正常一格一发，≥15 变成一个连起来的圆，可瓦尔基里弹匣很多也有格子」。
查明（§43）不是 14/15 的分界 —— 客户端 `0x48ca0d` **精确匹配**只认 2/3/6/10/14/18 六个容量，
其余一律退到帧 4（一张没刻度的光滑圆环）；瓦尔基里 `ch102-01` 正好是 18，所以它有格子。
原版玩家武器只用过那 6 个值，美术就只画了 6 张盘 —— **数据驱动的美术缺口，不是 bug**。

**用户拍板**：补画（不是限制容量）；**`> 20` 用光滑圆环**，格子太密反而影响观感；
管理页弹匣范围 **1~100**；其余武器参数也加合理范围，「不能过于大的离谱」。

**做法**（D33 / D34）：`tools/aimring.py` 拿原版帧 4 当底切等分黑缝，补 `2..20` 缺的 13 个容量
（图集 19 → 32 帧，原版区域逐字节未动）；`hook/aimring.h` 是生成物，`bshook.c` 把 `0x48ca0d`
整个改写成跳我们的表；`weaponcfg` 的范围拆成「管理页紧 / 读盘宽」两套，存量值不丢。
**管理页**：每格旁边写「限 a ~ b」，超范围当场标红 + 整行提示 + 锁保存键（纯函数判据，
`test_weaponrange.py` 在 node 里跑真的 `admin.js` 守着）。

**明确不做**：不动原版那 6 张盘（`cap=2` 用 6 格盘是原版就这样）；不放开 `cooling_ms` 的下限。
