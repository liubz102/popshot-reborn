### 会话 11 修的：模式跟不上 + 生效时机（§42 / D32）

`WeaponTable::Load` 的调用时机**不等于开局**（闯关第一局打完才跑、从闯关回对战一次都不跑），
所以 D27 那套「按 Load 返回地址推模式」永远慢一拍。改成**服务端在开局握手 `0x0400` 之前**
按 `room.session_type` 把模式连同整张表推下去（`0x0F01` 格式 1 → 2，多一个模式字节）；
登录后 / 管理页保存后那两发是 `0xFF` = **只换表不写内存** ⇒ 属性改动**下一局生效**（用户拍板）。
管理页弹窗常驻「⏱ 属性改动下一局生效」+ 说明文那行「要重新登录客户端」。
细节见 `sessions/2026-09-19-03.md`。

### 会话 13 修的：闯关里数值被冲回 ini 原值（§44）

改写武器记录有**两条**路，我们只钩了 `WeaponTable::Load` 那条。另一条是 `0x48ADB0`
（闯关进图时加载一份额外 ini、逐条解析进同一张表），**不经过 Load** ⇒ 闯关里我们写的值被它冲掉。
已补钩子 `WTAB_MERGE_VA`。`test_patchsites_wtab` 现在**穷举全镜像**核「逐节解析函数只有两个调用者」。
细节见 `sessions/2026-09-19-05.md`。

## 给接手会话的十句话

1. ★★★ **武器 Id 不能随便编**（§41 / D31）：客户端拆数位当弹药数组下标，必须满足
   「系列 ∈ [3,5] 且 档*10+槽 < 50」。现行 `1 0 0C 3 S 5`。`test_weaponini` 守着，别绕过去。
2. **原版武器一个字节不许改**（用户 2026-09-19）：`test_weaponini` 钉着 `weapon.ini` 前 221519 字节的 sha256。
   想调数值去管理页物品库的「自定义属性」弹窗，只有 9 把自定义武器能调。
3. ★★ **自定义武器的数值链**：`server/data/weapons.json` → `weaponcfg.effective()` → `0x0F01` → bshook 写内存。
   `weapon.ini` **每次进图重读**（`Load` 会把我们写的值冲掉），所以 hook 在 `Load` 返回点上还要再写一遍（§36 / D26）。
4. ★★★ **PVE / PVP 由服务端在开局握手里说，不是 hook 猜的**（§42 / D32，推翻了 D27）：
   `0x0F01` 头上那个模式字节，`0xFF` = 只换表不写内存 ⇒ **属性改动一律下一局生效**（用户拍板）。
   开局那一发必须排在 `0x0400` **之前**（弹匣容量进图时就快照走了）。`test_room` 守着这两条。
5. 自定义资源全部由 `tools/goldwp/build.py` 从爆裂 3 母本生成，**幂等**；改色规则在 `palette.py`，清单在 `spec.py`。
   手改生成物会在下次重跑时被盖掉。
6. `default.amf` 只许经 `tools/amftool.py` 改（定长记录，写错一格整张表读歪，§37）。
7. `shop_items.json` **FORMAT 2**、`bot_weapons.json` 13：改字段必须和重生成的产物同一次落地。
8. 部位码 `92` = 自定义武器（`tools/shopdata.PART_KIND`）；**物品 id `X92000S` 没变过**，改的只是武器 Id。
9. **版本号只由用户定**：`build-ver.config` 里是尚未发布的开发版本（现在 0.4.1，线上 V0.4.0）。别自己抬号。
