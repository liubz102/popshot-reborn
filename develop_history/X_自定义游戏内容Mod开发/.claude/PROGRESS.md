### 会话 10（2026-09-19）修的那个 bug —— 两个症状一个根因

用户实机报了两条：① 自定义武器弹匣不生效、按住鼠标无限连发；② 打完一局在结算界面客户端卡死。
查下来是**同一件事**：武器 Id 会被客户端 `0x40a138` **拆数位当弹药数组下标**，
初版编号 `1 0 0C 9 S 0` 解出索引 91/92/93，而那个数组只有 4 格、三个调用点都不查上界 ⇒
换弹把越界读到的堆指针当弹药数（永远减不到 0 ⇒ 无限开火、准星外圈弹格也不画），
开火时又把一个 dword 写进越界处 —— 实测正好砸中 Surface 哈希表某节点的 `next`/`hash`，
退图销毁 Surface 时主线程死循环。**全部证据和地址见 §41，选型见 D31。**

修法：编号改成 `1 0 0C 3 S 5`（D 系第 4 档），碎片 `1 0 0C 5 3 5`，索引归一化回槽位 1/2/3。
**只动数据不动代码，hook 一行没改**；物品 id 没变 ⇒ 玩家仓库和 `weapons.json` 不用迁移。

## 给接手会话的十句话

1. ★★★ **武器 Id 不能随便编**（§41 / D31）：客户端拆数位当弹药数组下标，必须满足
   「系列 ∈ [3,5] 且 档*10+槽 < 50」。现行 `1 0 0C 3 S 5`。`test_weaponini` 守着，别绕过去。
2. **原版武器一个字节不许改**（用户 2026-09-19）：`test_weaponini` 钉着 `weapon.ini` 前 221519 字节的 sha256。
   想调数值去管理页物品库的「自定义属性」弹窗，只有 9 把自定义武器能调。
3. ★★ **自定义武器的数值链**：`server/data/weapons.json` → `weaponcfg.effective()` → `0x0F01`（登录后 + 保存后广播）→
   bshook `wtab_*` 写内存；`weapon.ini` **每次进图重读**，所以 hook 挂在 `WeaponTable::Load` 返回点上再写一遍（§36 / D26）。
4. PVE / PVP 由 hook 按 Load 的返回地址挑（D27），别改成服务端按房间推。
5. 自定义资源全部由 `tools/goldwp/build.py` 从爆裂 3 母本生成，**幂等**；改色规则在 `palette.py`，清单在 `spec.py`。
   手改生成物会在下次重跑时被盖掉。
6. `default.amf` 只许经 `tools/amftool.py` 改（定长记录，写错一格整张表读歪，§37）。
7. `shop_items.json` **FORMAT 2**、`bot_weapons.json` 13：改字段必须和重生成的产物同一次落地。
8. 部位码 `92` = 自定义武器（`tools/shopdata.PART_KIND`）；**物品 id `X92000S` 没变过**，改的只是武器 Id。
9. **版本号只由用户定**：`build-ver.config` 里是尚未发布的开发版本（现在 0.4.1，线上 V0.4.0）。别自己抬号。
10. ★ 跑测试：`runtime\python\python.exe test\run_tests.py`（3.14）和 `runtime-win7\python\python.exe test\run_tests.py`（3.8），
    全量名单现扫 `test/test_*.py`。**别加 `-j1`、别 `| tail`**。
