## 给接手会话的十句话

1. ★★★ **武器 Id 不能随便编**（§41 / §47 / D31）：客户端拆数位当弹药数组下标，必须满足
   「系列 ∈ [3,5] 且 档*10+槽 < 50」。C 批 `1 0 0C 3 S 5`、P 批 `1 0 0C 4 S 5`，**只剩 4 个合法组合**，
   第三批必须改系列位。`test_weaponini` 守着，别绕过去。
2. **原版武器一个字节不许改**（用户 2026-09-19）：`test_weaponini` 钉着 `weapon.ini` 前 221519 字节的 sha256。
   想调数值去管理页物品库的「自定义属性」弹窗，只有那 18 把自定义武器能调。
3. ★★ **自定义武器的数值链**：`server/data/weapons.json` → `weaponcfg.effective()` → `0x0F01` → bshook 写内存。
   `weapon.ini` **每次进图重读**（`Load` 会把我们写的值冲掉），所以 hook 在 `Load` 返回点上还要再写一遍（§36 / D26）。
4. ★★★ **PVE / PVP 由服务端在开局握手里说，不是 hook 猜的**（§42 / D32，推翻了 D27）：
   `0x0F01` 头上那个模式字节，`0xFF` = 只换表不写内存 ⇒ **属性改动一律下一局生效**（用户拍板）。
   开局那一发必须排在 `0x0400` **之前**（弹匣容量进图时就快照走了）。`test_room` 守着这两条。
5. 自定义资源全部由 `tools/goldwp/build.py` 生成，**幂等**、**一次跑全部批次**（两个 ini 都是
   「砍掉标记再整块重写」，只跑一批会把另一批带走）。批次表 / 编号 / 选定的配色变体都在 `spec.BATCHES`，
   改色规则在 `palette.SCHEMES`。**不带参数跑就是重现盘上那一套**；手改生成物会被下次重跑盖掉。
6. `default.amf` 只许经 `tools/amftool.py` 改（定长记录，写错一格整张表读歪，§37）。
7. `shop_items.json` **FORMAT 2**、`bot_weapons.json` 13：改字段必须和重生成的产物同一次落地。
8. 部位码**一批一个**：`92` 第一批 / `93` 第二批（`tools/shopdata.CUSTOM_WEAPON_PART`），
   物品 id `X<部位码>000S`。⚠ 别为了省一个部位码去共用 92 换尾号 —— `weapon_variant()` 会误判（§47）。
   两批的默认中文名靠**韩文名后缀字母**分（`shopcfg.CUSTOM_WEAPON_ZH_BY_SUFFIX`：`C`→自定义1 / `P`→自定义2）。
9. **版本号只由用户定**：`build-ver.config` 里是尚未发布的开发版本（现在 0.4.1，线上 V0.4.0）。别自己抬号。

    全量名单现扫 `test/test_*.py`。**别加 `-j1`、别 `| tail`**。
