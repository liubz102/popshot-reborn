# 会话 10 · 2026-09-19 · 修「自定义武器无限开火 + 结算界面卡死」

## 用户报的两条

1. 自定义武器的弹匣设定没生效，按住鼠标一直连发、不用换弹（**用的是默认数值，没改过**）。
2. 打完一局，在结算界面客户端卡死无响应（用户保着现场没关）。

补充线索（第二轮给的，关键）：正常武器的准星是个圆，外圈按弹匣容量排一圈弹格、打一发少一格；
自定义武器**外圈整圈都不画**。道具赛掉落的水枪 / 冰枪也是这样，也能一直连发。

## 怎么查的

- **卡死现场**（pid 24692，`Responding=False` 但 CPU 还在涨 ⇒ 死循环不是死锁）：
  没有调试器，自己写了 ctypes 采样器（`Wow64SuspendThread` + `Wow64GetThreadContext` + EBP 链回溯）。
  主线程停在 `0x5c552c` = 退图时的 `Surface::DestroyAll`，由 `0x477dac` 的析构调用。
- 把那张 Surface 哈希表（1543 桶 / 974 元素）**整个扫了一遍**，找出唯一一个
  `hash % 桶数 != 所在桶` 的节点；再读它的 `key*` 发现是 `Maps/!Basic//101-BlueStartingPoint.png`、
  `value` 是个完好的 Surface ⇒ **不是坏数据，是前 8 字节（`next`/`hash`）被野写覆盖**。
- **症状 1 的客观判据**：拿服务端日志的 `rpFire` 时间戳算「最长连打段」。原版那批日志是
  `[6,6,6,…]` / `[14,14,…]` / `[10,10,…]`（== 弹匣容量），出事那局是 `[100,42,31,…]`。
  这条 A/B 完全用现成数据做出来的，没让用户再跑一局。
- 数值链**逐段验清白**：服务端算出 6/2/14/3/1 → hook 偏移 `+0x60` 对（解析器 `0x489379`）→
  活内存里 `MagazineCount` 就是 14 → 把自定义记录和母本 `1002215` 的 **0x254 字节整条逐字节比对**，
  只差 `Id`、`WMeshIdx` 和资源路径指针。⇒ 问题不在数值，在**客户端怎么用这个 Id**。
- 顺着准星那条线索找到 `0x48fed6`（画准星）→ `0x48ba3a`（取弹药）→ `0x48bac2`（开火扣弹）→
  **`0x40a138`（拆 Id 出索引）**。真相见 §41。

## 结论（§41 / D31）

武器 Id 被拆数位当弹药数组下标；初版编号 `1 0 0C 9 S 0` 解出 91/92/93，数组只有 4 格、
三个调用点都不查上界 ⇒ ① 换弹把越界读到的堆指针当弹药数（永远减不到 0）② 每开一枪越界写一个 dword。
实测 `[管理器+0x54] + 92*4 / + 93*4` **正好等于**那个坏节点的 `next` / `hash` 地址 —— 两个 bug 一个根因。

道具赛的水枪不是 bug：`ch-water ForceTime=10000`，限时强制武器，原版就不画弹格、也不扣弹药。
