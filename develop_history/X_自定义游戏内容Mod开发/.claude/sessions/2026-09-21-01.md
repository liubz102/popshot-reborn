## 一、时区：三侧一律改成「启动时算一次」（D52 改写）

会话 25 **刻意没照用户说的做**，理由是「客户端一开十几个小时，跨夏令时切换会
重现那个 1 小时错位」。用户第二天直接否了这个前提 —— **这个场景在本项目里不存在**。

- `server/tzstamp.py`：`_zone_key` / `_zone_texts` / `_zone_for(is_dst)` 整套删掉，
  换成 import 时算一次的 `ZONE_TEXT`。**不加公开的 `refresh_zone()`** ——
  那会变成「生产路径永不调用、只有测试在用」的 API，反而引诱后人在运行时重算；
  测试直接 `tzstamp.ZONE_TEXT = tzstamp._zone_text()`。
- `hook/bshook.c`：`g_zone_key`（第几分钟）→ `g_zone_ready`（一次性）。
  `bslog_emit()` 一个字没改，第二版砍掉多余 `_snprintf` 的优化原样留着。
- `updater/src/util.c`：它本来是**每次现算**（没缓存），一并改成一次性，三侧同形状。
- `test_tzstamp.py`：夹具 `_FakeZone` 换完三个全局后**自己补一下重算** ——
  不补的话所有假时区用例（半小时时区 / 负偏移，开发机一辈子跑不到）全部失效。

★ 教训记进 D52：「为一个用不上的场景做正确性设计」不是稳妥，是成本。

## 二、挂机判定接上（D53b）

`conn_is_afk()` 里加一条前置短路，排在 `dead_since` / `afk_carried` **之后**：

```python
if conn_presence_afk(conn, now) is True:
    return True
```

四条口径全是用户拍的：**三档全判**（含「只有鼠标」，他知道并接受误判风险）、
**后果只有管理页显示**、**管理页不显示证据明细**、时区那边三处都改。

自己定的实现取舍（都有用例钉着）：

- **只补不削**：presence 说「在玩」不能把服务端两条钟判出的挂机洗白 —— 那两条问的是
  「他在玩**这一局**吗」，presence 只能证明「他人在机器前按过键」。
- **20 秒沿用 `AFK_AFTER_S`**，不另立一个数（D53「判据同源」）。真正靠这条线的是
  `后台` —— 它是布尔、翻转是瞬时的；另外两档自带 60 秒回溯量，**别接力着算**。
- **起点是「档位翻转」这个事件**（`presence_since`），同档重复报不动它
  ⇒ 丢包既不重置也不加速；撤销也是事件（翻回「在玩」当场生效）。
- **断流退回「没有证据」**（6 个上报周期），不冻在最后那一档。
- **开局 / 换图 / 复活都不清** presence 的计时：那两条钟要清是因为证据只在一张图内
  有意义；「人在不在机器前」跟换不换图无关，清了就是把「管理页一局一局地闪」造回来。

★ 白拿到的：`conn_is_afk()` 只有三个调用点，另外两个是 `note_seat_died()`（定格）
和 `note_seat_settled()`（跨局继承）⇒ presence 判出的挂机自动跨局、自动在躺着时定格。
`web/` 一行代码没改，只把 `_afk_places()` 的 docstring 补成三条判据。
