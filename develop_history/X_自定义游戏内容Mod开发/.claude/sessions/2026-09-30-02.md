# 会话 59 · 2026-09-30 傍晚 · X17 追加：7z 压缩等级「低 / 高」

## 用户说的

1. 「现在压完 7z 是比 zip 小，但还是没有我自己压缩的那么小……能不能帮我调整成『标准压缩』」
   + 问：云服务器上标准压缩要多少内存、CPU 高多少。
2. 第一版计划（统一改成标准）被否，改要：弹窗选 7z 时加「压缩等级」高 / 低开关 + 小字内存估算；
   默认按服务器内存（低于 800 MB 选低），只是进系统时的默认，关弹窗保持、重新登录才回默认。
3. 问答里定：崩溃包固定「高」；刷新页面也算重新进系统（回默认）。
4. 追问：内存不够会不会失败、失败了怎样（→ 加了开压前那一关）。
5. 看过实验室后：「格式」「压缩等级」放同一个背景块、两组开关上下对齐。
6. 再看：切 zip / 7z 时「格式」和开关的距离会变 → 标签列固定成「压缩等级」四个字宽（`min-width: 4em`），
   实验室 1280 / 375 宽量过：7z → zip → 7z 三次间距都是 36 px、开关不挪位。

## 查明（§143）

- 差距主要在字典不在档：-1·1 MiB ≈ 7-Zip 快速；7-Zip 标准 -mx5 = liblzma preset 5 + 16 MiB 逐项同参数。
- 用户那份 12h 日志：现在 4.63 / 标准 3.46 / 7-Zip 自己 3.34 MB；云服 12h 1.53 → 1.06；两份玩家崩溃包 11.8 → 6.6、7.7 → 6.7 MB。
- 编码器 9 → 186 MB（tracemalloc / 工作集 / 提交一致）；单线程慢 2~7 倍；Py3.8 32 位同字节、慢 25%。
- 7-Zip 对话框 2624 MB 是 16 线程 8 路编码器；-mmt1 / -mmt16 输出只差几字节。

- 两套全量 5086 绿（3.14 跳过 12、3.8 跳过 4，同上一轮）；改坏 17/17 全抓到（scratchpad `mutate59.py`，还原后哈希核对一致）。
