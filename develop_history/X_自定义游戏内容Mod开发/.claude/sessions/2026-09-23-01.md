# 2026-09-23 会话 33 —— X13 第二轮：鲤鱼上弹起的雷「模型消失、鱼背炸开」+ 本机模式开 UDP 旁路

## 用户报的

站在「云桥」中间的鲤鱼上，bot 扔苹果雷：雷在鱼上弹起，模型突然消失，鱼背上出现炸裂动画。
（上一轮 §74 修完之后「能撞到鱼」已经好了。）

## 查的过程

1. 日志：`logs/bshook_20260923_131227_pid17068.log`（debug 模式，有 `PROJ.` 逐帧轨迹）+ `logs/server.out`
   （13:12:24 那次启动，逐包 dump）。bot 这局 13 发主雷，`rpFire` / `rpExplode` 全在 dump 里（inner 0x0002 / 0x0003，
   发送方座位 1）。**「爆炸:」那行日志按距离档去重，别拿它数发数，要解包。**
2. 逐颗对：客户端在鱼上弹起的 7 颗，服务端炸点都在弹起点 0~7 px 内，炸的时刻都是出膛后 45 tick（引信）。
3. 代码：`_bounce_shell` → `_block_facing` / `_terrain_facing` / `_nearest_solid` 查格子不带 `t_ms` ⇒ 鱼背上量不出朝向
   ⇒ 只减半不转向 ⇒ 贴住。客户端 `0x473b36` → `0x473969` = max(静态格, 框内各对象 vft+0x11c) —— 连鱼一起算（§77）。
4. 顺带发现：本机模式下 hook 的 UDP 旁路整个不开（`sync_on_plain_frame` 开头 `if (!popshot_online_mode()) return;`），
   所以这局**相位一次都没报**（`MOVER LinkPath` 记了，`MOVER 报 …` 那行没有），服务端用的是开局估计。
   另：LinkPath 那一刻 `gc=00000000`（GameContext 还没建，t0 取自另一个计时器）—— §74 已预料，记一笔。

## 离线重放（方法留给下一轮）

scratchpad 里写的 `replay.py`：从 `server.out` 解 `rpFire` 原字节（角度 / 力度是 f32，日志里那行 `<Shot …>` 只有 3 位小数，
不够）→ `ballistics.Shot` + `bot.Shell` → 逐格调 `bot._shell_step(None, shell, terrain, [])`，猴补 `bot._mover_clock`
返回「开局后 ms」→ 和客户端 `PROJ.` 第 k+1 帧逐格比。开局时刻 = `0x0402` 放行那一刻（`RoomQuest.started_at`）。
- 校准：**修前**代码在「开火那一格的日志时刻 − 开局 + 32 ms 起算、每格 +32」下 13 颗炸点 0 px 复现 ⇒ 服务端那局的时钟。
- 修后同一时钟：撞鱼 7 颗里 5 颗跟上（200074 全程 1.6 px），200062 / 200094 仍贴住。扫偏移：客户端那条鱼大约比服务端
  早 50~60 ms（偏移 −20 附近全体最好，最大差 18 px）。
- ⚠ 1 ms 就能差一格：鱼位置按像素取整。回归用例里的时钟必须抄，不能凑（200084 用 41728 + 32×格）。
