# 2026-10-23 会话 67 —— 云服玩家「闯关里闪退、提示服务器故障」（`bug调查/29`，§151 / D109）

## 用户说的

「云服的玩家说他今天早上遇到了游戏闪退，然后提示服务器故障的问题。我看了服务器管理页面，显示没有收到任何客户端崩溃包。
服务器 log 和玩家 log 我都放到下面的文件夹里了，帮我查一下原因并修复。」—— `bug调查/29`（`client/` = 玩家 try998821 的 `logs/` + `game_patched/Debug`；`logs_server_20261023-100649/` = 云服全量日志）。

## 结论（细节在 §151）

- 今早两次：04:53（Quest04）、06:07（Quest06_boss），都是单人闯关打到一半。
- 不是崩溃：bshook 日志里是「★WS2 connect」（客户端自己重连）+「★拆除 …LobbyStage 已经没了」，06:09 正常 `process detach`、退出码 0 ⇒ 管理页没有崩溃包是对的。
  玩家眼里的「闪退」= 原版 `OnDisconnected` 把关卡拆掉；「服务器故障」= 它弹的「发生服务器障碍,自动尝试连接。」。
- 不是服务端：断前服务端一直收得到 `0x0410`，然后 20~25 秒一发都没收到；32 ms 模拟循环一格没落后、钟差断前断后一致；服务端那条连接一直开着直到被重连顶掉。
- 是玩家到云服之间断网十几秒：玩家那台 Windows 重传 5 次放弃（本机实测 21.0 s，10060）→ 中继出站 TCP 断 → `_pump` 关掉面向游戏的那条 → `FD_CLOSE`。
  判据：中继「#2 连接结束」两次都正好比游戏重连的 connect 晚 5.0 s = `_handle` 里 `join(timeout=5)` 到点 ⇒ 先断的是服务器那头。
- 网在重连那一刻已经好了（新连接秒通）—— 符合「重传放弃时网已恢复、旧连接却回不来了」。

## 查的过程（顺序）

1. 客户端 `relay.out`：两次都是「#3 ✓ 游戏服」之后「#2 连接结束」；`bsloader.out` 退出码 0。
2. 服务端 `server.out` / `game_*_286|288_27799.txt`：断前 `0x0410` 很密，之后整台服务端一行日志都没有，接着就是新连接 + 「被顶号」+ 旧连接 `OSError 10038`。
3. 翻 V0.2 §132 / §171：被顶号 / 断线时客户端自动重连重放票据，那句提示是 `OnDisconnected 0x54da2e` 弹的。
4. 量钟差（relay「✓」对服务端「+++」）：00:16 0.445 s，04:44 起 1.80 s，同一轮断前断后不变；数模拟循环格数 vs 墙钟、找「落后」行 —— 排除服务端卡死 / VM 暂停。
5. 本机对不回包的地址 connect：默认 21.0 s、`TCP_MAXRT=3` 3.0 s、`-1` 不放弃；两套运行时 `getsockopt` 读回 -1。
6. 顺带看了 10-20 05:42（旧连接空闲 5 小时没被发现，不是这一类）、00:06 daxin001（没客户端日志，没定性）。

## 做了什么

- `server/relay.py`：`TCP_MAXRT = 5`、`outlast_outages(sock)`（Windows 上设 -1、别的平台不设、失败忽略），`connect_remote` 连上之后调（认证 / 游戏 / 中继三条、直连 / 代理都过它）。
- `test/test_outage.py` 7 条：默认是 0、设上是 -1、直连和 SOCKS5 两条出站路径都是 -1、非 Windows 不调 setsockopt、关掉的 socket / 非 socket 不抛。两套全量 5159 绿。
- 文档：§151、D109、PROGRESS（会话 67 段 + 下一步 + V222 / V223；会话 65 段挪进归档第 1 节）。

## 第二轮：用户追问三件事

1. 「网都断了，强行维持连接有意义吗？直接显示网络断开不是更好懂？」—— 答：有意义。TCP 两头的状态都还在，网一通就接着走；
   10-23 那两次 Windows 宣布断开的那一刻网其实已经好了（新连接 0.08 s 就通）。「显示断开」该做成提示、不该靠拆连接（没做，待定）。
2. 「断网的本质原因能不能查出来？」—— 服务端日志只能到「玩家这一侧整段丢包十几秒」：公网 IP 不变、UDP 的 NAT 源口断前断后不变
   ⇒ 路由器没重启、宽带没重拨（§152）。哪一段丢的要玩家那边的数据 ⇒ 写了 `tools/net_outage_diag/`（见下）。
3. 「逻辑正确的话服务端也一起改，服务器可能是 Windows 也可能是 Linux」—— 服务端不能也「永不」（断电的人不会有 FIN / RST，
   卡在开局加载会把全房间卡死），改成两种系统同一个上限 60 s（D110，数暂定）。查清了服务端还压着应用层 8 s / 2 s 的积压上限（§152）。

## 第二轮做了什么

- `server/netlisten.py`：`limit_silence(sock, seconds)`（Windows `TCP_MAXRT` 秒 / Linux `TCP_USER_TIMEOUT` 毫秒 / 别的系统不设，`None` = 永不）+ `PEER_SILENCE_LIMIT_S = 60`。
  `relay.py` 的 `outlast_outages` 删掉改调它（`None`）；`gameserver` / `relayserver` / `authserver` 的 accept 调它（60）。
- `test/test_outage.py` 重写成 12 条：三种平台各设什么（假 socket 记 setsockopt）、真 socket 读回、中继直连 / SOCKS5 是 -1、服务端三个 accept 都是 60。两套全量 5164 绿。
- `tools/net_outage_diag/net-diag.bat` + `.ps1`：电脑信息（去掉 MAC / SSID）、最近 72 小时断网相关系统事件、每秒 ping 路由器 / 223.5.5.5 / 服务器、
  服务器一断就后台追一次线路、按 Q 收尾出汇总 + zip。本机试跑三遍：第一遍事件 0 条 —— `WriteLine("…" -f a, b)` 的逗号被当成方法的多个参数，套一层括号修好。

## 第三轮（10-25）：玩家发回 `net-diag`（`bug调查/29/网络诊断结果-20261025-000821`）

- 结论（§153）：两次都正好是他电脑 Wi-Fi 掉线 ——「无线安全停止」#11004 → 正好 10 s 后「网络被驱动程序断开」#8003 → 3~4 s 连回；
  Windows TCP 放弃时已经连回 6 s。72 小时 14 次驱动断开，12 次在 2.4G 上，5G 上稳。用 scratchpad 的 `wlan_timeline.py` 把事件压成时间线（去掉 SSID / MAC）对出来的。
- 给玩家的建议交给用户转达：只连 5G（2.4G 那个取消自动连接 / 忘记）、网卡电源管理里关掉「允许关闭此设备以节约电源」、无线适配器节能改最高性能、更新 Intel 驱动、能插网线就插。
- `net-diag` 两处毛病修了：System 日志 `Get-WinEvent` 整块报「找不到映像文件中指定的资源类型」→ 改 `EventLogReader` 逐条读、描述读不出的单条标出来；
  事件描述里的 Wi-Fi 名称 / MAC 写盘前脱敏（中英文写法都试过）。本机重跑：System 读出 700 多条、脱敏后零残留；拿玩家那份原文套脱敏也零残留。

## 第四轮（10-25）：「是网卡的问题还是路由器的问题」

- 答：分不死，两头都没坏，坏的是 2.4G 那段空口（§153 末条）。scratchpad 的 `wlan_bands.py` 按网络名是否 `_5G` 结尾分频段，
  统计连着的时长、掉线 / 短抖次数、关联耗时；5G 那几次断开是「0.05 s 内直接断 + 之后几小时没动静」= 睡眠样，不算掉链路。
- 给了四个能分开嫌疑的实验（关蓝牙 / 换信道 / 手机对照 / 连 2.4G 重跑 `net-diag`），玩家只用 5G 的话就不必做。
