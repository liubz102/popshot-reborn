# 2026-09-20 会话 02（总第 17 次）· X7 管理页：来源筛选 + 批量多选

## 用户点的题

1. 「物品库 / 商品货架 / 选择物品弹窗」加一个筛选下拉：**全部物品 / 原版物品 / 自定义物品**
   —— 以后还会加自定义防具、材料。
2. 「商店货架 / 合成配方 / 材料掉落」三页顶部的「添加」改成**能一次勾多件**；
   「加一种材料」的加号也要，上限 4 − 已有数。**但点已有条目弹出的换物品 popup 必须单选**，
   并且「请帮我仔细核对逻辑并判断是否能多选后再修改」。

问了两轮才定下来的两件事：
- 范围 → 用户：「**凡事有筛选条的地方都加**」（+ 卖出页也不会空，自定义武器可以卖）。
- 材料格 → 用户第一轮选「取消勾选 = 移除」，**第二轮又追加**：点已有材料也开多选、
  自动勾上已选的、**上限永远是 4，差几个补几个**。⇒ 材料从「补充器」变成**整组编辑器**。

## 几个只有实际跑过才知道的坑

1. ★ **node 那层 Proxy 空壳吞 `onclick`** ⇒ 上限判据写在 onclick 里一条都测不到。
   先定死 6 个纯函数的签名再写功能代码，是这次唯一正确的顺序。
2. ★ **Proxy 里的 `$` 不够用**：换成能读回文本的假节点之后，文件末尾那个 IIFE 会在**微任务**里
   跑 `showLoggedOut → paintTabChrome → $("tabs").children`，抛出来让 node 非零退出。
   ⇒ 把 `showLoggedOut` / `showLoggedIn` 直接换成空操作，别去给页面外壳伪造 DOM。
3. ★ **`pickerState` 探针要先叫一次 `paintPickFoot()`** —— 真页面每翻一格重画一次底栏，
   不照做就永远量到「开窗那一刻」那句话（第一版有两条用例假红在这儿）。
4. ★★ **掉落页真的折行了**（D41）：加第四个下拉后 `.filters` 36 → 69 px，
   `barHeight` 62 → 93。**当场做了对照实验**（把新 select 摘掉再量，回到 36）才敢说是它引起的。
   D68a 早写着「1320 只剩 140 px 余量」，实测缺口 25 px。
5. `tools/launch.ps1` 有个 **`-NoGame`**（`start.bat` 没透出来）—— 只验管理页时省得弹游戏窗口。
6. 登管理页用的是仓库里那个出厂管理员常量（`account_store.DEFAULT_ADMIN_NAME/PASSWORD`），
   不是去翻用户的 `accounts.json`。**卖出页因此是锁的**（`admin` 没有同名游戏账号），
   那一页的三个下拉都填不上 —— 原有行为，不是这次改坏的。

## 实测过的（服务端 + 浏览器，改完都放弃修改复原了）

- 物品库：**844 = 826 原版 + 18 自定义**，分类标签上的件数跟着筛选走。
- 货架「添加」：18 件自定义武器全是灰的「已上架」（用户已经上过架了）；
  换未上架的勾 3 件 → 3 个**互不相同的对象**、`price:0 / listed:true`、toast「已加入 3 条」。
- 配方材料：点**已有材料格**开整组编辑器，3 种预勾选、底栏列名字、第 5 个被红条拒且网格不跳、
  换一种之后另外三种的 `count`（2/3/4）一个没动。
- 单值字段三处（换商品 / 换产物 / 换掉落材料）：`multi=false`、底栏不出现、红框还在。
