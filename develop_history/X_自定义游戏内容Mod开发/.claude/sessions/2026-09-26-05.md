## 改了什么（D75，只动 `server/bot.py` + 新测试）

- `_pushed_by`（从 `_apply_motion_constraint` 抽出来的解除判据，行为不变）+ `_held_by_push`：被推着的那一段 `_tick_bot` 不冲、不开枪，
  按状态翻转打一行「被座位N 的近身招式推着…这一段不出手」。
- `_hit_breaks_melee`（`OnHit` 两步：进门就解 bot 的约束；类型 0 / 没格挡 / 不免伤 / `int(伤害) ≥ 10` 就打断）接在六处挨打点：
  真人直接命中 / 溅射近身、bot 直接命中 / 溅射 / 火墙；`_cancel_melee`：bot 停 `DashSwing`，真人把 `motion_action` / `jab_until` 收到此刻。
- `_advance_dash`：伤害段逐帧先滤掉优先级比冲刺高的人（`_outranks_dash` / `_melee_priority`，出拳伤害段 = 2），打中先 `_cancel_melee` 对方。
- `_note_motion_event`：出拳时记 `jab_strike`（⌊CastEnd×0.625⌋ ~ ⌊DamageEnd×0.625⌋ 帧）。`DashSwing.outranked`、`BotConn.push_hold_logged` 两格新状态。
- `test/test_botmelee.py` 12 条：被推不冲 / 不开枪 / 招收完照常 / 挨打解约束 / 推它的人被打断就放开；≥10 打断、9.9 不打断、护盾里不打断；
  打中收掉真人的招、出拳伤害段不挨、出拳伤害段按原版帧、冲刺中是 1。逐项猴补关掉修改（hold / breaks / outrank / cancel）各有用例变红。
- `re/packet_api.md` §5.4b（打断每台各判）/ §5.4c `+12`（类型 0 ≥10 打断）/ §5.4f（谁发、被推的人怎样、何时解）。

## 第二段：用户追加（边打边报）

用户 21:37:49 重启了服务端在打（跑的已是新代码，日志里「被推着不出手」「这一下被打断了」都出现了），陆续追加：

→「两次近身之间必须隔开 0.3 秒以上」。

1. **击退 ×2 坐实**：写了 `hit_samples.py` / `human_knock.py`（scratchpad）。bot 逐帧里挨打后那一格几乎都夹着一发心跳、速度是整数 ——
   是服务端心跳盖上去的值（服务端没乘：−10 走一格重力截断成 −8，16:43:44 那个「对不上」的样本就是它）；真人被 bot 冲刺打中后
   自己报的心跳 8 例都从 −20 起 ⇒ 客户端 ×2 没错。`OnHit` 类型 0 那一支除 ×2 外没有别的改击退向量的地方。
2. **多一帧**：`Move.frames()` 上界改成不含（`reach()` / 瞄准 / 商店统计的走廊跟着变一点）；`_advance_dash` 同口径。
3. **体力**：`StartDash` 扣 `DashNN-SpCost`；`ProcessMove` 在冲刺 / 出拳时整段跳过 ⇒ 不回。`[+0x5d0]`（第几式）的写入追到
   「돌격기（突击技）」装备（`PartFlag=32`，`ShopItem-Chn.ini` 是 UTF-16）。`AssultSpCost` 没人读。bot 快跑确实扣，但逼近时不快跑。
4. **0.3 秒间隔**（D77）：按「收招 / 被打断 → 下一下开始」算（按开始算恒满足）。常量注释写明这是用户定的玩法限制、不归铁律 10 管。
5. 测试：`test_botmelee.py` 共 20 条（+帧窗口 / 体力三条 / 间隔四条）；`test_chrprops` 帧表、`test_botsync` 两条击退改成 ×2、一条换 440 高的平地
   （180 高那张上 ×2 后会撞图顶）。两套全量 4634 绿。
