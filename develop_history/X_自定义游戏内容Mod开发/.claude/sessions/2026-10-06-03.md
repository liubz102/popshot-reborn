# 2026-10-06 会话 65 —— X21 全屏改「无边框全屏」：Alt+Tab / Win 键瞬间切换（§147~§149 / D107）

## 用户说的

1. 「全屏模式下按 alt+tab 切换到别的窗口会比较卡，再切回来也会卡一两秒……现代游戏都能做到瞬间切换，全屏也可以不关游戏窗口就打开开始菜单……为什么？能改成和现代游戏一样的吗？」
2. 选：画面「保持 4:3，左右黑边」；大厅 / 房间 / 商店里游戏在前台时鼠标「锁在画面里」。
3. 看计划时追问：「很多现代游戏即便选全屏（非无边框）也能瞬间切换，为什么？能改成类似的吗？」——
   答：现代游戏全屏 = 原生分辨率 + Win10/11 全屏优化（底下就是无边框 + 独立翻转）+ DXGI 切走不丢资源；BigShot 分辨率≠桌面用不上，
   硬做真独占照样丢设备 / 重读贴图 / 开始菜单把游戏打出去 ⇒ 无边框就是手动做 Windows 替现代游戏做的那件事（写进 D107 ②③）。
4. 计划审批按钮看不到，用户：「方案没问题，实施吧」。

## 查的过程（结论在 §147 / §148）

三个只读探查（bshook 基础设施 / 游戏窗口鼠标设备丢失逆向 / 历史文档）+ 自己逐指令核：显示模式三态、F11 链 `0x40e33c`、Present 包装清矩形、
`0x5bf960` 的 `Sleep(500)` + 10 轮重试、主循环失焦且全屏不画、鼠标两套（战斗拽回 (500,400) 与客户区无关；大厅 `GetCursorPos + ScreenToClient` 直接当界面坐标）、
`Direct3DCreate9` 导入槽直指导出（RVA 0x64B20）。规划代理审查后改了：取整（ceil / 真 floor，中心取整在 1<k<2 往返会漂）、补丁时机、黑边光标、设备丢失暴露面。

## 中途翻的车（都记进了 §149 / D107）

1. 放大：scratch D3D9 夹具实测 `Present(pDestRect)` 是**点采样** ⇒ 加附加交换链 + `StretchRect(LINEAR)`（夹具：1 像素线变两级灰）；附加交换链活着 Reset 回 INVALIDCALL ⇒ 恢复前先放掉。
2. 第一版钩 IDirect3DDevice9 vtable：冒烟时 F11 后第一帧放大、之后整屏横向拉伸，切回窗口的 Reset 也没进 ⇒ 无边框关不掉。夹具二分：`BeginStateBlock / EndStateBlock`
   把槽位抄回原函数；改钩槽位指向的内部函数 —— Present 稳、Reset 槽刚建设备时指向别的函数 ⇒ 整层放弃，改钩游戏的两个函数。
