# X_Mod DECISIONS —— 为什么这么选

**编号从 D1 起**，和 V0.1 / V0.2 / V0.3bot / V0.3商店 相互独立。
引用旧版一律写全前缀：「V0.2 D103」「V0.3商店 D51」。

**只记「为什么」，不记「是什么」**（「是什么」在 FINDINGS 和代码注释里）。
一条选择一节，**≤ 20 行**，写清**被否掉的方案**和**否掉的理由** —— 那才是防止后人白推翻的东西。

---

## D1 · 爱琳的模型 = **整套克隆 ch01 卡希尔 + 改皮**（用户 2026-09-15 拍板）

**选**：把 `Models/Characters/ch01` 的 671 个文件整套复制成 `ch03`，
`.msh` 里的贴图名同步改名（`ch01`→`ch03` 等长，原地替换），再照原画改贴图/网格。

**否掉的方案**：
① **照原画从零建模 + 绑骨** —— 本仓库没有 `.msh` 写出器，也没有任何 3D 建模软件，
工作量以周计，而且绑骨一错就是「骨骼查不到返 NULL 喂进矩阵乘直接崩」（§7）。
② **克隆 ch106 시리아**（白发、只有 175 文件 / 5.7 MB，体积小四倍）——
她是深肤 + 盔甲风，和花精灵的气质差太远，重绘量反而更大。
③ **只克隆最小零件集**（默认套 + 武器 + 动作，约 175 文件）——
省 12 MB，但会放大「身上穿着别人的衣服切过来，去找 ch01 根本没有的设计号」的风险。

**理由**：克隆同一个角色的 `.msh` + `.mtn` 保证**骨架同源**，这是不崩的前提；
ch01 是纤细女性体型，和原画最接近；爱琳 ChrProps 点名的三根骨在 ch01 骨架里全有（§7）。

**代价（要认）**：仓库 **+32 MB**（明文 20 + 卷 12）。爱琳第一版长得像卡希尔。

## D2 · 爱琳走「第 4 个基础角色，白送」，**但保留原版的 4 级门**（用户 2026-09-15 拍板 + 建议）

**选**：patch `0x55853c` 的 `cmp eax,3` → `4`，让持有判定对 id 3 恒真；
服务端 `BASE_CHARACTER_IDS` 加 3。**不发任何物品。**

**否掉的方案**：**商城角色卡**（上架一张 `4400001`，金币买）——
要改 `account_store.character_id_of_item()` 的白名单、改 `shopcfg` / `shopdefaults` 的默认货架，
`test_shopcfg` 那条「货架恰好 11 张角色卡」会红，牵动面比白送大得多。

**理由**：原版中国区的文案写的就是「**您可以从4级开始使用爱琳**」——
她本来就是**免费基础角色**，不是商城角色。照原版做（铁律 12）。

**★★ 4 级门：2026-09-17 改口径 —— 固定去掉，没有开关**（用户原话：
「去掉就是固定去掉，不要搞选项，没让你搞选项」）。
三处判据（`0x44c954` / `0x44cc07` / `0x467eb1`）现在和那六处**一起无条件打**，
爱琳 **1 级起就能选**；环境变量 `BSHOOK_IRENE_LEVEL_FREE` 已**删除**，别再加回来。

- **原先**（2026-09-15）是「白送 ≠ 取消等级解锁，照原版保留 4 级门，要试就设环境变量」。
  否掉它的不是技术理由，是**用户要的产品形态**：这是 Mod 分支，爱琳是送的，
  不该让新号先练到 4 级才能用。
- ⚠ **别把它和 `BSHOOK_KEEP_IRENE_LOCK` 搞混**：后者是「整个角色回到原版」的总开关
  （九处一起不打，爱琳在三个面板里都不出现），不是 4 级门的选项，保留。
- ⚠ 改了 `bshook.c` 就**必须 `hook\build.bat` 重编**，它会顺带刷
  `server/manifest-hook.json` 的哈希 —— 不刷的话服务端会判客户端「被篡改」强制更新。

★ 推论：`character_id_of_item(4400001)` **必须继续返回 `None`** ——
以后谁好心加一张爱琳的角色卡，会把 `0x55853c` 那处补丁架空。

## D3 · 建模改造和贴图改造**外包给 Fable 5.1 子代理**（用户 2026-09-15 拍板）

**选**：M1 克隆 + M3 证伪实验通过之后，起一个 `model: "fable"` 的子代理做外观，
和主会话的 hook / 服务端工作**并行**。给它白名单（只许碰 `ch03/**` 和新建的几个 tools 脚本），
禁止碰 ch01、`server/`、`hook/`，禁止跑 build-pack 和任何 git 命令。

**否掉的方案**：① 主会话自己顺手改 —— 串行，而且美术活和协议活抢同一份上下文；
② 开 `isolation: "worktree"` 隔离 —— `game_patched` 有 540 MB 在 git 里，开 worktree 代价太大。
`ch03/` 整个目录是本次新增的未跟踪文件，靠白名单就足以避免撞车。

**理由**：外观改造是一块**边界清晰、可离线验收**的活（改完渲对照图就能看），
天然适合外包；而它又需要写 `.msh` / `.dds` 的解析器，是硬活。

**准入门槛（硬性）**：改网格之前，`tools/mshtool.py` 的 parse→write 必须在**全部 256 个
`.msh` 上 round-trip 逐字节一致**。做不到就停在「只改贴图」，**不许硬改**。

—— 这是个**数据 bug，不是设计**。补数据才是真修好；借位是把两个角色都顶着别人的脸。
而且前 24 帧逐字节相同，覆盖等于只追加 4 帧，风险极低。

**额外收益**：顺手修掉「角色 110 进关卡必崩」那个老 bug，110 拿回自己的头像。
**这一步可以完全不碰爱琳就独立验收**（让有 110 的号进一次关卡看头像）。

- **打包**：`dist/` 和更新器不动，等实机跑通再说。

## D6 · X_Mod 的进度文件用「**需求池 + 体量红线**」，不沿用线性路线图（用户 2026-09-15 拍板）

**选**：`PLAN.md` 改成需求池（每个 Mod 一条，`X1` 起，四种状态）；
`CLAUDE.md` 里把每个文件的体量预算写成硬规矩；编号全部从 1 重新起。

**否掉的方案**：照抄 V0.3 的 `M0→M9` 线性路线图 + 接着 `D118` 往下编号。

**理由**：V0.1~V0.3 是**有终点的版本**，X_Mod 是**长期会不断加需求的分支**，
线性路线图表达不了「随时插一条新需求」。
编号重起是为了让引用不含糊 —— 本版写 `§1`，旧版一律写全前缀。

**体量红线的由来**：V0.3 那套四个文件加起来 **826 KB**，后期每个会话光读索引就吃掉大量上下文。
判据定成「**下一个会话需不需要它**」：改了哪一行 git 里有，**为什么这么改**才要写下来。

## D7 · 双面薄片的修法：**只改邻接表规则**，顶点照旧复制一份反着放（Fable 子代理，2026-09-15）

**选**：`mshtool.build_adjacency` 改成原版导出工具的「每条边上的面按面号**两两配对**」；`geometry.py` 的 `mirror_faces` 不动
（正面 / 反面各一份顶点、法线相反）。几何一个字节不变，只有邻接表重算（§17）。

**否掉的方案**：
① **把 UV 岛向内缩半个纹素 / 加 padding** —— 贴图和 UV 本来就干净（每片花瓣独占一块连续渐变），
   缝只在花瓣外沿，怎么缩都画不出花瓣**内部**的格子；
② 照 `ch01B0006` **共用顶点、只反绕向**（不复制顶点）—— 反面会拿正面的法线，永远背光；
   而且它不解决问题：只要邻接规则错，共用顶点的 4 面边一样会配错；
③ 干脆做成**单面** —— 裙摆从下往上看、披风从侧面看会消失（引擎开背面剔除）。

**理由**：根因在表不在网格；两两配对在 ch01 256 个文件上的复现从 213 涨到 235、无退步，
说明它才是导出工具真正的规则，不是为这一个 bug 打的补丁。

## D8 · 武器网格**在骨骼局部坐标里从零造**，不在卡希尔的件上改（Fable 子代理，2026-09-15）

**选**：`tools/ch03_skin/weapons.py`：每件在「骨骼局部（场景单位）」的设计坐标里用管子 / 盒子 / 花瓣拼，
再乘母本文件里那根骨的 `inv(offset)` 落进网格空间；骨骼名取母本文件的子集、offset 逐字节抄；贴图 128×128 R5G6B5 按件独立。

**否掉的方案**：
① **给卡希尔的件换贴图** —— 手枪 / 酒瓶 / 宝箱的造型摆在那儿，怎么涂都不是叶子枪 / 种球 / 喇叭花；
② **在网格空间里直接摆坐标** —— W0001 的顶点带 5.849 缩放、枪管还抬 25°，手算必错；
   骨骼局部里「原点 = 手、+x = 枪管」，尺寸直接对着原件的包围盒抄（§18）；
③ 트릭스터只做**一把**（参考图只画了一把）—— 动作是卡希尔的双枪，左手会空着；
④ 弹体换成别的骨名 —— 弹体骨是对象自己的帧，名字一改引擎查不到（§18）。

**理由**：用户要的是造型（「能不能换成她自己的」）；骨骼局部坐标让「在手里的位置 / 朝向」直接继承原件，
风险只剩造型本身。`D0003A` 顺手脱离 `D0003` 的别名关系，变成独立的药水 / 图腾（有自己的 `ch03D0003A.dds`）。

## D9 · 步枪的持枪动作：**从瓦尔基里移植上半身旋转**，不拷文件、不手摆（用户 2026-09-16 要求「类似瓦尔基里」）

**选**：`tools/ch03_skin/anim.py`：Stand01 / Attack01 / Reload01 / Run-F01 / Run-B01 / Idle101 六个动作，
上半身 31 根骨抄 ch102 的旋转键，其余全留爱琳自己的（§20）。母本 ch01 → 爱琳，幂等。

**否掉的方案**：
① **直接拷 ch102 的 `.mtn`** —— 她的树 169 节点，爱琳网格引用的头发 / 裙摆骨不在里面，查不到就崩（§20）；
② **手工摆姿势** —— 没有任何 3D 软件，一帧一帧写四元数不现实，而且做不出换弹 / 跑动那种连贯动作；
③ **保留卡希尔的双枪动作只换模型** —— 图标只有一把枪，双手各举一把手枪的姿势拿着一把步枪必穿模。
④ 全身移植（含腿）—— 腿长不同，脚会浮起或插进地里；下半身留自己的最稳。

**代价（要认）**：Jump / Crouch / Dash01 / Damage 仍是卡希尔的双枪姿势，步枪跟着右手走，那几帧里只是单手拎着。

## D10 · 步枪绑在右手 `Bone_Wp01_R02`，枪口点用**静态骨补丁**挪到枪口，不反过来迁就原 FirePoint

**选**：`rig.py` 在移植后 Stand01 第 0 帧的世界坐标里定枪身轴线和枪口，换算成 R02 局部坐标摆网格；
`Bone_Wp01_R_BarrelPoint / R03 / R_FirePoint` 三根静态骨的局部矩阵改成沿枪身、落在枪口，打进全部 86 个 `.mtn`。手杖同理。

**否掉的方案**：
① **让枪身穿过原来的 FirePoint** —— 那个点是卡希尔手枪的枪口（R02 前方 38、抬 25°），移植后的右手朝向一变，
   它跑到头顶左上方去了（世界 y≈100），枪身要迁就它就得斜指天；
② **新增一个 `Bone_Wp01_FirePoint` 节点**（引擎优先找它）—— 要改树的节点数，86 个文件 + 所有网格的骨骼查找都跟着变，风险高于改三根已有骨的矩阵；
③ **绑左手链 `Bone_Wp01_L02`**（瓦尔基里的枪挂左前臂）—— 引擎只读 `_R_FirePoint`（§19），左链上没有枪口点。

**理由**：改矩阵不改拓扑，`mkchar --audit` 的骨架树一致性照样成立；`rig.py` 一份数字两边共用，网格和枪口点不会各说各话。
## D11 · 卡希尔的锤子走 `mkchar.py` 的 **`SKIP` 名单**，不是手动删文件（用户 2026-09-16 要求删）

**选**：`mkchar.py` 加一份 `SKIP = {("ch01","ch03"): {"ch01J0000.msh", "ch01J0000.dds"}}`，
克隆时就不产出；体检 ① 反过来盯着「SKIP 里的文件又冒出来」当**硬伤**报。

**否掉的方案**：
① **只 `rm` 掉那两个文件** —— 下次谁重跑一遍 `mkchar.py` 就原样长回来，而且长回来是静默的；
② **把网格改成空网格 / 把贴图涂成全透明** —— 文件还在、还会被加载，只是看不见；
   而另外 14 个角色**根本没有 `J` 件**，照它们来才是对的（§21）；
③ **把它改造成爱琳自己的近战武器** —— 她的 `[ch03-dash]` 写的是 `WMeshIdx=-1`（空手），
   `Dash00-DamagingObjBone=Bip01_R_Finger1`（右拳）—— 原版就没打算让她拿东西（§22）。

**理由**：克隆脚本是**唯一的产出口**，白名单 / 黑名单都该长在那里；
「删了又长回来」这种回归只能靠体检卡住。

## D12 · 冲刺攻击移植取「**全部 45 根 Biped 骨的旋转 + 爱琳自己的时长和平移**」

**选**：`anim.CLIPS` 的每条动作自带一个「抄哪些骨」的选择器；`Dash00` 用 `take_biped`
（全部 `Bip01_*`），时长取爱琳自己的 **1.0 s**，平移 / 缩放照旧全留爱琳的。
`ch03@Dash00.evn` 的两条特效改指 `Effects/CH03/` 里原版发好的那两个。

**否掉的方案**：
① **照 D9 只抄上半身** —— 冲刺是整个身体扑出去，只换上半身就成了「瓦尔基里的上身 + 卡希尔的抱熊步」，
   离线对照条上一眼能看出来没像源动作；
② **取 ch102 的 0.833 s 时长** —— 爱琳 `Dash00-TotalFrame=31`（≈1.0 s），动作短 6 帧会在技能末尾定格；
③ **连根骨平移一起抄（按 75/90 缩放）** —— 渲出来和留爱琳自己的看不出区别，
   却要多一套「重锚定 + 缩放」的机制，没有收益就别加（D9 的「平移全留自己的」继续成立）；
④ **留着 CH01 的冲刺特效** —— 它挂在 `Bone_Wp00_11`（熊身上的骨），爱琳没有熊，
   特效就从空气里冒出来；CH03 版挂 `Bip01_R_Hand`，是原版给她画好的花瓣（铁律 12）。

**代价（要认）**：D9 ④「腿长不同、脚会浮起」在这一条上**不成立** —— Dash00 全程腾空，脚不落地。
别把这条当成「以后全身移植都行」的先例。

## D13 · `.evn` 里的特效改指做成**一张全局路径映射表**，放在 `anim.py`，不是逐个动作写

**选**：`anim.EVN_EFX_REMAP` = `{母本 ch01 的特效路径: CH03 版}`，对全部 61 个 `.evn` 生效；
名单由「母本引用的 24 个特效逐个去 `Effects/` 找 CH03 版，**有就换、没有就留**」得出，共 16 条。
main() 开头逐条断言目标文件真实存在，跑完断言每条都在母本里命中过（名单不许留死条目）。

**否掉的方案**：
① **按动作名分组写**（`{"Dash00": {...}, "MutuStand-P00": {...}}`）—— 同一个特效被 7~8 个动作引用
   （`CH01_MutuDust` 7 个、`CH01_DashDust00` 8 个），分组写就是把同一条抄 8 遍，改一次要改 8 处；
② **搬进 `mkchar.py` 当克隆的一部分** —— 概念上更对（这是「克隆得更像」），但 `mkchar` 的
   `.evn` 现在是**一个字节都不改**的纯字节复制，破了这条就得同时改它的幂等 / 下游保护那套判据；
   而 `anim.py` 本来就在写 `.evn`（`EVN_FROM_SRC` 把 Reload01 换成瓦尔基里的），放这儿不新增职责；
③ **机械串替换 `CH01`→`CH03`** —— `CH01_MutuDust.efx` 的 CH03 版叫 `CH03_MutuDust00.efx`（多个 `00`），
   而 `Jab00` / `DashAttack01..05` / `Dash04` / `Dash-B04` **根本没有 CH03 版**，无脑替换会造出死引用。

**理由**：判据是「磁盘上有没有」，不是「名字像不像」；一张显式表 + 两条断言，
比任何猜名字的规则都好查。`mkchar --audit` 第 ⑤ 条（死引用不许变多）再兜一道。

## D14 · 空手跑 `Run-F00` 的源取 **ch00 泰尔**，而且摆臂相位**算出来**，不写死

**选**：`CLIPS["Run-F00"] = dict(src="ch00", ..., sync_legs=True)`；
`leg_sync_phase()` 在动作自己的帧格上把一个周期试一遍，取「同侧手·同侧脚前后位移内积」最负的偏移。

标签也本来就该显示。缺的是中文版翻译时截掉的那两帧（§34）。
补丁会把一个「资源少了」的问题伪装成「代码不该这么写」，而且会**永远看不到这个标签**。
`.smf` 前 22 帧和原版逐字节相同 ⇒ 整份抄回来是零风险的，和 §3 补 `BigChrIcons_CN` 同一招。

**为什么 §27 另外两份不跟着补**：

- `RoomUserSlot.smf`（27 / 28）、`ShopSlotImg.smf`（20 / 22）**没有这种取帧点**。
  全镜像扫过「`mov r,[x+0x24]` 紧跟 `mov r,[x+r*4+K]`」这种绕过边界检查的写法，
  **带高位常量下标的只出现在 `0x48e3xx`~`0x48e7xx`**（全是结算界面这一个函数），
  别处都走 `ImageSet::Draw`（`0x5ccefc`）—— 那条路查 `([this+0x28]-[this+0x24])/4`，
  越界只是不画，不会崩。
- `ShopSlotImg` 中文版还是**另画**的（不是截断，§27 已记）⇒ 照抄原版会错位。

⇒ 这张「帧数下限」表只收**确实会崩**的两份（`test/test_smfframes.py` 的 `GUARDED`）。

## D25 · D3D 索引缓冲那条走**跳板补丁**，而且**离线把站点钉死**，不指望实机复现

**为什么非跳板不可**：站点 `0x5bf6d0` 只有 9 字节，三条指令一条都省不掉
（`[ebp+0x54]` 是函数返回值，`[ebp+0x5c]`/`[ebp+0x60]` 是循环计数），
加 `cmp`+`jcc` 还差 6 字节；而那一带**没有 `int3` 填充洞**（§33 查过，exe 加过壳）。
⇒ `VirtualAlloc` 一块 RWX 当洞。这是本仓库第一个跳板式补丁，`install_inline_hook`
那套用不上（它是给**函数头 + C detour** 用的，这里要的是函数中段、`ebp` 相对的局部变量）。

**判指针不判 `HRESULT`**：要防的就是「往这个指针写」，那就直接判它。
而且 `0x5bf6c7` 先把它清了零，`Lock` 成功必然写非零 ⇒ 判指针严格包含判 `HRESULT`。

**跳到 `0x5bf73f` 而不是 `0x5bf733`**：压根没锁上，就不该 `Unlock`。
代价是这一次索引缓冲没填好（下一次重建成功前画面可能有乱三角）—— 但原版在这条路上是
**直接崩**，没得比。真要「重建失败就整体重试」是另一个量级的改动，不在这一轮。

**被否掉的方案**：① 包 `Lock` 的 vtable，失败时发一块 3 KB 草稿纸给它写 —— vtable 是
全进程共享的，surface 比 9 字节站点大得多；② 干脆改窗口化（`UserConfig.ini FullScreen=0`）
—— 那是**玩家的选择**，不该由我们替他定，留作规避手段写进 §35。

★ **「没法实机复现」不等于没法验**：站点特征串、两个跳转目标落在哪条指令上、
代码洞每一个字节、以及「循环的回跳不会落进被覆盖的 9 字节」，全部拿
`re/BigShot_22524.img` 离线判定，见 `test/test_patchsites.py`（9 种改坏法都试过会红）。
