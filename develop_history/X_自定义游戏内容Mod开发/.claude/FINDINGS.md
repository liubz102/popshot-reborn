## §6 ★★★★ 「一个角色」由什么构成（🔍静态 + ✅离线核对）

- **模型**：`Models/Characters/chNN/chNN<类><4位设计号>.msh` + 同名 `.dds`；
  `chNN@<动作>.mtn` + 可选 `.evn`。
  类字母（`0x505cee` 的跳转表）：`0`=头发/头 `H`=脸 `B`=上衣 `G`=手套 `L`=下装 `S`=鞋
  `^C`=头饰 `^N`=? `^T`=尾巴 `^W`=翅膀 `T`=套装 `W`=手持武器 `D`=弹体 `J`=?
  路径模板 `Models/Characters/Ch%02d/%s` + `ch%02d%s%04d.msh`（`%02d` 是最小宽度，100→`ch100`）。
  **最低必需动作集 = 15 个角色目录的交集 = 73 个**。
- **数据**：`ChrProps.ini`（`ChrIndex=` 才是真 id，节号只是下标；`WeaponIdxBase=1e6+id×1000`）、
  `weapon.ini` 的 `[chNN-dash/-01/-02/-03]`、`NewMutu.ini` 10 节、`Chinese.ini`（**韩文原串当 key**）、
  2D 弹体还要 `default.amf` 里的条目。
- **图集**：小头像 2 帧 + 大头像 2 帧（灰 / 彩），见 §3。
- **音效**：`Sounds/FX/char/KR/char/chNN/`、`…/voice/chNN/`、`FX/wp/chNN/`、
  `Sounds/CharacterChanger/ChNNN.ogg`。
- ★ **战斗内 HUD 立绘不是图集**：`Images/Ui/Portrait.png` 那 35 帧在 exe 里**没有任何引用**，
  HUD 立绘是把模型实时渲染到名为 `Game/Portrait` 的贴图上
  （`ChrProps` 的 `PortraitScale` / `PortraitXOffset` 就是给它用的）。**加角色不用管它。**

## §7 ★★★★ `.msh` / `.mtn` / `.evn` / `.dds` 格式（够用的部分）（🔍静态 + ✅离线核对）

- **`.msh`**：`u32 版本=3` + 4×4 矩阵 + `+0x6c` 顶点数 + `+0x70` 索引数 + 顶点 32 B +
  索引 u16 + 材质块（含 **`u32 码元数 + UTF-16LE 贴图名`**，如 `len=13 + "ch01B0000.dds"`，
  同一文件可能出现 2 次）+ `u32 骨骼数`，每根 `u32 长度 + UTF-16 骨骼名 + u32 n +
  n×索引 + n×权重 + 16 float`。
  ⚠ **偏移 `0x4c` 还有一个长度前缀串是挂接特效路径**（`ArmorSpakle\Efx\CH01_*.efx` 等，
  ch01 有 8 个文件带）—— **含 `/` 或 `\` 的串一律不能当贴图名改**。
- **`.mtn`**：`u32 版本=3 + u32 长度 + UTF-16 "AnimationSet0"` + 骨骼名表。
  ch01 的 86 个 `.mtn` 内部 **0 处** `chNN` 串 ⇒ 克隆时**一个字节都不用改**。
- **`.evn`**：明文 XML，CP949，声明 `encoding="ks_c_5601-1987"`，逐帧事件（`PlaySound` /
  `RenderEffect` + `ResourcePath`）。⚠ ch01 有 **2 个 `.evn` 引用别的角色**
  （`Mutu-DamagedFly`→ch00、`MutuStand-P00`→ch02），**无差别替换会改错**。
- **`.dds`**：128 字节头 + 像素区。ch01 的 268 张里
  **117 张 64×64 R5G6B5（8320 B）、122 张 64×64 A8R8G8B8（16512 B）、
  17 张 128×128 R5G6B5（32896 B）、只有 8 张 DXT1/DXT3** ⇒ **绝大多数是未压缩的**，
  改像素时**把 128 字节头原样保留**即可，别用 `PIL.Image.save(*.dds)`（它不保证吐出同样的头）。
- ★ **骨骼必须同源**：V0.3商店 §50 记过「骨骼按名字在角色骨架里找，找不到返 NULL，
  喂进矩阵乘直接崩」。ch02 有 `Bone_Spine_01`/`Bone_Pelvis_01` 而 ch00/ch01 没有。
  爱琳 ChrProps 点名的 `Bip01_R_Finger1` / `Bone_Wp00_02` / `Bone_Wp00_11` **在 ch01 骨架里全有**。

## §11 ★★★★ `.msh` 的**完整**布局（✅ 257/257 round-trip 逐字节一致）

§7 只写了「够用的部分」。`tools/mshtool.py` 把整个格式吃透了，按顺序：

```
u32 版本=3 | 4x4 矩阵 | 0x44 处 4B 标志 | 0x48 处挂接特效数 + 每条(wstr + 4B)
| 32B 零块 | u32 顶点数 | u32 索引数 | 顶点(32B) | 索引(u16)
| 材质块（★ 45 个头发件有 **2 个**材质，不是一个）
| u32 子集数 + n×4×u32
| 骨骼块（u32 骨骼数，每根 wstr + u32 n + n×索引 + n×权重 + 16 float）
| ★ 末尾还有**模板阴影用的邻接表**：u32 面数 + 每面 40B
  （面号 / 邻居数 / 3×u16 邻居面 / 3×2×u16 共享边 / 14B 零）
```

- `ch0300011.msh` 的邻接表后面还挂着 **676 B 残片**，引擎只读前 n 面 —— 原样保留即可。
- ⇒ 改顶点坐标是安全的（只动 xyz，拓扑/骨骼/权重/邻接表一个字节不碰）；
  **追加三角形要同时改索引、子集面数、邻接表**，是完全不同的风险等级。

## §14 ★★★★ `.mtn` 格式全解 + 绑定姿态的三条坑（✅ 86 个文件复现，工具 `tools/mtntool.py`）

```
u32 3 | wstr "AnimationSet0" | f64 3600(tick/s) | f64 时长 | u32 229 | u32 0
| 骨架树 | u32 轨道数 | 轨道…
```

- **骨架树按 D3DXFRAME 序列化**：每节点 = 名字 + 16 f32；有子节点写 `1` 递归首子、
  有兄弟写 `2` 递归兄弟、收尾写 `3`。ch03 是 **229 个节点**（173 有子、55 有兄弟）。
- 轨道 = 名字 + 旋转 `(t, qx qy qz qw)×n` + 平移 `(t, xyz)×n` + 缩放×n，**帧距 120 tick**。
- **86 个文件的骨架树完全一致**；`Crouch-Start.mtn` 轨道后有 35602 B 垃圾残片（引擎不读）。
- **103 根骨没有轨道**，用树里的静态矩阵。

三条坑：

1. `.msh` 骨骼块尾部那 16 float 是**绑定姿态世界矩阵的逆**（网格单位）。
2. **默认件顶点是「场景单位 ÷ 2.8791」**（`0x04` 的世界矩阵就是这个缩放），
   另有 185 个文件用场景单位或轴置换。
   补缺骨的公式：`bind(子) = 局部(Stand00, t=0, 场景单位) · bind(父)`，
   ★ **平移不要再除 2.8791**。
3. **绑定姿态 ≠ 任何一帧动画**（Stand00 第 0 帧头在 y=69.2，绑定姿态 70.96）；
   而且**不同套装的手臂骨绑定姿态不同**（`B0014` 的 Clavicle 差 13）——
   从别的件借 offset 前必须逐骨核对共同骨。

## §15 ★★★ 邻接表和绕向的规则（✅ 256 个文件复现 213 个）

- 位置**逐位相等**焊接后找共边，每条共边**只记在面号小的那面**；
  条目 = `u32 面号, u32 邻居数, 3×u16 邻居(补 0xFFFF), 3×2×u16 本面该边顶点号, 14 B 零`。
- 面绕向 `cross(b-a, c-a)` = 外法线（98%+），**引擎开背面剔除** ——
  要做双面片（花瓣、蝴蝶结）就得像 `ch01B0006` 那样放 15 组反向重复面。
- **每顶点最多 3 根骨**；双材质只出现在头发类（39 个件）。

## §17 ★★★★★ 「裙子上有网格线」的根因：邻接表把双面薄片的**正面和反面配成了邻居**，不是贴图 / UV（✅离线复现，⏳等实机）

**结论**：`.msh` 末尾的邻接表是给**模板阴影**抽轮廓边用的（一对邻居面一朝光一背光 ⇒ 这条边挤出阴影体）。
`geometry.py` 的花瓣是双面薄片（正面 F/F2 + 反绕向副本 F'/F2'，每条内部边上 4 个面），
`mshtool.build_adjacency` 的旧规则「取第一个面号更大的面当邻居」写出了 `F2→F'`（正面配反面）——
正反面永远一朝光一背光 ⇒ 花瓣的**每条内部边都成了轮廓边**，阴影体沿三角形的边落回裙面，就是那些暗线。

- 贴图 / UV 排除：每片花瓣独占一块连续渐变区，缝只在花瓣外沿，画不出花瓣**内部**的格子（`tools/ch03_skin/compare_D_skirt.png` 左）。
- 原版 `ch01B0006`（蝴蝶结，15 组反绕向重复面）的表：内部边记 `(F,F2)`+`(F',F2')`，**只有边界边**才记 `(F,F')`
  ⇒ 导出工具的规则是「每条边上的面按面号排序后**两两配对**」。换成这条规则后 ch01 256 个文件复现 213 → **235** 个，无退步。
- 用 `mshtool.silhouette_edges` 按同一光向模拟：旧表在 `ch03B0000` 上抽出 508 条轮廓边（花瓣内部全是），新表 220 条（只剩外沿）；
  新表里法线相反的邻居对 128 个，**全部落在只有 2 个面的边界边上**，和 B0006 同构。
- 修法：只改 `build_adjacency` 规则重跑 `geometry.py`，顶点 / 索引 / 骨骼逐字节不动（`ch03B0000` 去掉 309 对、`ch0300000` 去掉 28 对）。
- ⚠ 🤔 exe 里没搜到 `stencil` 字样（只有 `Shadow=` 这个 ini 键和 `NpcBossShadow.png`），「引擎拿这张表做模板阴影」是从

## §30 ★★★ 管理页日志下载：审计行是**发完结束块之后**才写的（✅两套运行时实测）

`web/admin.py::_admin_logs_download` 的顺序是：`body.finish()` 把 chunked 结束块写进
socket → **然后**才写 `eventlog.online(…)` 那一行审计。而 `wfile` 不带缓冲

## §51 ★★★★ 改色要做出「金属」，键必须是**亮度 Y**、归一化区间必须**固定**（✅逐图直方图）

**结论**：纯 HSV 旋钮做不出金属。`GOLD = {hue:44, sat_mul:.95, val_mul:1.08}` 的产物
（`ch00W0141.dds`）色相**全程钉死** 44°、**62% 的像素 S ≥ 0.9**、最亮只到 `#FFD45C`

→ 只在最顶端塌成近白」，那是**非线性**曲线，`hue_by_val` / `sat_by_val` 的两端线性插值做不出来
⇒ 要多档**渐变映射**（`recolor.apply_op` 的 `ramp`）。

- ★★ **键取亮度 `Y = .299R+.587G+.114B`，不能取 HSV 的 `V`。** 特效贴图的 V 是死的：
  `CH00_Wp01D3_BulletTail00` 的 V 动态范围 **literally 0.00**（p5=p50=p95=1.00），它们的形状是
  靠**饱和度**画的（白热核心 S≈0.25 / 边缘 S≈1.0）。Y 才有范围 —— 那张 0.30~0.83、
  `Fire01` 0.45~0.79、`CH02_Wp01D3_Damage00` 0.36~0.84，而模型 `ch00W0131` 是 0.00~0.66。
- ★★ **`ramp_range` 必须钉死，不许像 `val_range` 那样逐图自适应**：逐图拉伸把亮度本来就集中在
  高段的特效贴图整片映射到色标**底端** —— 实测 `Fire01` 一半像素落到 `#251703`/`#452B06`，
  枪口火光变深褐。这是 D37「不用 `sat_by_val`」那条坑换了个马甲。钉成 `[0, 0.62]` 后：
  枪身走完整条色阶、弹道 / 火光落在上半段 = 「金属枪 + 金色光」，一条区间同时成立。
- ★ **色标的 t 要按母本亮度的实际分位排，不能均匀分**：Y 对高饱和暗红压得厉害，爆裂 3 手持贴图

  落在 t≈0.32**，放到 0.5 整把枪偏暗发褐。
- ★ **中段饱和度要撑到 t≈0.7 才塌**：中段压到 S≈0.76 渲出来是米色 / 土黄，在 64×64 上读作
  「脏」不是「金属」。让人读出金属的是**高光那一下的骤降**（S 0.9 → 0.05），不是整条曲线都淡。
- ★ **`ramp_mix` 留 10%~20% 给 HSV 那套结果**：纯映射是「亮度 → 颜色」的多对一，同亮度不同
  色相 / 饱和度的像素会被压成一个色，贴图细节平掉。
- 残留红的最坏值 32%（`CH01_Wp03D1_StaticExplo00.dds`）**各变体一模一样**，是 §46 那批
  三系列共用的爆炸闪光红（原版做 R3/F3 时就没动），不是改色漏掉的。
- ★★ **原版美术自己的金是同一套 profile**（用户 2026-09-20 指的 `3010015`

## §52 ★★★★★ 仓库提示框：**一个类通吃三处**，说明文能在绘制点整段换掉（🔍逐指令，字节钉死）

结论先行：**大厅仓库 / 商店页里的仓库格 / 待机房间的快速换装背包是同一个 `UiCabinetToolTip`**，
所以「按场景换说明文」只需要**一处**补丁 —— `0x4554e7`。

- `UiCabinetToolTip` vft `0x6681ec`，构造 `0x454572`（`0x454588` 写 vft）。
  **全镜像恰好 3 个调用点**：`0x44d2a2`（商店页）/ `0x453be4`（大厅仓库页）/
  **`0x46ee58`（待机房间快速换装面板）**。第三个的身份是硬证据：它所在的函数（起点约
  `0x46eced`、上游 `0x46ea13`）同时在建三个按钮，文案 `0x661ec0`「이전」/ `0x661e88`「다음」/
  **`0x66b1f4`「교체완료」= 换装完成**。
- 刷新文字的是 vft 槽 1 `0x454dd5`：`0x454de3 mov ebx,ecx` 之后 `ebx` 全程不变 = `this`；
  `[this+0xd0]` 是 `ItemInfo*`，由 `0x454b15..0x454b23`「拿 `CabinetItem+4` 当 key、
  `ecx=[0x72e1dc]` 调 **ItemDB 查表 `0x415a94`**、存进 `+0xd0`」填的；入口 `0x454df5` 已判过非空。
- ★ 补丁点 `0x4554e7` 那 9 字节 `8b 83 d0 00 00 00 83 c0 18` = `mov eax,[ebx+0xd0]` + `add eax,0x18`。
  **全镜像没有任何跳转落进这 9 字节内部**（`0x4553f9` 的 `jmp 0x4554df` 汇在补丁**之前**，
  两条入边上 `ebx` 都是 `this`）。
  ⚠⚠ **同样的 9 字节在 `0x45ff1b` 还有一份 —— 那是 `UiCompositionToolTip`（合成，只在大厅），
  不打那处**。所以补丁按「固定 VA + 字节签名」双重校验，**绝不按签名全图搜**。
- ★★ 接手的切分函数 `0x5d5789(dest, &字符串, L"|")` 对第 2 个参数**只做一次**
  `mov eax,[ebp+0xc]; mov eax,[eax]`（`0x5d57c3`）取出 `wchar_t*`，随即 `wcsncpy` 进
  `sub esp,0x7e4` 开的 1000 wchar 栈缓冲（`push 0x3e7`），之后 `0x5d57ff lea ecx,[ebp+0xc]`
  把那个参数槽当局部变量**复用**掉 ⇒ **替身只要是「首 dword 指向我们自己那串 UTF-16」的地址**，
  不用构造字符串类、**不涉及堆所有权**（游戏的 CRT 和注入 DLL 的不是同一个堆，让它 `free`
  我们的缓冲会炸 —— 这正是「不去改写 ItemDB 里那个指针」的理由，见 D45）。
- `eax` 的活期只有一条指令（`0x4554f5 push eax`，下一条 `lea eax,[ebp-0x38]` 就覆盖），
  `0x4554f0` 起没有任何指令读标志位 ⇒ 换成 `call` 出去再回来是逐寄存器等价的。
- 以上每一条都在 `test_patchsites_itemdesc.py` 里按脱壳镜像钉死了（含「构造调用点恰好那三个」
  和「`교체완료` 那个 push 在第三个调用点的函数体里」）—— **前提塌了会先在这儿红。**

## §53 ★★★★★ 从**外部**读客户端：武器表 / 持枪器 / stage / 座位，四条地址链（✅ 实机读通）

## §60 ★★★★ 「拿得到裸内存指针」的 D3D 调用，全镜像清点（🔍 全量扫描 + 逐处手核）

**结论**：用户 2026-09-20 要求「整体查一遍还有没有改漏的」。按**形状**（`Lock` /
`LockRect` 的出参是 `lea` 出来的局部、且必须是真 COM 调用 `mov R,[obj]; call [R+n]`）
扫全镜像，**21 处**，逐处手核：

| 状态 | 处数 | 地址 |
|---|---|---|
| 查了 HRESULT | 13 | `0x47c355` `0x50bc80` `0x57709f` `0x5770b7` `0x577642` `0x57768f` `0x5be860` `0x5d26c4` `0x5d3643` `0x6139e4` `0x6169d7` `0x618cca` `0x618d9f`（另 `0x618eee` `0x618fcb`）|
| **已补** | 4 | `0x5bf6cd`（§35）`0x61186a`（§57）`0x5c5dd8`（§60-D）`0x612707`（§60-E）|
| 找到没补 | 2 | `0x61392c` / `0x613b92`（同一个 D3DX 纹理填充函数 `0x61382a`）|

- **§60-D `0x5c5dd8`** 最险：`LockRect` 之后**一句判据都没有**就 `mov [pBits],ecx`，
  而 `D3DLOCKED_RECT` 是**没初始化的栈变量** ⇒ 失败时往随机地址写 4 字节，
  **静默破坏内存**，比崩还糟。
- **§60-E `0x612707`** 是 `ID3DXSprite::Flush`，**每帧都跑**，`rep movsd` 灌 96 字节。
  它用 `D3DLOCK_DISCARD`（动态缓冲，比 §35 / §57 那两处的 `Flags=0` 静态锁难失败得多）
  —— ⇒ **真正爱出事的是「`Flags=0` 的静态缓冲锁」**，两次线上崩溃都正是这一种。
- 剩下两处在 D3DX 的纹理填充里，`Flags=0` 但**有计数守卫**（结构被清零时循环长度算出来
  是 0，自己就跳过了），且线上一次没崩过 ⇒ 记着，先不动。

★ 扫描器的两个坑（重写了三遍才对）：① 参数要从 `reversed(pushes)` 的**头部**取，
不是尾部，否则拿到的是上一个 call 的参数；② `call [obj+n]` 是**对象里存的函数指针**，
不是接口方法，不判掉会多出 600+ 误报。

## §73 ★★★★★ 移动平台客户端怎么算：`PathFollower` + `Path::Eval` 的三次 Hermite（🔍逐指令，已在服务端复现）

**类关系**：`MapObject` 里嵌了两样东西 —— `+0x88` 一个 `PathFollower`、`+0x9c` 一个 `IPath`
（**每个地图对象自己都是一条“路径”**，`type 111 PathObj` 只是把点读进来的那一种）。

| 环节 | 地址 | 干什么 |
|---|---|---|
| `MapObject::LinkPath` | `0x511d60`（**虚表 +0x1c**，载图收尾那一遍 `0x47492b` 对每个对象调一次） | 拿 `v17[0]` 去 World 里找路径对象，把它的 `IPath`（`+0x9c`）交给自己的 follower，**并记下 `t0 = Timer()`** |
| `PathFollower::SetPath` / `GetPos` | `0x549bd6` / `0x549bec` | `elapsed = now + (offset − t0)`；`+0x10` 非零才是相对模式（**这 5 个平台都是绝对**） |
| `Path::Eval` | `0x548ccd` | 下面五步 |
| `MapObject::GetWorldPos` | `0x47c6bf` | 绝对模式直接用路径算出来的点，自己的 (x,y) **不参与** |

1. 累计时间表 `cum[i] = ms[0..i]` 之和（`0x548deb` 建，点数和表长不符就重建），`总 = cum[-1]`；
2. `loop==0`：`t %= 总`；`loop==1` 乒乓：`t %= 2×总`，过半 `t = 2×总 − t − 1`；
3. `i = upper_bound(cum, t)`，`u = (t − 段起点) / ms[i]`；
4. `w = pow(u, 1/ease)`（`0x5ce3a0` 就是「底、1/指数」那个顺序）；
5. 三次 Hermite（`0x5697a7`，常数 3.0 / 1.0）`h00·P_i + h10·M_i + h01·P_j + h11·M_j`，`j` 越界回 0；再加路径对象的世界坐标。

**文件格式**（`Path::Deserialize` = `0x54971a`、`PathPoint::Deserialize` = `0x548b81`）：
`i32 loop`、`i32 count`，每点 `i32 kind, f32 x, f32 y, i32 ms`，**`kind==1` 才有** `f32 tx, f32 ty`，
**地图版本 ≥ 18 才有** `f32 ease`。⇒ 原版 24 条路径切线全是 0、ease 全是 1 ⇒ 实际就是 **smoothstep**。

★★ ~~**相位原点只能逼近**~~ —— **改了，见 §74 / D55**：`t0` 走的是 `Timer()` 不是墙钟，
服务端猜不出来；现在由 `bshook` 报过来，**开局**（`RoomQuest.started_at`）只剩兜底。

## §75 ★★★★ 内联 hook 的蹦床**必须重定位相对跳转** —— 被第三方抢先挂钩时原样搬 = 启动必崩（✅ 夹具复现 0xC0000005）

> ★ **定性更正（2026-09-22 第二轮，拿到玩家的 rpt + 16 份 minidump 之后）**：
> 下面这个缺陷是**真的**、也该修，**但它不是 `bug调查/27` 那个加载页闪退的原因**。

**结论**：`install_inline_hook()` 偷来的字节里只要有 `E9/E8 rel32` 或 `EB rel8`，

且崩在所有模块之外（原版异常过滤器给不出有用的 rpt）。现已逐条重定位（`reloc_insn()`）。

**什么时候序言里会有相对跳转**：**只有**第三方先内联挂过这个导出函数 ——
输入法 / 安全软件注入的组件都这么干。⇒ 这是**竞态**：对方先挂 ⇒ 必崩；
我们先挂（序言是干净的 `8b ff 55 8b ec`）⇒ 正常。
（★ 推断到此为止：搜狗那几个组件**有没有**挂我们也挂的那几个导出函数，

## §76 ★★★★★ 加载页闪退的真病因：客户端**不看 `GetAdaptersInfo` 的返回值**，网卡 ≥ 11 块就遍历未初始化的栈（✅ 16 份 minidump 逐份实证）

**结论**：`BigShot.exe` 的 `0x0040F7E6`（收集本机网卡 IP，加载页「网络初始化中」那一步）
在**栈上**开 `0x1900` 字节 = 正好 10 个 `IP_ADAPTER_INFO`（10 × 640），
调 `GetAdaptersInfo(buf, &len)` 之后**既没清零缓冲区、也没看返回值**，直接顺 `Next` 遍历：

```asm
0040F80F  mov dword [ebp-0x7c], 0x1900   ; len = 10 个的大小
0040F816  call GetAdaptersInfo           ; ← 返回值没有任何人看
0040F81B  lea esi, [ebp-0x74]            ; esi = buf（栈上，没清零）
L: 0040F823  lea eax,[esi+0x1b0]         ; &Adapter->IpAddressList.IpAddress
   0040F82A  call [inet_addr] / test / je
   0040F85E  inc edi
   0040F85F  mov esi,[esi]               ; esi = Adapter->Next   ★ 崩在这条
   0040F861  test esi,esi / jne L
```

网卡 **≥ 11 块**时 API 返回 `ERROR_BUFFER_OVERFLOW` 且**一个字节都不写**，
栈上留着什么就被当链表遍历什么 ⇒ 野指针 ⇒ `C0000005`。

**三条实锤**（`bug调查/27/Dump/*.mdmp`，16 份）：
① 16/16 崩在 `0040F85F`，指令是 `8b 36` = `mov esi,[esi]`，`ESP`/`EBP` 一字不差；
② 崩溃时 `[ebp-0x7c]`（即 `*pOutBufLen`）= `0x1B80` = **7040 = 11 × 640** > 传进去的 6400；
③ 把 `[ebp-0x74]` 起那 6400 字节 dump 出来，里面是栈垃圾，能直接读出 UTF-16 的
`…\AppData\LocalLow\SogouPY\Users\…`，`buf[0]` 就等于崩溃时的 `ESI`（`0x00100081`，一个 HWND）。

**输入法不是原因，是「往那片栈上留垃圾」的那一方**。必要条件是网卡 ≥ 11 块；
崩不崩取决于那 6400 字节栈里恰好是什么：全 0 ⇒ 第一轮读到 0，循环干净收场
（一个 IP 也没收到，没人发现）；别人留下的指针/句柄 ⇒ 踩空。
⇒ **关掉输入法只是把概率压下去，根因还在**；换个会注入的东西（安全软件 / 录屏 / 加速器）照样触发。

**★★ 本机 100% 复现过（2026-09-23）**：开发机默认 6 块网卡（所需 3840 字节，够用），
装 5 块 Microsoft KM-TEST 环回适配器顶到 **11 块 ⇒ 所需 7040 字节 = 玩家 dump 里那个 `0x1B80`**，
再用 `BSHOOK_NO_ADAPTERS_GUARD=1` 关掉护栏，`stop → start → drive.py login` 跑批：
**护栏关 16 轮崩 6 轮（约 1/3，批次间波动极大 —— 这就是「有概率」），护栏开 8 轮 0 崩**。
每次都是 `0040F85F` / `EAX=1` / `EDI=2` / `EBP = ESP+0x88`，只有 `ESI` 不同
（实测 `5F657275` = "ure_"、`00390036` = UTF-16 "69" —— **栈上的字符串碎片**，
玩家那边是 HWND）。装/卸网卡的脚本和跑批脚本没留仓，做法记在 `bug调查/27/调查结论.md`。

⚠ **别拿成功路径的 `*size` 当「所需字节数」**：`GetAdaptersInfo` **成功时不改写**
`*pOutBufLen`，读回来的还是你自己传进去的数。要先用 `NULL` 探一次。
（夹具第一版就是这么误读的，还据此得出过「开发机正好 10 块网卡」的错结论。）

**修复**：`hook/adapters_guard.h` 钩住 `IPHLPAPI!GetAdaptersInfo`，见 **D57**。

**指纹**：玩家日志里 `IPADAPT ★本机网卡需要 N 字节、客户端只给了 6400` ⇒ 那台机器命中本条。
