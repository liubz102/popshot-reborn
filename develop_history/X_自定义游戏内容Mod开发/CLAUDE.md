# 炮炮火枪手 · X_Mod —— 自定义游戏内容

`develop/X_Mod` 是给原版游戏**加自定义内容**的分支：加角色、加装备、加玩法。

和 V0.1 ~ V0.3 的关系：**那几版是「把原版复活」（还原），这一版是「往原版里加东西」（扩写）。**
所以本版**没有终点**，需求会不断加 —— `PLAN.md` 是一个**需求池**，不是线性路线图。

**已完工并归档**（只读参考，别重新推导）：

| 版本 | 内容 |
|---|---|
| V0.1 基础单机 | 客户端在 Win10 上跑起来，localhost 假服务端撑起登录→大厅→建房→闯关→结算闭环 |
| V0.2 联机 | 真多人服务端、网页注册、云端对战与合作闯关、TCP 中继、UDP 旁路、版本门禁 + 自动更新器 |
| V0.3 前半 · bot | 房间 bot：占座、换角色、进图、走跳射击、寻路战术；离线地图地形提取 |
| V0.3 后半 · 商店 | 材料掉落、合成、商店购买、仓库装备、装备加成、管理员网页 |

## 🔴 开工前必读（每个会话第一件事）

按顺序读，**不要重新推导已知结论**：

1. `.claude/PROGRESS.md` —— 现在在哪、下一步、当前卡点、**⏳ 待用户验证**
2. `.claude/FINDINGS.md` —— 已查明的硬事实，以及**试过但不行的路子**
3. `.claude/DECISIONS.md` —— 为什么这么选，别无意义地推翻已定方案
4. `.claude/PLAN.md` —— **需求池**：每个 Mod 一条，`X1` 起，带状态

### ★★ 动协议之前的第 5 个文件：`re/packet_api.md`

客户端 ⇄ 服务端通信包的**参数 / 返回值手册**，按 opcode 排，每个字段带
✅实测 / 🔍静态 / 🤔推测 / ❓未知 标记，并写明「这一发**必须回什么**」。

- 要读某个包的字段、要知道某个 opcode 不回会怎样 → **先查它**；
- 逆出新字段、或纠正旧结论 → ★ **写 FINDINGS 的同时把它一起改掉**。

### ★ 旧版结论在哪

```text
develop_history/V0.1_基础单机功能开发/CLAUDE.md + .claude/{PLAN,PROGRESS,FINDINGS,DECISIONS}.md
develop_history/V0.2_联机功能开发/CLAUDE.md    + .claude/{...}.md
develop_history/V0.3_bot 功能开发/CLAUDE.md    + .claude/{...}.md
develop_history/V0.3_合成与商店/CLAUDE.md      + .claude/{...}.md
```

**引用方式**：写「V0.1 §119」「V0.2 D103」「V0.3bot §174」「V0.3商店 §50」。
旧版 FINDINGS 单份就有 30 ~ 45 万字符，**别整份翻** ——
先在本版 FINDINGS 里找有没有转述，再按 §号 `sed -n` 定位过去。

### ★ 编号规则（★ 本版全部从 1 重新起）

| 东西 | 规则 |
|---|---|
| `FINDINGS.md` 的 §号 | **从 §1 起**。引用旧版一律写全前缀 |
| `DECISIONS.md` 的 D号 | **从 D1 起**。同上 |
| `PLAN.md` 的 Mod 号 | **从 X1 起** |
| `sessions/` 的会话号 | **从 01 起**，文件名 `YYYY-MM-DD-NN.md` |

**不接** V0.3 的 `D118` / `§122` 那一套。

## 🔴🔴 本版最硬的一条规矩：**体量红线**

用户 2026-09-15 明确要求。上一版四个文件加起来 **826 KB**，后期每个会话光读索引就吃掉
大量上下文 —— 这是反面教材，本版不许重蹈。

**判据只有一条：下一个会话需不需要它。**
需要 → 记；「我改了哪个文件的哪个函数」→ **不记**，git 有。
改了哪一行 git 里有；**为什么这么改**才要写下来。

| 文件 | 预算 | 写法 |
|---|---|---|
| `FINDINGS.md` | **一条 ≤ 25 行** | 一条一小节，**先结论后证据**。不写调查过程、不贴大段反汇编 —— 贴地址 + 那一句指令就够 |
| `DECISIONS.md` | **一条 ≤ 20 行** | 只记「为什么」，不记「是什么」。**必须写清被否掉的方案和否掉的理由** —— 那才是防止后人白推翻的东西 |
| `PROGRESS.md` | **全文 ≤ 150 行** | 只留「现在在哪 / 下一步 / 当前卡点 / ⏳ 待用户验证 / 给接手会话的话」。上一轮最多留一段，再往前的**挪进 `sessions/`** |
| `PLAN.md` | **一条 Mod ≤ 15 行** | 细节进 FINDINGS / DECISIONS，不在这里展开 |
| `sessions/*.md` | **一篇 ≤ 80 行** | 流水账只进这里 |

**超预算不是报错，是信号**：该合并同主题条目了，或者该把历史挪进 `sessions/` 了。

## 🔴 收工规则

- **每完成一个可验证小步就立刻更新 `.claude/PROGRESS.md`**，不要攒到会话结束
  —— 上下文随时可能被打断，攒着就丢了。
- 新查明的硬事实立刻追加进 `.claude/FINDINGS.md`（**失败的尝试也要记**）。
- ★★ 只要新结论涉及「某个包的某个字段 / 某个 opcode 要回什么」，
  **必须同时更新 `re/packet_api.md`**。
- 做了方案选择就记进 `.claude/DECISIONS.md`。
- 会话结束时写 `.claude/sessions/YYYY-MM-DD-NN.md`：做了什么、结果、遗留。

## 🔴 ★ 需要用户实机操作时，停下来问用户

有些验证 agent 自己做不了 —— 真打一局、点开某个界面、看模型长什么样。

**做法**：

1. 一次把话说全：**要做什么操作 / 期望看到什么 / 怎么把结果告诉我**
   （截图路径？日志片段？还是一句「行」「不行」）。
2. 登记进 `PROGRESS.md` 的 **「⏳ 待用户验证」** 区，写清「怎么做 / 期望结果 / 当前状态」。
3. **然后停下来等**，不要假装验证过了，也不要用「大概能行」代替实测结论。
4. 在等的同时，把**不依赖这条结论**的活儿继续做完。
5. 用户回话后**立刻**更新 `PROGRESS.md`，结论进 `FINDINGS.md`。

反过来也成立：**没实机跑过的就明说没跑过。** V0.1 的教训是
「单元测试全绿 ≠ 客户端认」，客户端只认字节和时序。

## ★ 启动 / 停止游戏 —— **脚本在项目根目录，agent 自己跑**

| 脚本 | 干什么 |
|---|---|
| `start.bat` | 一键启动：服务端 + 中继 + 客户端。精简日志 |
| `start-debug.bat` | 同上 + 调试日志（服务端逐包 dump）。**查协议用这个** |
| `stop.bat` | 一键停止。按端口的 `OwningProcess` 找进程，不会误杀别的 python |

- 用 **PowerShell 的 `Start-Process`** 起，别用 Git Bash —— 这两个 bat 末尾有 `pause`。
- **改完 `server/` 必须先 `stop.bat` 再 `start.bat`**（铁律 7）。
- 起完看三个地方：`logs/server.out`、`logs/server.err`（该是空的）、`logs/bshook_*.log`。
- ★ `server.out` 永远是「当前这次运行」；上一次那份被改名成
  `server-<结束时刻>.out` 归档。**要看上一局就翻归档那份。**

### ⚠ 「启动游戏」≠「操作游戏」

脚本只负责把它跑起来。要 agent 自己点鼠标打一局还得 computer-use 授权，
而且开始菜单里的「炮炮火枪手」指向的是**只读原版** `game_org\...\bigshot.exe`，
**不是 `game_patched`**。⇒ 正确入口是 start.bat/start-debug.bat：**能自己跑的验证自己做完**
（起服务端、看日志、跑测试、离线校验资源），只有「真打一局」才停下来请用户操作。

## ★ 跑测试 —— **用默认的并行，别跑串行**

```powershell
runtime\python\python.exe test\run_tests.py            # 3.14，默认并行
runtime-win7\python\python.exe test\run_tests.py       # Win7 的 3.8，同上
runtime\python\python.exe test\run_tests.py test_bot   # 只跑几个模块 / 某个类
```

- ★ 测试代码和夹具都在根目录 `test\` 下（夹具按用途分在 `test\data\` 里），
  被测代码在 `server\`。**全量名单是现扫 `test\test_*.py` 得到的** ——
  新加测试文件自动进全量，没有哪张手写表要去登记。

- ★★ **别加 `-j1`**。两套运行时都要绿，串行跑一遍就是 7 分钟，并行 1.5 分钟。
  只有「怀疑某条红是并行引起的」才拿 `-j1` 复核一次。
- ★★ **别拿 `... | tail -N` 看结果**：管道要等进程整个跑完才吐第一个字节，
  中途零输出，会被误当成卡死。要么直接看输出，要么
  `> logs\test.out 2>&1` 再 `Get-Content -Tail 5`。

## 铁律

1. **`game_org/` 和 `原版安装包/` 只读。** 想改什么都去 `game_patched/`。
   原始件毁了就再也找不回来了（客户端是从已停运 15 年的游戏里抢救出来的）。
2. **不要让 2007 年的 nProtect GameGuard 真的跑起来**（它会装内核驱动）。
   `game_patched/GameGuard.des` 必须保持改名状态。
3. **换行符和编码，三套规矩，别记混**：

   | 类型 | 行尾 | BOM | 理由 |
   |---|---|---|---|
   | `.bat` / `.cmd` | **CRLF** | UTF-8 **无** BOM | LF 的 bat 在中文 Win10 + `chcp 65001` 下会被拦腰截断 |
   | `.ps1` | **CRLF** | UTF-8 **有** BOM | 无 BOM 会被 PowerShell 5.1 按 CP936 读，中文注释乱码成语法错误 |
   | `.sh` / `.py` / `.json` / `.md` | **LF** | 无 BOM | 服务端包要在 Linux 上跑，`.sh` 带 CR 直接 `bad interpreter: /bin/sh^M` |

   ★ **`.bat` / `.cmd` 里一个中文都不许有** —— 全部写成纯 ASCII 的壳，
   中文提示搬进同名 `.ps1`。原因见全局规范（cmd.exe 按字节偏移回读，
   UTF-8 下每读一个中文指针少走 2 字节，越积越多，最后在行中间恢复执行）。
   ★★ **写中文文件一律用 Write / Edit 工具，不要用 Bash 的 heredoc**
   —— 这台机器的 Git Bash 把 heredoc 里的中文按 **CP936** 落盘，不是 UTF-8。
4. **客户端是 32 位。** 编译注入 DLL 必须用 x86 工具链（`hook/build.bat`）。
5. **不启动 `NMService.exe`**；`BsPatcherChn.exe` 现在是自研更新器，不是 NGM。
6. **GameGuard 绕过必须用配套构建的 `bsloader.exe` + `bshook.dll`**，两个不能只换一个。
7. **改完 `server/` 的代码必须重启服务端进程才生效。**
8. **`server/` 是单机和云端共用的同一套代码。** 不允许「单机分支 / 联机分支」两份实现；
   差异只能体现在**配置**和**监听地址**上。
9. **明文口令**：`server/data/accounts.json` 按需求就是明文存密码；
   **日志里不要打印密码**，打印票据即可。
10. **一切判据都要事件驱动，禁止固定次数 / 固定时间的阈值。**
    「跳过头 N 次」「等 XX 毫秒再说」这类常量是拿一台机器上的观测值当真理，
    它**掩盖**竞态而不是消除竞态。唯一例外是物理上等不到事件的地方，
    这时要在注释里写清「这里为什么等不到事件」。
11. **线上玩家数据一个字节都不能丢。**
    已经有真人在玩，云上的 `accounts.json` 是**生产数据**。
    加字段只能走「读盘时按默认值补齐」，**幂等**，反复启动不写坏也不回滚。
12. ★ **本版新增：「打开原版埋好的」优先于「自己造一个」。**
    原版常有做好了却没开的东西（爱琳 id 3 就是整套数据都在、只差模型）。
    先查原版有没有现成的坑位，有就去开它 —— 顶替 / 复活的成本比开新 id 低一个数量级
    （新 id 要补三处枚举上界、两处图标 switch、名字 switch，还得从零造全套资源，见 §2）。
13. ★ **本版新增：加资源之前先在 `Pack_develop` 里搜一遍。**
    原版画好但没用上的素材比想象的多 —— 爱琳的战斗头像就一直躺在
    `Images/NewUI2/BigChrIcons.png` 里，只是中文版的 `.smf` 把帧数截断了。
    **先搜，再动手画。**
14. ★ **本版新增：不替用户动 git 履历。**
    `commit` / `push` / `reset` / `rebase` / `merge` / `stash` 一律不做，改完停在工作区，
    把「改了哪些文件、改了什么」讲清楚，由用户自己决定怎么提交。
    只读的 `status` / `log` / `diff` / `show` 照常可以用。
