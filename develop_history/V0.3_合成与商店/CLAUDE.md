# 炮炮火枪手 · V0.3 后半 —— 装备合成与商店

复活 2007 年的《炮炮火枪手》（NEXON《Big Shot: Kaska Tournament》，世纪天成代理，2009 停服）。

**已完工并归档**（只读参考，别重新推导）：

| 版本 | 内容 |
|---|---|
| V0.1 基础单机 | 客户端在 Win10 上跑起来，localhost 假服务端撑起登录→大厅→建房→闯关→结算闭环 |
| V0.2 联机 | 真多人服务端、网页注册、云端对战与合作闯关、TCP 中继、UDP 旁路、版本门禁 + 自动更新器 |
| V0.3 前半 · bot | 房间 bot：占座、换角色、进图、走跳射击、寻路战术；离线地图地形提取 |

**本版（V0.3 后半）要做的事**：让游戏里有**东西可赚、可买、可穿**。

1. 打任务掉**合成材料**，结算界面「合成材料」那一栏真的画出来；
2. 用材料在原版**合成界面**合成装备；
3. 在原版**商店界面**买武器（**爆裂 D / 极速 R / 复合 F** 三系列）；
4. 在**仓库**里装备，装备后**伤害 / 生命 / 防御 / 换弹速度真的在游戏里变**；
5. 一个**管理员网页**（和注册页同端口，`/admin`）改上架 / 价格 / 配方 / 掉落，
   **不重启即刻生效**。

**★ 用户拍板：只做原生游戏内 UI，不做网页商店。** 风险全压在协议上（见 D1）。

这是一个**跨多会话、多 agent 的长工程**。任何一个新会话都可能是接手方。

## 🔴 开工前必读（每个会话第一件事）

按顺序读，**不要重新推导已知结论**：

1. `.claude/PROGRESS.md` —— 现在在哪、下一步、当前卡点、**⏳ 待用户验证**
2. `.claude/FINDINGS.md` —— 已查明的硬事实，以及**试过但不行的路子**
3. `.claude/DECISIONS.md` —— 为什么这么选，别无意义地推翻已定方案

总计划在 `.claude/PLAN.md`（M0 ~ M9 路线图）。

### ★★ 动协议之前的第 4 个文件：`re/packet_api.md`

客户端 ⇄ 服务端通信包的**参数 / 返回值手册**，按 opcode 排，每个字段带
✅实测 / 🔍静态 / 🤔推测 / ❓未知 标记，并写明「这一发**必须回什么**」。

- 要读某个包的字段、要知道某个 opcode 不回会怎样 → **先查它**；
- 逆出新字段、或纠正旧结论 → ★ **写 FINDINGS 的同时把它一起改掉**。

本版要往里加一整节：**商店 / 合成 / 仓库段**（`0x05xx` / `0x06xx` / `0x0704` /
`0x041c`），现在这些在 §3.6「有类名但语义未查明」里躺着。

## 🔴 收工规则

- **每完成一个可验证小步就立刻更新 `.claude/PROGRESS.md`**，不要攒到会话结束
  —— 上下文随时可能被打断，攒着就丢了。
- 新查明的硬事实立刻追加进 `.claude/FINDINGS.md`（**失败的尝试也要记**）。
- ★★ 只要新结论涉及「某个包的某个字段 / 某个 opcode 要回什么」，
  **必须同时更新 `re/packet_api.md`**。
- 做了方案选择就记进 `.claude/DECISIONS.md`（记「为什么」，不记「是什么」）。
- 会话结束时写 `.claude/sessions/YYYY-MM-DD-NN.md`：做了什么、结果、遗留。

### ★★★ 本版最硬的一条规矩：**只记关键信息，语言要短**

用户 2026-09-03 明确要求，**上一版反复没落实**（四个文件加起来 88 万字符，
后期每个会话光读索引就吃掉大量上下文）。本版立四条：

1. **判据是「下一个会话需不需要它」**。需要 → 记；只是「我改了什么」→ **不记**。
   改了哪一行 git 有；**为什么这么改**才要写下来。
2. **FINDINGS 一条一小节，先写结论再写证据**。不写调查过程、不贴大段反汇编
   —— 贴地址 + 那一句指令就够，要细节的人自己去看。
3. **PROGRESS 只保留当前状态**。做完的事从「正在做」挪走，不留历史；
   流水账进 `sessions/`。
4. **不写「修改流水账」**。「改了 X 文件的 Y 函数」这类条目一律不进这四个文件。

## 🔴 ★ 需要用户实机操作时，停下来问用户

有些验证 agent 自己做不了 —— 真打一局、点开商店界面、看结算界面那一栏画没画出来。
本版**尤其**是这一类：协议全是静态逆出来的，**只有实机能证伪**。

**做法**：

1. 一次把话说全：**要做什么操作 / 期望看到什么 / 怎么把结果告诉我**
   （截图路径？日志片段？还是一句「行」「不行」）。
2. 登记进 `PROGRESS.md` 的 **「⏳ 待用户验证」** 区，写清「怎么做 / 期望结果 / 当前状态」。
3. **然后停下来等**，不要假装验证过了，也不要用「大概能行」代替实测结论。
4. 在等的同时，把**不依赖这条结论**的活儿继续做完。
5. 用户回话后**立刻**更新 `PROGRESS.md`，结论进 `FINDINGS.md`。

反过来也成立：**没实机跑过的就明说没跑过。** V0.1 的教训是
「单元测试全绿 ≠ 客户端认」，客户端只认字节和时序。

## 铁律

1. **`game_org/` 和 `原版安装包/` 只读。** 想改什么都去 `game_patched/`。
   原始件毁了就再也找不回来了（客户端是从已停运 15 年的游戏里抢救出来的）。
2. **不要让 2007 年的 nProtect GameGuard 真的跑起来**（它会装内核驱动）。
   `game_patched/GameGuard.des` 必须保持改名状态。
3. **换行符和编码，三套规矩，别记混**：

   | 类型 | 行尾 | BOM | 理由 |
   |---|---|---|---|
   | `.bat` / `.cmd` | **CRLF** | UTF-8 **无** BOM | LF 的 bat 在中文 Win10 + `chcp 65001` 下会被拦腰截断 |
   | `.ps1` | **CRLF** | UTF-8 **有** BOM | 无 BOM 会被 PowerShell 5.1 按 CP936 读，中文注释乱码成语法错误 |
   | `.sh` / `.py` / `.json` / `.md` | **LF** | 无 BOM | 服务端包要在 Linux 上跑，`.sh` 带 CR 直接 `bad interpreter: /bin/sh^M` |

   ★★ **写中文文件一律用 Write / Edit 工具，不要用 Bash 的 heredoc**
   —— 这台机器的 Git Bash 把 heredoc 里的中文按 **CP936** 落盘，不是 UTF-8。
4. **客户端是 32 位。** 编译注入 DLL 必须用 x86 工具链。
5. **不启动 `NMService.exe`**；`BsPatcherChn.exe` 现在是自研更新器，不是 NGM。
6. **GameGuard 绕过必须用配套构建的 `bsloader.exe` + `bshook.dll`**，两个不能只换一个。
7. **改完 `server/` 的代码必须重启服务端进程才生效。**
   V0.1 会话 09 就因为服务端是改代码前启动的旧实例，白踩了一整轮。
8. **`server/` 是单机和云端共用的同一套代码。** 不允许「单机分支 / 联机分支」两份实现；
   差异只能体现在**配置**和**监听地址**上。
9. **明文口令**：`server/data/accounts.json` 按需求就是明文存密码（管理员账号同理，
   见 D3）；`.gitignore` 已排除它；**日志里不要打印密码**，打印票据即可。
10. **一切判据都要事件驱动，禁止固定次数 / 固定时间的阈值。**
    「跳过头 N 次」「等 XX 毫秒再说」这类常量是拿一台机器上的观测值当真理，
    它**掩盖**竞态而不是消除竞态。唯一例外是物理上等不到事件的地方，
    这时要在注释里写清「这里为什么等不到事件」。
11. ★ **本版新增：线上玩家数据一个字节都不能丢。**
    已经有真人在玩，云上的 `accounts.json` 是**生产数据**。
    加字段只能走「读盘时按默认值补齐」，**幂等**，反复启动不写坏也不回滚。
    动它之前先想「这一步如果崩在中间，老数据还在不在」。
12. ★ **本版新增：不要自己发明原版没有的玩法。**
    合成没有成功率（原版 UI 上没有任何概率控件）、攻防加成就是 15% 概率触发、
    换弹速度就是不受装备影响。**照原版做，把「合不合理」留给用户判断。**
    唯一允许自己设计的是**合成配方**（原版配方随服务端 DB 一起没了，见 D2）。

## ★ 启动 / 停止游戏 —— **脚本在项目根目录，agent 自己跑**

| 脚本 | 干什么 |
|---|---|
| `start.bat` | 一键启动：服务端 + 中继 + 客户端。精简日志 |
| `start-debug.bat` | 同上 + 调试日志（服务端逐包 dump）。**查协议用这个** |
| `stop.bat` | 一键停止。按端口的 `OwningProcess` 找进程，不会误杀别的 python |

- 用 **PowerShell 的 `Start-Process`** 起，别用 Git Bash —— 这两个 bat 末尾有 `pause`。
- **改完 `server/` 必须先 `stop.bat` 再 `start.bat`**（铁律 7）。
- 起完看三个地方：`logs/server.out`、`logs/server.err`（该是空的）、`logs/bshook_*.log`。
- ★ `server.out` 永远是「当前这次运行」；上一次那份被改名成
  `server-<结束时刻>.out` 归档，3 天后自动清掉。**要看上一局就翻归档那份。**
- ★ **日志一律异步写**（`server/asynclog.py`）。别往热路径上加同步 `print` / `fh.write`。

### ⚠ 「启动游戏」≠「操作游戏」

脚本只负责把它跑起来。要 agent 自己点鼠标打一局还得 computer-use 授权，
而且开始菜单里的「炮炮火枪手」指向的是**只读原版** `game_org\...\bigshot.exe`，
**不是 `game_patched`**。⇒ 在有正确入口之前：**能自己跑的验证自己做完**
（起服务端、看日志、跑测试），只有「真打一局、看界面长什么样」才停下来请用户操作。
