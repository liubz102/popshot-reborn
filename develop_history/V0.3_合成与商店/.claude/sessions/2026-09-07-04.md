# 2026-09-07 会话 14 —— 商城角色改成商店买（D51）

## 题目

用户：「之前把所有角色用 hook 的方式全解锁了，现在有商店了，把 hook 里的强制解锁删掉，
商店上架所有角色，统一 1000、不限等级，商店配置文件和生成模板一起改。」

## 查明

- 「全解锁」不在 hook 里，在服务端存档层：`account_store.NEW_ACCOUNT_DEFAULTS`
  的 `character_unlock_all = True` 让 `owned_characters()` 直接返回 11 个商城角色，
  `0x030b` 把 11 张角色卡 id 全发下去（V0.1 §119）。`hook/bshook.c` 里唯一沾边的是
  角色 110 图标越界的崩溃修补（`REGION_SITES[2]`），角色可买之后**必须留**（§43）。
- 角色卡 `kind == "character"`、`part_flag == 0`，`shop.category_of` 会把它兜进
  「道具 → 其他」；`check_purchase` 的「已拥有」只看 `part_flag != 0`，角色卡能重复买。

## 做法（D51）

- 角色 = 仓库里的角色卡：删掉 `character_unlock_all` / `owned_characters` 两个存档键，
  `owned_characters()` 从 `inventory` 派生（新增 `character_id_of_item()`）；
  `player_character()` 记着没买的商城角色时退回 0。
- `ensure_item_fields()` 开服迁移：旧列表转成角色卡、两个旧键删掉，幂等；
  `parse_save` / `import_account` 对旧版导出的存档同样处理。
- 商店：`shop.CATEGORY_MERCENARY = 0x30001`，角色卡归「人物 → 佣兵」；
  角色卡也受「已拥有不能再买」；买了角色卡顺手整份重发 `0x030b`。
- 模板：`shopdefaults.CHARACTER_PRICE = 1000`，`build_all` 里 `kind == "character"` 走
  `sell(…, 1)`；`gen_listing.py --apply --all` 只重写了 `shop.json`（484 → 495，
  旧文件 `.bak-20260907-220642`），items / recipe / drops「不变」。
- 测试：`RealDefaultsTests` 钉 495 + 11 张卡 1000 金币 / (1, None)；`CharacterUnlockTests`
  改成「仓库里有卡才发」；`ShopBuyAndEquipTests` 加买角色 / 重复买被拒 / 买装备不重发；
  `ItemFieldTests` 加迁移四条；`CategoryTests` 加佣兵分类。
  两套运行时全量 **2880 项都绿**（3.14 84 秒 / 3.8 157 秒）。
- 文档：README 的「角色全解锁」改掉；PLAN「本版不做」；`re/packet_api.md` 0x030b 那张表。
- 四路评审（购买链路 / 数据安全 / 协议 / 测试与文档）之后补的三处：
  ① `shopdata.resolve_equipped` 把 `part_flag == 0` 的一律丢掉 —— 不然角色卡能被
  `0x0702` / 控制通道 `equip` 写进 `equipped`，`0x030b` 发两遍、`0x0604` 把卡当衣服发；
  ② 管理页 `stackable()` 对角色卡返回 False（数量对角色没意义）；
  ③ `app.py` 开服多查一条：货架上一张角色卡都没有就喊一声（拿着旧 `shop.json` 升级的
  情形；`ensure_files` 照 D7 不碰已有文件，补卡走 `shop-backfill apply`）。
  测试补到 2885 项（两套运行时都绿）：0x0301 选没买的角色回 0、同车两张同卡整车拒、
  0x0601 带卡且 0x0501 在前、真模板的佣兵标签正好 11 张、管理页塞卡 = 送角色、
  卡穿不上身、`character_id_of_item` 边界。
- 服务端重启过（`launch.ps1 -NoGame`，只起了服务端 + 中继）：开服日志 11 个号各一行
  「删掉作废的 character_unlock_all / owned_characters」，`server.err` 空，
  货架有卡所以那条提醒没响。
