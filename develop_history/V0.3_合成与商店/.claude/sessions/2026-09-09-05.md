# 会话 22 —— 客户端闪退后自动上传诊断日志

## 需求

用户：新加的道具有时会让客户端闪退，想要「崩溃后自动上传诊断日志」。
点名的约束：只在远程模式上传 / 只传最近一次 / 先压缩 / 服务端按
`logs_client_crash/<客户端ID>_<时刻>/` 存不解压 / 失败隔 3 秒重试 3 次 /
无论成败都写日志。追加要求：**上传和服务端保存都要异步，不能阻塞其他操作**；
以及「用户名拼进文件夹名有没有考虑特殊字符」。

## 纠正了用户方案里的一个前提

用户说「由本机服务端监控客户端状态」。**改成本机中继**（D58）——
`launch.ps1` 每次都同时起 `app.py` 和 `relay.py`，而模式是玩家在登录界面点单选钮选的、
纯内存不落盘。本机服务端**不知道**这一局是不是联机；中继知道，而且是由构造知道
（本机模式下 bshook 压根不连中继）。这样「只在远程模式上传」不用写任何判断。

## 顺手查明的东西（都进了 FINDINGS）

* **§54 `0x0103` 本身就是崩溃报告包**，不是「收尾标志」；而且**客户端上报完就把
  `LastCrashReport.txt` 删掉**。这条是干活当中撞见的 —— 磁盘上那个文件在我调查期间
  消失了，回去翻归档的 `server-20260909-122222.out` 才看清：12:09 那次登录的 `0x0103`
  载荷 1890 字节 = `int32(1)+int32(1878)+正文`。⇒ 打包必须用**已经读进内存**的那份文本。
* **§55** 三份崩溃文件的关系和「哪一份属于这一次」的定位规则。
* **§56** 认 PID / 等退出 / 拿会话起点的三个 Windows API，以及「进程对象置位 ⇒ 文件
  一定写完了」这条把竞态整个消掉的性质。
* **§57** `bshook_*_pid<PID>.log` 文件名带 PID；`UserConfig.ini` 的 `LastLoginId`
  不是注册账号名。
* **§58** minidump 压缩比实测。

## 踩到的三个坑

1. **`open(..., "r")` 的通用换行**把 `\r\n` 变成 `\n`，包里那份就不再和玩家机器上那份
   逐字节相同。⇒ 读崩溃文本一律 `newline=""`。
2. **`zf.writestr(str)` 按 UTF-8 编码**，把 latin-1 读进来的原始字节又编了一遍。
   ⇒ 写进包前 `.encode("latin-1")` 编回原始字节；想说的话放 `meta.json`，
   不掺进要保持原样的正文。
3. **拒收时一个字节都不读就关连接**，对方卡在 `send` 上被 RST 打断，
   **连我们回的那句「包太大」都读不到**。⇒ D64：回完再读掉一部分，上限取
   `crash_max_bytes`。
4. **`BUILD.ver` 被当成一个字符串整份塞进 `meta.json`**（用户看试传的包时发现它是空的）。
   两个问题：读不到时**静默变成空串**（分不清「没版本号」和「没读着」）；
   而包里那份是**富 JSON**（`buildId` / `bshookHash` / `bsloaderHash` /
   `serverCodeHash` + 一大段中文 `notes`），整份塞进去既难看又浪费。
   ⇒ `read_build_info()` 解析后只挑 8 个有用字段，读不到时回 `{"error": ...}`。
   顺带把原版客户端自己的 `Version: 311` 也解出来存成 `client_version` ——
   它和我们的 `BUILD.ver` 是两回事，查崩溃两个都要。

## 验证

* `server/run_tests.py`：**3014 项全绿**，3.14 和 3.8（Win7 运行时）各跑一遍。
* **离线重放真实崩溃**（脚本在 scratchpad）：拿磁盘上那份 35.2 MB 的
  `BigShotV0311N001.mdmp` + `BigShot.rpt` 的第 13 段，
  → 打包 **11.6 MB / 0.5 秒**，rpt 只截最后一段，mdmp 按 `Dump File Name:` 定位对，
  ID `testuser1_cb4eb64b_20260909-013642` 过服务端正则，zip 自检通过。
* **端到端**：真包经真的上传器 POST 给真的服务端 —— **0.36 秒（32 MB/s）**，
  落地逐字节一致、sha256 对上、没解压；把目录改名成大写再传一次，
  自动变成 `testuser1-2_...`（D60 那个 Linux 大小写坑）。
* **不阻塞**：一边灌 11.6 MB、一边打 `/api/register` —— 注册响应中位 **27 ms**
  vs 基线 30 ms。
* `stop.bat` → `launch.ps1 -NoGame` 起过：中继和服务端两条新日志都对，`relay.err` 空。
* **客户端包当服务器用的那条路**（用户追问）：直接跑 `python server/app.py`
  （客户端包用的就是这个文件），往 `local_register_port` 传那个真包 —— **收下了**，
  落在**包根**的 `logs_client_crash/` 里，逐字节一致、sha256 对上。
  接收端在 `web/server.py` + `app.py`，两个包同一份代码（铁律 8），不存在
  「服务端版才收」。顺带补了两处：`build-portable.ps1` 也建那个空目录、
  README 明说这条路 + 不需要额外开防火墙端口（走的就是注册页那个 27810）。
  新增 `LayoutTests` 把「落地目录 = `server/` 的上一级」这条不变量钉住。
