# 2026-09-10 会话 03 —— 排云端收到的 5 份线上崩溃现场（bug调查/17）

## 用户要的

「云服务器收到了几个崩溃日志，我拿下来放到 `bug调查/17` 了，请分别帮我调查并修改。」

## 做了什么

### 1. 先发现「5 份里 3 份是空的」，并查明为什么（§65，最要紧的一条）

三份 `LastCrashReport.txt` 都只有开头四行、`.mdmp` 没生成。
一开始以为是上传或收集出了问题，逐字节看之后发现**断点唯一**：
永远停在 `Exception code: …\r\r\n` 之后，而那之后到 `Fault address:` 之间
**只有 `call 0x5d7695` 一个调用**。读那个函数 ⇒ `AllocationBase == 0` 时
`[0+0x3c]` 读空指针，而 `GetModuleFileNameA(NULL,…)` 恰好返回非 0 把判断骗过去。

**A/B 实证**（本机）：`CreateRemoteThread(起始地址=0)` 造一次 EIP=0 的崩溃 ——
原版 238 字节无 dump，补丁后 982 字节 + 12.6 MB dump。

⇒ 顺带得到推论：那三次的出错地址在**未映射页** = 野指针 call 跳飞，
和有完整栈的那次 `PRIV_INSTRUCTION` 同族 ⇒ **5 次里 4 次同类**。

### 2. 有完整栈的那次：`[Character+0x57C]` 的 `DashDamage` 虚表不是虚表（§66）

栈是 `GameContext::Process → Character::ProcessMove → ProcessDash → 0x4814f2`，
崩在 `mov eax,[esi] / call [eax+0x78]`，`[esi] = 0x425DECA0`（堆地址）。
三处解引用全补虚表校验，**只跳过不写回**。根因（谁放掉的对象）没查到 —— 明写着是兜底。

★ 函数名是从 exe 里 `push 行号 / push ".\\X.cpp" / push "Class::Method"` 那套
探针串批量还原的（`call 0x5d601f` 的 15 个调用点）—— 这套以后还能再用。

### 3. 顺手查掉本机 `BigShot.rpt` 09-10 00:05:39 那次（§67）

`0x0411 gspEndGame` 处理器 `0x5518de` 不判空，`[0x72e2dc]`（GameContext）
关卡外就是 NULL。补在客户端不补在服务端 —— 理由见 D71 ②。

### 4. 剩下那次：`nmconew.dll` 的锁在等待期间被析构（§68）—— **没修**

理由写进 D71 ④：跳过那两句写只是把崩溃挪到下一句，而且那个 DLL 基址随机。
可选缓解（拦 `NMService.exe`）单列成「要用户拍板 + 实机验」的事。

### 5. 把「是不是内存吃紧」变成一行数（§69）

原本只是看 dump 里线程栈铺得高得来的印象，而线程栈本来就随机落位。
给 30 秒心跳加了已提交 / 已保留 / 最大连续空闲块（纯 `VirtualQuery`）。
**本机登录界面基线：561~570 MB / 最大空闲块 804 MB。**

## 结果

- 只改 `hook/bshook.c`（**服务端一行没动**），`hook/bin/bshook.dll` 重编 185344 字节。
- 真客户端起过，5 处签名全对上；再从活进程回读这 5 处反汇编核对过。
- 报告写在 `bug调查/17/调查报告.md`。

## 遗留

- **V-64 等实机**：正常打一局别出新毛病 / `0x0411` 判空实测 / 心跳那行数看趋势。
- 崩溃 A 的根因没查到（谁释放的 `DashDamage`）—— 靠新加的 `★DASH` 探针等下一次。
- 崩溃 B 没修。
- ★ **线上玩家要拿到这一批，必须重打客户端包 + 抬版本号**（和 U-63 同一包）。

## 踩过的坑

- `MINIDUMP_EXCEPTION_STREAM` 的 `ThreadContext` 偏移是 **`r+160`**
  （`8 + sizeof(MINIDUMP_EXCEPTION=152)`），写成 176 会读到 SystemInfo 里的 CPUID 串。
- `start.bat` / `stop.bat` 里有 `pause`，`Start-Process -Wait` 会永远等下去 ——
  agent 直接跑 `tools/launch.ps1` / `tools/shutdown.ps1` 就好。
- 仓库里的便携 Python（`runtime\python`）没有 capstone，反汇编脚本要用系统 python。
