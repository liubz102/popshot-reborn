# 2026-09-05 会话 02 —— 商店段全部逆通，M4 收尾 + M5 实装

## 起点

会话 01 的遗留：「M4 第 2 步（开始回包）没动」，以及 PROGRESS 里那条
「货架目录到底走哪个 opcode 仍然没落锤」。

## 做了什么

### ① 货架目录落锤 = `0x0600`（FINDINGS §20 ~ §23）

顺序是：`gspRepEquippedList` 的 Des → `Equipment` 类 → `0x0500` 的元素其实是
`ShopStockGroup`（嵌套 vector，不是「3 个 int」）→ 顺着 `0x45bc93`（格子刷新）
找到价格 / 货币两个字段 → 顺着 `0x445e40`（带 10 秒节流的那个）
找到**货架请求 = `0x0600`**。

**最关键的一步是回头翻旧日志**：`0x0600` 在 2026-09-04 那次实机里**早就抓到了**
（`logs/server-20260904-223901.out:186`），只是会话 03 的 `SHOP_PROBE_OPCODES`
里没有它，所以只落在通用包日志里没人看。⇒ **新增上行 opcode 要两边都加。**

顺带纠正 §19 记错的线格式（`u8+i32+u16+i32`，判据三条）。

### ② 实机：货架真的画出来了

用户进商店，8 个格子有图标 + 中文名 + 价格 +「金币」+「购买」。日志还证实了
**翻页**（20 件 → `1/3`）、**角色切换**（`1120xxx→2120xxx→3120xxx`）、
**武器 1/2/3 子分类**都对。

**抓到一个 bug**：点「人物 → 英雄」列出一堆武器 —— 服务端把 `分类 = 0` 当成
「全部」，其实那是英雄标签的真 id。改成 `CATEGORY_ALL = -1` 当哨兵。
顺带把 6 个顶级标签的分类 id 全对上了（§22）。

### ③ ★★ 穿装备是 `0x0702` / `0x0703`，不是 `0x0604`（§24）

`0x0604` 上行的唯一调用点写死 `210003`（扳手）⇒ 它是**修理**。
真正的穿脱是**从没出现在任何表里的 `0x0702` / `0x0703`**，两发都回 `0x0604`，
而且**必须一发不落**（客户端用 `[ShopStage+0x13c]` 数着还差几发）。

**找到它的办法**：机械扫 `SetType` 扫不出来（线性反汇编在数据处失步），
是顺着 UI 按钮一路跟出来的：`착용` 串 → 按钮存 `[obj+0xac]` → 分发 `0x45270a`
→ `0x445703` → 校验全过之后 `0x554393`。⇒ **跟按钮比扫 opcode 可靠。**

顺带把 `0x0601`(要物品定义) / `0x0603`(卖) / `0x060b`(用道具) 也对上了 ——
商店段的上行现在**一个 ❓ 都不剩**。

### ④ 实装

- 新增 `server/shop.py`：解包 / 分类 / 分页 / 五发下行组包 / 购买校验。
- `gameserver.py` 现在回：`0x0600`→`0x0500`、`0x0704`→`0x0604`、
  `0x0607`→`0x0508`(空)、`0x0602`→`0x0502`(+补 `0x0600`+`0x0604`)、
  `0x0702`/`0x0703`→`0x0604`(+重发 `0x030b`)。**`0x0700` 坚决不回**。
- 控制命令：`shop-reply on|off <op>`（运行时二分，D18）、
  `shelf-probe on|off`（在界面上找未查明字段，D19）、`shelf` 干看一页。
