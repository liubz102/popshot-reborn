# 2026-09-09 会话 06 —— 关掉客户端自己画的那行绿色加成文字

## 用户报的五个现象（实机截图）

改完 §53 那版说明文后，用户在合成 / 仓库两个面板上看到：

1. 绿色的属性加成和上面白字重复，不知道该删哪个
2. 有个装备中间绿字写「速度+d%」
3. 绿字显示不下会换行，超出中间格子高度
4. 仓库里绿字会「错位」到下面的格子
5. 绿字会变英语，尤其称号

## 查明：**五个里有四个不是我们改出来的**

那行绿字是**客户端自己**按 itemId 查本地 `EquipBonus-Chn.ini` 生成的
（`0x414128 → 0x4136af`），画进 `ItemInfo2Txt`，颜色 `0xFF22C701`。
和服务端下发的 `ItemInfo+0x18` **完全无关**。详见 **§59**。

| # | 真相 |
|---|---|
| 1 | 绿字 = 客户端自算；**只在仓库 / 合成出现**，商店提示框那条绿字是 grant 列表 |
| 2 | `Chinese.ini` 错字 `Spd%+d%%=速度+d%%`（漏了 `d` 前面的 `%`），长格式是对的 |
| 3 | `ItemInfo2Txt` 在 `.ui` 里只有 **240×14 = 一行**，属性一多就溢出 |
| 4 | **不是错位**：三个框位置写死，绿字 y=256 本来就夹在第 1 段(y=165) 和第 2 段(y=274) 中间 |
| 5 | `Chinese.ini` 漏翻 `Team %d%% %s` / `Self %d%% %s` / `Down`（只翻了短格式） |

### 一个查了很久的 ❓ 顺手结掉

`.ini` 加载器 `0x413ec9` 先问 `0x55e7f0`「在不在 pak 里」，**不在就跳 `0x4140d2` =
函数尾直接 return**。⇒ **散文件不能覆盖 pak，也不会被当作补充加载**。
§1 结尾那条「真要改数值时先实测散文件能否覆盖」有答案了：**不能**，
要改 `Chinese.ini` / `EquipBonus.ini` 只能重打 `.pkn`（项目里没有打包工具）。

（不画加成），而仓库那几个面板**共用同一个类**。

## 改了什么

**两处各一个字节。** `hook/bshook.c` 新增 `try_patch_hide_client_bonus_text()`
（一张两条的表，**两处都打中才算成功**）：

| 补丁点 | 生成器 | 原字节 → 改成 | 管哪些界面 |
|---|---|---|---|
| `0x41415E` | `0x414128`（单件）| `74 20` → `EB 20` | 仓库提示框 / 合成提示框 / 修理界面 |
| `0x414208` | `0x4141AC`（按 id 列表累加）| `74 07` → `EB 07` | **商店提示框** |

★ 打在**生成器**上而不是五个绘制点上；走的是**原版每天都在走**的那条路
（武器 / 材料 / 纯外观装备本来就查不到条目），SEH 状态和 vector 生命周期一步不差。
累加那一处还额外核对了：`0x4136AF` **两条格式分支都逐项判零**
（`0x41379D` / `0x413A7F`），累加器全 0 ⇒ 输出空表。
`BSHOOK_KEEP_CLIENT_BONUS_TEXT=1` 可回到原版。

`hook/bin/` 重编（bshook.dll 178688 字节），两条特征串和 exe **逐字节核对过**。
**服务端一行没改**，全量测试 3022 项绿。

## ⚠ 中间翻过一次车

第一版**只堵了 `0x414128` 就收工**，用户实机一眼看出「商店浮窗里还有绿字」——
商店走的是**另一个**生成器 `0x4141AC`。两条错误的判据：

1. 只扫 `push 0xFF22C701` ⇒ 漏了修理界面那处 `mov [eax+0x4c], 0xFF22C701`；
2. 找到一个生成器就当成「唯一入口」⇒ 漏了商店那条。

★ 正确的判据是**数据源**：`xref 0x72e440`（EquipBonus 显示表）出 11 个引用，
逐个分类，才能确定谁在用它。写进 §59 ⑦。
