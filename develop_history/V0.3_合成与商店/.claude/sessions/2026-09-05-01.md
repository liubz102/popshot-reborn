## 做了什么

### ① 装备生效 —— 两条独立实证（FINDINGS §16）

- 新写 `tools/probe_equip_bonus.py`：从跑着的客户端读 `EquipmentEx` 的桶表。
  路径 `[0x72e29c] → +0x250+seat*4 → +0x3c 的 hash map → 节点 +8 的 int 数组`。
  **大厅里就读得到**（`0x030b` 一到桶就建好），所以不用真开一局 —— 这是关键，
  否则每验一次都要人工进房。
  实读：桶 0 = `Attack=-1 / Defense=3 / Hp=29 / Sp=2` ⇒ 血上限 **129**。
- 从 2026-09-04 那份 `logs/game_*.txt` 里把 `rawPeerData` 全解了一遍
  （脚本在 scratchpad，逻辑写进了 FINDINGS）：69 发 `rpFire` 的 ammo 全是
  `1000115`（D2），`rpExplode` 伤害 60 发 5.0 / 9 发 4.0。

### ② 「有时候 4」查清了（FINDINGS §16 ③）

9 发 4.0 的 `rpExplode` **flags 全带 `0x0800`**，而 `0x480827` 那句
`or byte [ebp-3], 8` 正好是「装备攻击加成是负数且这一发触发了」的标记位。
玩家的裤子 `1020062` 是 `Attack=-1`，`int(5×0.99)=4`；9/69=13% 对上 `0x6938cc`=0.15
那道概率门。**原版机制，不是 bug。**

「虚弱攻击」那个提示在原版资源里搜不到（`Data/*.ini` 三种编码全量搜 +
`Images/` 扫了一遍），判断是记岔了。

### ③ 管理页难度下拉框（D17 / FINDINGS §18）

**测完把三份 json 按备份还原了**，`md5` 逐个核对过，用户的数据一个字节没动。
