# 2026-09-10 会话 06（第 31 个会话）—— 管理页「发送奖励」：批量发到玩家的原版礼物盒

## 用户点的题

管理页「玩家仓库」现在只能一个一个点开「修改仓库」加东西，想给多人发奖励太麻烦。要：

1. 利用原版的**礼物盒**：直接发到各玩家的礼物盒里，玩家自己在礼物盒里领；
2. 「玩家仓库」页加一个「发送奖励」钮，放在「当前在线」文字**左边**；
3. 弹窗左右分屏：左边玩家列表（名称 + 在线状态筛选，逐个勾或一键全选，选中的
   显示在上方「奖励玩家名单」），右边物品选择区（和「修改仓库」一样，去掉等级 /
   经验 / 金币），「添加物品」再开一个可多选的选择弹窗；
4. 右侧还要能输经验和金币；
5. 「确认发送奖励」先弹确认框；玩家点开礼物盒要能正常领；
6. 不知道原版礼物盒能不能装经验 / 金币，不行就想个方案。
7. （看完计划后补的）留言要有个输入框可以自由输入，默认「管理员发送的奖励」。

## 第二轮：用户实机看了礼物盒（截图五张）

礼物盒开得出来、8 格翻页、接收 / 合并弹窗都对 ⇒ `Gift` 线格式落锤。三个问题：

1. 「绿色小珠 ×5（0个）」、合并框「道具数量增加为 2 个」—— 赠品条目 `Item@ShopStock`
   的第二个 int 是**数量**（`0x443444` 读 `+0x08` 拼「N개」、`+0x0c` 拼「N일」），
   以前照货架的习惯填 0。`build_shop_stock(grants=[(id, 数量, 天数)])`，`build_gift` 填真实数量。
2. 材料 / 卡片「(FileNotFound)」—— 客户端有两张 id→图标表：`[Stock-]`（1817 件商店货）和
   `[Item-]`（808 件全表）；礼物槽 / 接收弹窗 / 货架用 `0x4169e9` 查前者，合成 / 仓库 / 结算用
   `0x416a1a` 查后者。材料没有 `[Stock-]` 节。**hook 新增 `try_patch_gift_icon_fallback()`**：
   `0x4169e9` miss 分支的 `push L""` 换成 jmp，detour 里 `mov ecx,[0x72e1e0]; push [ebp+8];
   call 0x416a1a; jmp 0x416a14`（`BSHOOK_KEEP_GIFT_ICON_MISS=1` 保留原版）。`hook/bin/` 重编
   （bshook.dll 185856 字节）。★ 重编时用户的客户端还在跑、锁着 `hook/bin/` 两个文件 ——
   把它们改名挪到 `logs/*.inuse-pid*`（映射中的文件允许改名）再编，客户端退出后那两份可删。
3. 弹窗左栏搜索框打字不刷新（只有回车 / 改在线下拉才查）—— 改成 `oninput` 边打边查，
   每发带递增序号、只认最后一发的回包（不设延时，铁律 10）。

## 第三轮：「绿色小珠 ×5（5个）」重复

数量修好之后名字里的「×5」就多余了 —— `gift_display_name` 物品礼物只写名字，
凭证仍写「经验 ×500」（形态标志 0，括号里不显示数量）；控制通道的 `_gift_label` 自己补 ×N。
`test_shop.parse_gift` / `parse_rep_gift_list` 提成模块级函数给 `test_gameserver` 共用。
