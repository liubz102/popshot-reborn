# 2026-09-11-04（会话 37）—— 打包前自动重编 hook（被占用就中止）+ hook 编译改成可复现

## 用户点的题

> hook 的编译和最后的打包以前一直是分开的两件事，但是最近的防倒卖篡改的修改之后，
> 打包必须记录 hook 的 sha，所以每次打包前最好重新编译一下 hook，不然有不同步的可能。
> 帮我改一下打包脚本，每次打包时，先自动重新编译一遍 hook，再跑后面的打包逻辑。
> 如果 hook 当时被占用无法编译，则打包界面要有提示 hook 被占用，并且不能跑打包逻辑。

## 做了什么

- **`tools/build-common.ps1`** 新增两个函数（决定和理由全在 **D87**）：
  - `Assert-HookWritable`：判据是真去 `[System.IO.File]::Open(..., ReadWrite, Share::Read)`
    开一次写句柄 —— 和链接器待会儿遇到的是同一件事。`IOException` = 被占用，
    其它异常 = 写不进去（只读 / ACL），两种两句提示；进程名（`BigShot` / `bsloader`）
    只当**提示**列，列不到照样报被占用。
  - `Invoke-HookBuild`：跑 `hook/build.bat`，输出**捕获**起来只在失败时打，
    成功只打一行（DLL 字节数 + SHA 前 16 位）。占用问两次（编之前 / 编失败之后）。
    同一个 powershell 进程只真编一次（`$global:PopShotHookBuilt`）。
- **调用点四处**，都在**删旧成果物之前**：`build-portable.ps1` /
  `build-server-package.ps1` 排在 `Assert-EmptyTarget` 前；`build-menu.ps1` 加了个
  本地的 `Invoke-HookBuildOrExit`（失败打 `[失败] …` 再 `exit 1`），带参数和走菜单
  两条分支各在自己的 `Clear-Stale` 前调一次。
  ★ 菜单那次**故意排在读完选择之后**：不然「双击进来看一眼版本号又退出」也会
  重编一次、白白换掉三个文件的内容（§92）。判据是「人已经决定要打了」。
- **`server/test_hookintegrity.py`** 加 `PackagingRebuildsTheHookTests` 4 条：
  函数在不在、被占用是 `throw` 不是黄字、两个打包脚本和菜单的调用**下标**都在
  删除动作之前（菜单那条还比个数，少一条分支就红；变异测试验过这两条都不是空判）。

## 结果

- 两套运行时全量 **3210 项全绿**（3.14 / 3.8.10，新增 6 项）。
- **实跑过六条路**：
  1. 正常：`Invoke-HookBuild` 编出来、同进程第二次跳过；
  2. 占用：独占持有 `hook/bin/bshook.dll`，带参数（`-Client -Zip`）和走菜单（选 1）
     **两条分支**都 ⇒ 红框「hook 被占用，编译不了 —— 打包中止」+ `[失败]` +
     退出码 1，`dist\` 条目数前后一致、`hook/bin` 和清单的 `git status` 是空的；
     直接跑 `build-portable.ps1 -Force -OutputDirectory` 指向一个带标记文件的
     目录，标记文件**没被删**（证明确实停在 `Assert-EmptyTarget` 之前）；
  3. 只看菜单：选了个无效项 ⇒ `[错误] 无效的选择`，hook 的 sha **没变**；
  4. 选 1 之后对「删除旧成果物？」答 N ⇒ 先编（sha 变了）、再问、再「已取消，
     什么都没动」，`dist\` 一个条目没少；
  5. 整包：服务端包打进临时目录跑完（含自检，认证/游戏/中继/注册页全起来、
     注册页 200），包里 `manifest-hook.json` 的 sha256 和那一刻 `hook/bin/bshook.dll`
     **逐位相同**。
- **服务端代码一行没动**，`game_patched/` 没碰。
- 验完把 `hook/bin/*` 和 `server/manifest-hook.json` **从备份还原**回 HEAD 的状态，
  工作区只剩 5 个源码文件的改动。

## 第二件事（同一轮，用户当场拍板）：`/Brepro`，让 hook 的编译可复现

本来的代价是「同源码重编只差 PE 时间戳、但 sha 必换」⇒ 每打一次包就弄脏三个
文件，而且同版本先前发出去的客户端会对不上新打的清单。用户说「这个可以帮我做」。

- `hook/build.bat` 两条 `cl` **各加两个** `/Brepro`（编译一个、`/link` 后面一个）。
- 实测：**连编两次逐字节完全相同**（212480 / 126464 字节，diff 0）；
  `[hookman]` 第二次报「无变化」。
- 和改之前那份比差 4720 字节，来路查穿了（**代码没变**）：调试目录多一条
  `IMAGE_DEBUG_TYPE_REPRO`（28→56 字节）⇒ 后面的东西整体挪 `0x20`
  （POGO rva `0x30ED8`→`0x30EF8`）⇒ `.rdata` 一大片 4 字节指针表只有低位变、
  `.reloc` 跟着改、`.text` 64 个引用它的立即数跟着改。
  `TimeDateStamp` 从 `0x6AA405D2`（真实时间）变成 `0xD83770A5`（内容哈希，
  **不是** `0xFFFFFFFF`，不会触发那类 AV 启发式）。
- `test_hookintegrity.ReproducibleBuildTests` 2 条钉住：两条 `cl` 的编译半截和
  链接半截各有 `/Brepro`；外加一条守铁律 3 的「`build.bat` 字节数 == 字符数」。

## 遗留 / 要知道的

- ★★ **`hook/bin/*` 两个二进制 + `server/manifest-hook.json` 现在是改动状态**
  （新 sha `7931f38ee900e7ef…`）。它们和 `hook/build.bat` 是**一套，要一起提交**。
- ★★ **这一版 hook 还没实机跑过** —— 登记成 **Z-76**。原理上碰不到补丁逻辑
  （hook 打的是 BigShot.exe 里的硬编码地址，和它自己的布局无关），但这个项目
  的判据一向是实机，**别拿静态结论当跑过**。
- ★ 用户那台服务端当时**开着**（pid 32756 听 27810），本轮**没碰** ——
  Z-76 要 `stop.bat` 会把它一起停掉，时机由用户挑。
- 编译时的 C4819 / C4474 警告是这个环境下 cl 的老毛病（V0.2 FINDINGS 已澄清），
  和 `/Brepro` 无关，**不是本轮引入的**。
- 顺带记一条**本来就有**的噪音：`tools/build-menu.ps1` 是 **LF 行尾**（有 BOM），
  不符合铁律 3 的「`.ps1` 用 CRLF」。本轮**没动**它 —— 改行尾会让整份文件进 diff，
  和这次的改动混在一起。功能上没影响（PowerShell 吃 LF）。
