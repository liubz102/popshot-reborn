# 2026-09-05 会话 04 —— 四个实机 bug 一个根因：**物品定义表是服务端喂的**

## 起点

用户带着实机反馈进来：

1. 进商店初始是「基本顺序」（= §25 那条推测的实测确认）；
2. 左边人物模型区**一进去是空的**，点个商品加购物车才显示出来；
3. 点购买 → 弹「**无法从服务器读取道具信息**」；
4. 仓库是空的（`gs_ctl.py inv` 明明有东西）；
5. 人物模型不显示已穿的装备。

## 做了什么

### ① 顺着那句中文提示查到根因（§28）

`Chinese.ini` 把它翻回韩文原串 → 镜像里 `0x666e30` → 10 个引用点，
全是「ItemDB 查不到 id」的分支。再顺着 `0x55403a`（发 `0x0601`）
和它的 Des `0x559357` 挖出**服务端方向的 `0x0501`**（处理器 `0x554136`）。

结论：**客户端有两张物品表**。`ShopItem-Chn.ini` 只填图标 + `PartFlag`
（`[0x72e1e0]`）；名字 / 等级 / 角色限定 / **可装备位**在另一张
（`[0x72e1dc]`），**开机是空的，只有 `0x0501` 能填**。
⇒ 用户报的 2/3/4/5 是同一个根因。

`ItemInfo` 十三个字段逐个跟消费点定的语义（表在 §28）。
关键三条：`+0x0c` 部位掩码、`+0x10` 形态标志（**bit3 = 可装备**，
`0x0604` 的处理器只认它）、`+0x1c` 等级要求（**大于玩家等级就穿不上**）。
剩下五格全镜像找不到消费点，和 `ShopStock` 那三格同款（§26），填 0。

### ② 仓库的数据源也找到了（§29）

`0x0700` 不是「进商店了」，是**「给我持有物清单」**，应答是**服务端方向的
`0x0601`**（又一对同号反向）。处理器整份换掉全局背包并重建仓库面板。
⇒ 之前这一发一直没人回，仓库当然是空的。

顺带发现 **`0x0604` 发的是「穿在身上的」不是「我拥有的全部」** ——
处理器把清单里每件可装备的都 `Equip` 进左侧人物模型那个 `EquipmentEx`。
原来的代码发的是全部持有物，等于让玩家同时穿着所有装备。

### ③ 实装

`shop.py` 新增：`parse_item_info_request` / `build_item_info` /
`build_rep_item_info` / `item_info_records` / `build_rep_inventory` /
`inventory_records`。`gameserver.py` 新增两个处理器 + 三处主动下发。
**顺序是硬要求**：定义永远排在清单前面（理由记进 D20）。

顺手修了 `tools/fakeclient.py`：它还在发原版的握手版本号 `311`，
V0.2 加了版本门禁之后**根本连不上**（被 0xFE 顶回来）。改成读包根 `BUILD.ver`。

## 结果

- **2585 + 新增 13 项全绿**；服务端 15:07 重启。
- 假客户端逐字节验过整条链：进商店五发 → 回 `0x0501`(8 条定义) + `0x0500`
  + `0x0501`(6 条) + `0x0604` + `0x0508` + `0x0501`(10 条) + `0x0601`(10 件)，
  字段全对（含材料 4 种、`flags=1`、`char=-1`）。
- `packet_api.md` 加了 §3.9，§1.5 同号反向表补了 `0x0601` / `0x0700`。

## 第二轮：实机反馈 → 又两个 bug（§30）

用户实机确认：**人物模型、仓库（材料在「收集品 → 材料」）、穿脱都好了**。
剩下两条：

### ④ 「买完问要不要直接穿上，选了没反应」

`0x0502` 的处理器点确定之后，去**本地背包 `[0x72e41c]`** 里找刚买的 itemId，
**找不到就一声不吭**（`0x4463f0` → `0x4463f7`）。而那个确认框是阻塞的
—— 我们把 `0x0601` 排在 `0x0502` 后面，玩家点确定时背包里还没有那件东西。
⇒ **顺序翻过来**：`0x0501` → `0x0601` → `0x0604` → `0x0600` → `0x0502` 最后。

### ⑤ 「买布洛克的武器报『未定义的错误』」

两个毛病叠在一起：

1. 我们按「玩家当前是哪个角色」拦了购买 —— **原版没有这条规矩**，
   商店上方那排角色箭头就是给「替别的角色买」用的（货架已经按预览角色滤过）。
2. 更要紧的是**那句「未定义的错误」暴露了 `0x0502` 第二格的语义**：
   它是**失败原因码**（`0x45915f` 的 switch，7 个分支 + 兜底）。
   §24 那句「失败时客户端什么都不显示」被实机推翻了。
   ⇒ 每条拒绝都挑一个码；**兜底是 6「内部错误」，不是 0**。

## 结果

- **2606 项绿 × 两个运行时**；服务端 15:44 重启。
- 假客户端拿 `test1` 验过失败路径：回的是原因码 `3`（等级太低）。
  ★ **买成功那条路的发包顺序线上没跑过**（不想动用户存档里的金币），
  只有单元测试盯着 —— 待用户实机。
- `packet_api.md` 的 `0x0502` 那两处都改了（原因码表 + 顺序）。

## 第三轮：又三条，全是「被判成死字段的格子其实有人读」（§31）

用户实机确认：跨角色购买、买完直接装备、失败原因都好了。新报三条：

### ⑥ 房间里「卸下」弹「已卸下。」但实际没卸

`Equipment` 头上那 12 字节**不是死字段**（§23 那句作废）：它是
**每个角色一个 `PartFlag` 槽位掩码**，房间里的卸下按钮拿
`(掩码[角色] & PartFlag) == PartFlag` 判「这件穿着没有」（`0x5584ab`）。

**为什么只有房间里出问题**：`0x0604` 的处理器**先默认构造再逐件 `Equip`**
（掩码客户端自己算），`0x030b` 走的是**拷贝构造**（`memcpy` 我们那 12 个零）。
⇒ 两发都按 `shop.equipment_slot_masks()` 算着发。
★ 战斗加成不受影响（只遍历 id vector），所以 §16 那轮实测没暴露它。

### ⑦ 提示框价格写成「0 → 3000」

`ShopStock+0x10` = **划线原价**，和售价不等就画「原价 → 现价」（`0x45c354`）。
⇒ 不打折就填成和售价一样。

### ⑧ 提示框下半是空的

`ShopStock+0x18`（商店）和 **`ItemInfo+0x18`（仓库）** 都是**物品说明**，
按 `|` 切最多 3 段。原版的说明随服务端 DB 没了 ⇒ 新增
`shopcfg.item_desc_zh()` **从本地数据现算**（`weapon.ini` 的伤害/弹匣/换弹/初速、
`EquipBonus-Chn.ini` 的加成）——**每个数客户端自己也查得到**，不算发明玩法。

★ **§26 的教训应验了两次**：探针轮的负结果是在**货架格子**上跑的，
只能证明格子不读。提示框读得好好的。

## 结果

- **2612 项绿 × 两个运行时**；服务端 16:35 重启。
- 假客户端线上验过字节：划线原价 = 售价、说明发出去了、
  槽位掩码 = `[4124, 0, 0]`（武器槽3 + 手套 + 鞋 + 头）。
- 探针从三格缩成两格（`ShopStock+0x1c` 和 `0x0502` 第三格），值统一 `888`。
