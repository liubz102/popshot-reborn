# 2026-09-09 会话 04 —— 把 13 种装备加成全写进物品说明文

## 用户要什么

「鼠标指到物品上会弹详细说明，GM 管理页也用同一份。但**很多物品没有说明文，
其实它有会影响游戏的加成效果** —— 比如昨晚刚修的火焰蝙蝠，它给溅射伤害加成，
要不是遇到那个 bug 我都不知道。请整体扫一遍所有道具，逆向查出每个道具实际有
什么加成，写成简单的效果说明文显示到弹窗里。」

附加：① 只扫**当前上架**（商店 + 合成）的；② **已经写了数值的也要扫**，
可能还藏着别的特殊效果。

## 做了什么

### 根因

不在数据 —— `shop_items.json` 里 `bonus` / `bonus_lua` **早就把 13 种全提取好了**
（`tools/shopdata.py:141`）。在展示层：`shopcfg.BONUS_ZH` 只翻了 5 种，
剩下 8 种被一句注释「客户端界面上根本没有它们的格子，说明里也就不提」跳过了。
⇒ 不用重跑 `update-gamedata.bat`、不用动任何 `FORMAT`。

### 逆向（结论全在 §53）

- `GetEquipBonus`（`0x407014`）**14 个调用点逐条对过** —— 13 种属性的算法 /
  概率门 / 单位全部落定。`HeartBoost` 也有 15% 门（`0x522ac0`，原来没人注意）；
  `TeamReflection` 的值是**秒**（`0x50b4ef` 的 `imul x,0x3e8` + 道具 10303）。
- `Critical` 查实是**死属性**：三份 INI 零条、零调用点、flags `0x02` 找不到产生点。
- **全表 1870 件的 id 逐个在代码段里搜 4 字节立即数** —— 硬编码效果只在称号槽，
  查实的只有 `560004`「受击 50% 概率完全免疫」；`560005` / `560006` 有硬编码
  但效果没查明，**故意留白不写「无属性加成」**。
- 提示框实际**只有 2 段**不是 3 段（循环顶部 `cmp i,2`）；换行符引擎认的是
  **字面 `\`+`n`** 不是 U+000A（`Chinese.ini` 官方译文就是这么写的）。

### 改动

| 文件 | 改什么 |
|---|---|
| `server/shopcfg.py` | `BONUS_ZH` + `BONUS_ORDER` + 新增 `SPECIAL_BONUS_ZH` / `DEAD_BONUS_KEYS` / `SPECIAL_EFFECT_BY_ID` / `BONUS_LUA_ZH` / `KIND_USAGE_ZH`；`item_desc_zh()` 拆成 `_weapon_lines` / `_bonus_lines` / `_effect_lines` 三个helper，重写成「压行 + 两段」 |
| `server/web/admin.js` | `paintTip()` 先按 `\|` 分段再按 `\n` 分行（不改就冒裸竖线） |
| `hook/bshook.c` | 新增 `try_patch_dash_visual_guard()`（`0x481EF3`，6 字节），重编 178688 字节 |
| `server/test_shopcfg.py` | 新增 `ItemDescTests` 14 项 |
| `re/packet_api.md` | 三处「最多 3 段」→ 2 段 |

## 结果

- **上架 617 件：从「102 件空说明」变成 0 件空**；能穿能拿的 **725 件一件不空**。
- 武器的**溅射伤害 / 范围**第一次画出来（46 把有溅射的武器，原来完全不显示）。
- 满 5 属性的 **10 件铠甲**不再被截掉「体力」（原来上限 4 行 + 字母序）。
- 全表只有 **2 件**（`220002` / `220006`）会发 `|` ⇒ 分段的风险面极小。
- 两套运行时全量测试 **2939 项都绿**（3.14 / 3.8）。

## 第二轮：三个 exe 写死的称号查到底

用户：「称号我计划将来上架，所以现在需要把说明全都调查清楚写好，避免之后再踩坑。」

| id | 名字 | 查明的效果 | 关键地址 |
|---|---|---|---|
| `560004` | [幸运幸存者] | 受到伤害时 **50%** 概率完全免疫 | `0x480995` 掷 `0.5f` → `0x4809b4 and [esi],0` |
| `560005` | [手下留情] | 开局起伤害翻倍，`新伤害 = min(原伤害×2, 剩余额度)`，额度 45 用完失效 | 发放 `0x49136e`（`GameContext` 虚表槽 `+0xc`）→ 生效 `0x4808cd → 0x50b3bd` |
| `560006` | [红心达人] | 自己捡「心」时 **15%** 概率，同队活着的每人（含自己）各回 5 点 | `0x522a3a` → 座位循环 → `0x493af5(座位, 10315, 5, 我)` |

⇒ **20 个称号一个不落全有说明文**，`title` 收进了「不许空说明」那条护栏。

顺带查实的两件事：

- **`[角色+0x2b4] != 0` = 已死亡** —— 它和当前 HP `[角色+0x150]` 成对写
  （`0x4ffbce`/`0x4ffbd4`、`0x51f695`/`0x51f69f`、复活 `0x503086`）。
  TeamReflection（萤火虫）那道 `0x50b684` 判的是同一件事 ⇒「活着的队友」。
- ★ **两条客户端上行包，服务端没有处理器**（已补进 `re/packet_api.md`）：
  `0x040b`（16 字节，`0x493af5`）—— 青鸟 `220001` **已上架**，实机上大概率
  已经发生过；`0x0415`（4 字节，`0x493b5d`）—— 560005 额度耗尽时发。
  两个都只会在日志里留一行，不会崩；**要不要回点什么没验过**。
