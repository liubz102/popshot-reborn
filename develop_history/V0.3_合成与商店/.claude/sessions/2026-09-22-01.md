# 2026-09-22 会话 01（总第 61）—— 更新源改成服务端下发

## 用户点的题

> 现在的自研更新器，github的仓库地址是写死在代码里的，而且代理地址列表也是写死在
> 客户端更新器的配置文件里的，导致 github 仓库地址变更 / 改了代理后，所有玩家需要
> 手动下载新版，之后第二次以后的更新才生效。
> 我想改成：manifest 获取地址也写到 `config\update.config` 里；这个文件要打进服务器包
> （客户端包里也要有）；更新器跑升级时不读自己本地那份而是从服务端取；先拿 manifest
> 地址和代理，再下 manifest，再从 manifest 拿游戏包地址下载（代理选取逻辑不变）；
> 状态提示里要写清下载的仓库地址；改后立即对所有玩家生效。
> 防倒卖提示不用变。进度写到 `develop_history\V0.3_合成与商店`。

追加的两问：① 服务端 `update.config` 改完要**立即生效、不重启**；
② 云服在 0.4.2，本次发 0.4.3 后老版本玩家怎么走。

四个拍板（AskUserQuestion）：状态行显示**简写**；手动下载地址**三处全写死**；
服务端包和客户端包**共用仓库根那一份**；manifest 地址**不校验**。
后来用户补充：**0.4.3 还没发，本次并进 0.4.3 一起发**（版本号不抬）。

## 做了什么

**方案**（D134 / §130）：`config/update.config` 加一个 `manifest_url = …` 键，
服务端在 `GET /api/update-config` 上原样下发，更新器开工时「本机读一份 → 问服务器
要一份 → 服务器那份压过本机 → 都没有才用编译期内置地址」。测速选源、代理兜底、
保护清单、版本探针**一律没动**。

## ⚠ 审 diff 前先知道：两个 `.ps1` 会显示成「整个文件重写」

`.gitattributes` 写着 `*.ps1 text eol=crlf`（= 仓库里存 LF、检出成 CRLF），
但 `tools/build-portable.ps1` 和 `tools/build-server-package.ps1` 的**已提交 blob 里
是 CRLF** —— 它们是在那条规则之前提交的、从没被重新规范化过
（对照组：`tools/launch.ps1` 的 blob 是干净的 LF）。
一动这两个文件，git 的 clean 过滤器就把工作区的 CRLF 转成 LF 再比，于是**每一行都算改过**。

* 工作区文件本身**仍然是 CRLF + BOM**（铁律 3 要的就是这个），实测没变；
* 提交之后 blob 会变成 LF，这正是 `.gitattributes` 想要的状态，算顺手修好了；
* 真正的改动只有 **17 行**。要看干净的 diff：

```bash
git diff --ignore-cr-at-eol -- tools/build-portable.ps1 tools/build-server-package.ps1
```
