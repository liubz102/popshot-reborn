## 已经答复过、不用再查的

**「合成界面点了不自动加购物车」不是 bug，是原版设计**（§33 ⑥）：
`0x0606` 的载荷是单个 i32，「조합」按钮 push 的是**当前选中那一条**的产物 id
（`0x45d738`）—— 合成一次只处理一件，没有购物车这个概念。
商店那边才有（`0x0602` 是 `i32 n + n×i32`）。

## 给接手会话的六句话

0. ★★ **§31 / §34 是本版最容易再犯的两个坑**：「探针在这个面板上没出现」
   只证明**这个面板**不读，别升成「死字段」；「按名字后缀分组」时那张后缀表
   是**观察到的**词汇不是规范，写完必须反查「有多少件一个后缀都没匹配上」。
1. ★★ **`0x0506` 的 `0` 是「合成成功」**（§33 ①）—— 和 `0x0502` 极性相反
   （那边 0 是「未定义的错误」）。写拒绝路径时兜底**绝不能填 0**。
2. ★★ **合成界面只有 8 个标签，没有武器也没有套装**（§33 ②）。
   往 `recipe.json` 加配方前先问「这个产物玩家点得到吗」。
3. ★★ **等级只有一个数**（§32 / D22）：显示、原版等级门、穿装备判定共用
   `[0x72e338]`。要绕某道门就去 `hook/bshook.c` 的
   `try_patch_player_level_gate()` 加一条，别去抬那个数。
4. **两处顺序都是硬要求**：`0x0501` 定义排在 `0x0500` / `0x0505` / `0x0604` /
   `0x0601` 前面（D20 / §33 ④）；一笔交易的**结果**（`0x0502` / `0x0506`）
   **排最后**（§30 ② / D28）。穿脱那条见 §24：**每一发都要回一发 `0x0604`**。
5. 实机万一界面不对，用控制通道的 `shop-reply off <opcode>` 二分
   （现在管八发：`0500` / `0501` / `0502` / **`0505`** / **`0506`** /
   `0508` / `0601` / `0604`），**不用改代码也不用重启**。
