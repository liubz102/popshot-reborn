## 给接手会话的七句话

-4. ★★ **数据备份（D46 / §40）**：`server/databackup.py` 是数据层，**不许 import
   `web/` 或 `gameserver`**（在线连接那些事留在 `web/admin.py` 的路由里）。四把配置
   锁在 `shopcfg.write_lock()`，加锁顺序只在 `_SPECS` 一处定；拷贝 / 回滚必须持锁
   （Windows 读着文件会挡别人的 `os.replace`）；回滚后必须 `shopcfg.invalidate()`。
   加接口先问它属于哪一档 —— 这一页整页是系统管理员档。

-3. ★★ **设计表在 `server/shopdefaults.py`**（D44 / D49 / D50）：它就是模板 ——
   第一次开服 `ensure_files()` 写出来的、和 `tools/gen_listing.py --apply` 写回
   `server/data/` 的是同一份。改默认数值改那边的表再 `--apply`（写前自动留 `.bak`），
   别手改四份 json 再回头对不上。`--apply` 默认只写 recipe / drops，items / shop
   和磁盘不一样时会跳过并提示（可能被管理页改过），加 `--all` 才覆盖。
   用户在管理页改过配置之后，再跑脚本前先把改动搬回表里。
   `RealDefaultsTests` 钉死了件数（484 / 122 / 52），改表就得改数。
   染色剂 / 突击技 / 宠物是**第一次**发给客户端，实机没验过。

-2. ★★ **管理页的保存已经不是整份覆盖了**（D36）：前台必须把 `base`
   （打开这一页时服务端给的那份**原文**）带回去，商店 / 合成还要带
   `cross_base`。往这条路上加东西时别把它们丢了 —— 丢了就退回「后保存的
   赢」，而且**没有任何报错**。合并逻辑在 `server/cfgmerge.py`（纯函数，
   `test_cfgmerge` 逐条钉）；「读磁盘→合并→写盘」外面那把
   `_config_locks` 也不能省（服务器是 `ThreadingMixIn`）。

-1. ★★ **中文名 / 等级 / 角色限定只有一个出处：`items.json`（物品库）**（D31）。
   要名字走 `shopcfg.name_of()` / `item_name()`，要门槛走 `rule_of()` /
   `item_rule()`。**永远别再往 `shop.json` / `recipe.json` 里加这三个字段** ——
   这个错已经犯过两遍（第一遍是等级和角色，第二遍是名字）。
   前台同理：JS 里查名字一律 `itemName(id)`，别读 `BYID[id].name`。
