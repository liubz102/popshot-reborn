它让「err 该是空的」这条健康检查失效了，已单独开任务收拾。

## ⏳ 待用户验证 —— **一次进游戏，三件事一起验**

先 `start.bat`，登录，**建一个房间**。三段可以按顺序做完再退出。

### ⏳ [M4] 第一段：点开「商店」，看服务端收到了什么

★ **这一段只要点开就行**，界面空着 / 转圈 / 报错都是有效结果 ——
服务端**故意一发都不回**，就是要先看客户端自己会怎么样。

**怎么做**：在大厅或房间里点「商店」按钮（合成、仓库界面也顺便点一下）。

**期望看到**：`logs/server.out` 里出现 `[shop-probe]` 开头的行。
**四发**应当依次是 `0x0704` → `0x0605` → `0x0607` → `0x0700`。

**怎么告诉我**：把 `logs/server.out` 里所有 `[shop-probe]` 的行贴给我
（`logs/online.log` 里也有一份，那份不会被下次启动覆盖）。
再加一句「界面长什么样」（空的 / 转圈 / 崩了 / 有商品）。

### ⏳ [M3] 第二段：穿上装备，属性变没变

**① 血条变长**（100% 生效的加法，最好看）

```bash
python tools/gs_ctl.py equip 1010037 && python tools/gs_ctl.py equip 1020062 && python tools/gs_ctl.py equip 1050037 && python tools/gs_ctl.py equip 1040037 && python tools/gs_ctl.py equip 1030058
```

五件铠甲合计 **HP +29**，泰尔基础 100 ⇒ 开一局血条最大值应当是 **129**。

**② ★ 武器 —— 最不确定的一条**：`0x030b` 里放武器 id，客户端会不会真换枪？

```bash
python tools/gs_ctl.py equip 1120012
```

`리볼버 D2` 伤害 5（基础左轮是 4）。打怪看伤害数字变不变。
**没变也是有效结论** —— 说明武器要走 `0x0604`，M5 的换装设计得改。

### ⏳ [M6] 第三段：结算界面「合成材料」那一栏

**开一局闯关**，进到关卡里（不用打完），然后：

```bash
tools\quest-clear.bat
```

**期望看到**：结算界面左下角「合成材料」那一栏画出材料图标。
（默认 `drops.json` 里关卡 3 难度 1 只有一条 25% 的规则 ——
一次没掉就多跑两次 `quest-clear.bat`，或者选难度 3 打，掉率高得多。
`python tools/gs_ctl.py inv` 可以看材料到底进没进存档。）

**怎么告诉我**：「那一栏画出来了 / 没画出来 / 界面崩了」。
`server.out` 里会有「掉落材料 座位N: …」和「已结算本局：每人各收到 N 份
gspRewardReceived(0x041c…)」两行可以对照。

服务端跑着的时候浏览器开 <http://127.0.0.1:27810/admin>，

**怎么告诉我**：有哪里不好用 / 不好看就说。**顺手把默认口令改掉。**
