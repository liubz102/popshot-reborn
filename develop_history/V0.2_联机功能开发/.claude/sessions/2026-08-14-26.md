# 会话 26 —— 生存模式一队三命耗尽后自动结束

日期：2026-08-14　　接手方：V0.2 会话 26

## 用户报告

> 生存模式，一队的人三条命都死完了，游戏还不会自动结束。一队所有人的三条命都用完了
> 应该要自动结束。

按 `CLAUDE.md` 先接上会话 25：上一轮只修了低等级房主进房后被客户端把模式 0 强制改成
模式 3；§202 / §203 已明确留下“服务端仍对生存房套夺分判据”这个独立缺口。

## 根因与原版规则

旧 `Conn.check_pvp_finished()` 对所有非闯关房都调用
`DeathMatchVictoryCondition` 的三条规则（240 秒 / 杀敌上限 / 只剩一边），从未读取
`arguments[1]`。所以第三条命只改变死亡数，不会触发任何结束条件。

本轮补读原版：

- 工厂 `0x55e0de`：模式 0 / 2 创建 `SurvivalVictoryCondition`，模式 3 才创建
  `DeathMatchVictoryCondition`；
- 构造 `0x55e018`：给每个在座角色写死 3 条命；
- `vf8 0x55db6f`：组队战逐队找“是否至少一名成员仍有生命”，存活队数 ≤1 即结束；
  个人战是存活玩家数 ≤1；淘汰判据之后才检查时间；
- 模式 0 时限 240000 ms，模式 2 同类但为 300000 ms；
- `0x498ef0` 读队伍初始生命减已耗生命，`0x55de78` 明确把个人剩余生命 >0 判为 +1。

完整硬证据写进 **FINDINGS §204**，方案选择写进 **D121**。

## 红灯与验证

先只写回归、未改实现时，定向 45 项稳定出现预期失败：

1. 同一队员环境死亡三次后 `quest.settled` 仍为 `False`；
2. 生存房杀敌数达到夺分上限时 `check_pvp_finished()` 错误返回 `True`；
3. `PVP_SURVIVAL_LIVES` / `survival_finished()` 尚不存在。

修复后：

- 生存 + RoomQuest + 夺分结束 / 结算定向 **46 项全过**；
- `runtime\python\python.exe server\run_tests.py`：**736 项全过**（7.319 秒）；
- 端到端环境击杀保持全场 0 杀敌分：前两死不结算，第 3 死立即给两条连接都下发
  `0x0309 + 0x0411`；尾数组为淘汰队 -1、存活队 +1；
- 四人模型：一名队员生命归 0、同队另一人尚余 1 时不结束，最后一人也归 0 才结束；
- 原夺分杀敌上限 / 时间 / 只剩一边 / 分数排名和闯关不抢结算全部继续通过。
