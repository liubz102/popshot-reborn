# V0.2 会话 46（2026-08-22）—— 自动更新：接管升级分支，旧客户端被拒后全自动升级

动机（用户原话）：版本门禁真机验证时发现，旧客户端连接后弹「运行需要管理者
权限」，确定后自动运行 BsPatcherChn.exe 更新，但更新连的是官方（已停机）
服务器，报「patch中出错」。希望把自动更新重定向到自己的更新源（GitHub），
利用原版自带的升级分支完成自动更新。

## 方案核心（§234 / D155）

客户端升级分支（0x54dbf6 非零结果码 → CNMExecuteNGMPatcherFunc）会拉起
`game_patched\BsPatcherChn.exe` —— **把这个 exe 原地替换成自研更新引导器**
（`tools/updater/updater.c`）：客户端一行不改、bshook 零新 hook、原版 NGM 的
强制 UAC 弹窗和死链报错整条消失。引导器 spawn 包内 Python 跑
`tools/update_client.py` 后立即退出（防死锁），探针问服务器要哪个版本、
从 GitHub manifest 下载全量包、校验、覆盖应用（玩家数据永不覆盖）、提示重启。

用户在方案阶段拍板的关键取舍（详见 D155）：只用 GitHub 托管；只做全量；
触发路径只有「服务器拒绝」一条（不做启动时检查）；manifest 地址硬编码
不新增配置文件；`UserConfig.ini`/`server.config` 更新不覆盖；manifest 生成
幂等（同版本原位替换）；随 0.2.7 重打。用户曾担心 C 盘写权限问题提议走
原版 NGM + hook 改 URL，被论证否掉（hook 管不到子进程 / NGM 协议零逆向 /
原版本就强制 UAC），改为「按需提权」兜底。

## 会话内补丁（用户三点反馈）

1. **版本语义确认**：探针解析到的「服务器要求的版本」= **服务器自身版本**
   （BUILD.ver），不是 ClientFilter 的最低版本（例：服务器 0.2.15 / 最低
   0.2.10 / 客户端 0.2.7 → 解析到 0.2.15）。实现本来就是这么写的；补
   `test_own_version_not_filter_minimum`（两份真实配置文件）钉死，
   `version_reject_message()` 加 `root` 参数方便测试。
2. **自动停本机服务端（用户要求）**：`stop_package_pythons()` —— 等游戏
   退出后，按「exe 完整路径 == 本包 runtime（两份）」精确找到本机服务端
   （app.py）和中继（relay.py）的 python，taskkill 后等退出再应用更新；
   别的 python 一律不碰；更新器自己排除（改名大法兜）。
3. **顺带修的真 bug（改名大法）**：更新器自己跑在
   `runtime\python\python.exe` 里，应用更新覆盖这个文件必被自己锁死 ——
   `copy_with_retry` 对被占目标先重试、再把旧文件改名 `.update_old` 让位
   （Windows 允许改正在运行的 exe 的名），新文件落原名；遗留文件由下次
   更新开头的 `sweep_update_old` 清扫（保护目录不进）。
4. README 用户手改过（自动更新一节并进了「版本号管理」的条目列表）——
   只在该结构内做最小补充，未回退任何手改。

补丁后：test_update 38 项、两套运行时全量各 **1058 项**全绿；
gameserver.py 有改动 → serverCodeHash 变 → 两个包**重新成对重打**
（buildId 换新的一对）。

## 会话内补丁二（真机闪退排查，17:19 用户复测）

用户在 dist 包真机触发：拒绝 → 「直接闪退，没有任何提示」。排查结论
（证据链：本机服务器 online.log 有拒绝记录、bshook 日志到 process detach
为止、无 ★SHELL/弹框记录、`logs\updater.log` 一行都没有）：

- **链路本身是好的** —— 手动跑引导器全通：updater.log 两行、update.log
  走完探针/manifest（GitHub 还没传 Release，404 → 停在错误提示等输入）。
- **闪退根因 = 客户端 CreateProcess 拉起引导器那一步被系统拒绝**（首
  次运行的新编译未签名 exe 被杀软拦下：排查时第一次从 bash 运行同样吃了
  Permission denied，第二次才放行）。客户端对拉起失败一声不吭就退出 →
  玩家看到「窗口全没了」。

三层修复：

1. **update_client.py**：`hold()` 留窗（所有出口，含「已是最新」）；顶层
   `__main__` 兜底捕获一切异常 → 打 traceback + 写 update.log + 留窗；
   server 模块导入失败也有友好提示；探针/manifest/下载全过程**打印
   正在连接的 URL**（用户要求：窗口能看到连了哪、进度、速度）。
2. **updater.c**：经 `cmd /s /c "title … & "<py>" "<script>" … & pause"`
   拉起 —— cmd 拥有控制台、python 继承，**任何退出方式（含 python
   崩溃/没起来）窗口都停在 pause**，永不秒关（无头实测：EOF 下整链
   自动走完，日志齐全）。顺手修 `_snwprintf(args, 2048…)` 写 256 数组
   的隐患。
3. **bshook.c**：钩 CreateProcessW/A + WinExec（升级分支的命令行是一整条
   字符串，像这三个入口；ShellExecute 已有钩）。★PROC 日志记下客户端
   起的每个进程；**拉的是 BsPatcher 且失败时由游戏进程自己弹框**（错误
   码 + 三条出路：手动双击引导器/加白名单/手动下载）—— 更新器自己被杀软
   拦时只有它能开口。

构建侧坑（记录备查）：无控制台环境（bash/PS 直接调 build.bat）跑 cl 会对
bsloader.c 报 C4819/C4474「历史病」症状，但字节级核对产物无损（bsloader
与提交版逐字节同尺寸、中文同为 UTF-8）—— 噪音而已；bshook 新代码以
二进制探测（★PROC×5 / UTF-16 BsPatcher×3）确认入包。

另一坑：17:27 手测留下的 python 停在 input()（本沙箱杀不掉，Stop-Process
拒绝访问），锁着旧 dist 目录的 update.lock —— 改用 `-OutputDirectory
…_b` 打包、zip 改回正式名、update_manifest 重跑（URL 按版本号生成，名字
不匹配有专门警告）。**待用户**：关掉那个残留的更新窗口、删掉
`dist\PopShot-portable-win64_V0-2-7`（旧目录），以 `_b` 目录 / 新 zip 为准。

补丁二后重新成对重打：buildId `20260822-174223`；zip 内 bshook（含
★PROC 钩）/引导器（cmd+pause）/update_client（hold+导入保护）三件
全部验证；1058 项测试仍全绿。

## 会话内补丁三（17:5x 用户复测二：UAC 根因 + 仿原版交互）

用户复测二：bshook 钩子弹了「启动失败」框（钩子起效了）；手动双击
引导器直接弹 UAC。**最终根因 = 文件名 "Patcher" 命中 Windows UAC 安装
程序检测**（无 manifest 的 exe 被自动要求管理员 → 客户端 CreateProcess
必失败；详见 FINDINGS §234 九）。按用户拍板重做成原版交互：

- exe 内嵌 **asInvoker manifest**（updater.manifest）+ **中文名版本资源**
  （updater.rc：「炮炮火枪手 自动更新」，UAC 框显示用）；
- 引导器流程：弹「游戏需要更新。自动更新需要管理员权限，是否允许？」
  → 是 → runas **重跑自己**（--elevated，UAC 显示中文名）→ 提权实例拉
  cmd+python 工作进程 → 否 / UAC 点「否」→ 直接安静退出；
- update_client.py：重启游戏经 explorer.exe 转手拿回普通权限（兜底照
  原版直接启动）；POPSHOT_UPDATER_NOUI=1 测试钩子；
- build.bat：rc 编译 + /MANIFEST:EMBED /MANIFESTINPUT；mt.exe
  -inputresource 验证 RT_MANIFEST 真嵌入；产物三要素（asInvoker /
  同意框文案 / UTF-16 中文名）逐一按字节验证入 zip。

补丁三后重新成对重打：buildId `20260822-180318`，serverCodeHash 与
上一对一致（服务端代码未动）；1058 项测试全绿。**待用户**：真机按新
交互走一遍（同意框 → UAC → 更新窗口 → 下载/应用 → 重启），以及取消
