## 做了什么

### 1. 重复文案 —— 修了，但坑比看上去大

重复来自两处各打一遍：`tools/launch.ps1`（带 `server.config` 的**实际**地址和端口）
和 `start.bat`（硬编码的静态副本）。保留前者、删后者。

删完之后**冒出一个新错误**：

```text
'…行拦腰截断（见' is not recognized as an internal or external command
```

那串东西是我写在 **`rem` 注释**里的文字。查明（**§135**）：`chcp 65001` 下
`cmd.exe` 执行批处理时按**字符**算文件偏移、按**字节** seek，文件里任何多字节字符
都在累积漂移，漂到某处就把后面的命令行从中间劈开。

- 和 CRLF **无关**（全程都是 CRLF + UTF-8 无 BOM）；
- **不限于 `if(...)else(...)` 括号块** —— 先改成 `goto` 标签，顶层 `rem` 照样中招；
- 发不发作取决于**前面累计了多少字节**，所以「原来好好的、只删了几行就炸」很正常。

**定论（D074）**：三个 `.bat` 只允许 ASCII，中文提示全部交给 `.ps1`
（UTF-8 with BOM，整文件读进来再解析，没有这个偏移概念）。
`launch.ps1` 加脚本级 `trap` 负责说「[启动失败] …」。

实机：`start.bat` 跑通、说明只出现一次、无截断；`stop.bat` 正常停 4 个进程。
两个 bat 的 RC=0 / RC=1 分支用 `sed` 替身 + `cmd /c "... <nul"` 非交互跑过。

### 4. 实机验证 —— 单机就把大部分验完了

关键手法（**§145**）：`fakeroom` 造「**没有连接**的房间」，
座位的 `conn=None`，广播时被 `Room.members()` 过滤掉，
所以它只影响列表和座位快照，不会往任何 socket 上发东西。
于是**一台机器一个客户端**就能验完房间列表 + 加入房间 + 聊天。

验过的（截图 05 / 06 / 10 / 11 / 14 / 15）：

- 列表：「组队战 / 무투전 / **待机中(2/6)** / **2号** 对战房」
  → §138 里那两个「⚠ 还没实机确认」全部落定：
  `Session+0x0c` = 当前人数、列表项 u8 = 上限；房间号从 **0** 开始分配（显示 = 值+1）
- 双击进房：三个座位的角色 / 昵称 / 等级 / 「房主」标记 / 人物选择头像全对
- 聊天：客户端发的解析对；广播回去渲染成 `Bob : hello from bob` + 角色头顶气泡
- 系统提示（显示名留空）：`someone joined the room.`，**无「谁 :」前缀**
- 自己建房 → 立刻上列表；`0x0302` 的地图名同步进大厅；退房 → 房间消失

## 意外收获 / 踩到的坑

1. **§144（里程碑 J 的头等线索）**：进房间之后客户端**每 10 秒发两发
   `0x0310 gcpStartTcpRelay`（8 字节）**。战斗还没开始就在要中继通道 ——
   §122 那个「P2P + TCP 中继」的推论第一次有了实测支撑。不回它不影响大厅任何功能。
2. **假房间逼出一个真 bug**：`Lobby._leave_unlocked` 原本按「还剩几条**连接**」
   判房间是否解散，应该按「**座位**还有没有人」。正常游玩时两者等价，
   但语义是错的。已改 + 补回归测试。**测试替身暴露真缺陷，值得记一笔。**
3. **`0x020d gcpReqUserList` 不是用户列表**：处理器 `0x553c5f` 把包里两个字符串
   塞进一个 0x588 字节的弹窗对象。大厅右侧那个「玩家列表」面板的数据源是别的包，
   还没找到。现在回空表客户端照常工作，优先级降低。
4. **两个自动化的坑（§146）**：`click.py` 用客户区坐标而 `screenshot.py` 抓整个窗口
   矩形，差 **(3, 26)**；没做过教程的账号一登录就被拉进教学关，
   跑大厅验证前要先把存档标成 `tutorial_completed`。
