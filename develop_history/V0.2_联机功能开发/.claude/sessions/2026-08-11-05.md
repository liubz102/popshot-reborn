## 2. 用户报的缺陷：模型不跟着消失

**现象**：非房主退房、或者被房主踢出之后，房里剩下的人看到「玩家列表」那一行空了，
但**房间上方蓝天白云那块的 3D 角色模型还杵在原地**。

**根因（§147）**：离开广播发的是 `0x0301` **action 3**。逐条读客户端
`0x40648d` 的分支表才发现：**只有 action 1/2** 会走 `0x406676 → 0x405f8f`
销毁座位的角色对象；**3 走的是 `0x406628`**（「按座位数据重建模型」，
对空座位干脆什么都不做）。V0.1 是按名字猜的，猜错了。

「玩家列表」为什么会正确变空：**所有 action 分支之前**都先把包里的 `SessionSlot`
反序列化进座位（`0x4064d6`），列表是被这一步冲掉的，跟 action 无关。

房主离开那条路为什么看起来是好的：它要转移房主，会**补发一份 `0x0300` 全量快照**，
而 `0x0300` 的处理器里调了 `0x405d8c(1)` —— 对每个不占用的座位调 `0x405f8f`，
顺手把模型收干净了。歪打正着。

**改法（D075）**：`SEAT_ACTION_LEAVE` 3 → **1**；
`build_session_member_update` 那条「action 1/2 绝不能发」的护栏是 V0.1 单人时代的
假设（那时销毁的是「我自己」），现在改成只挡跳表不认的码（0~4 之外）。

## 3. 怎么验的

**第一步（决定性的一发）**：用户说「客户端里现在就能看到这个状态」，于是直接对着
那个鬼影推了一发 `gs_ctl.py raw 0301 010100000000000000000000 --user testuser1`
—— **模型当场消失**，客户端没崩。这一发就把「action 1 到底销不销毁」钉死了，
不用等第二台电脑。

**第二步**：新写了 `tools/fakeclient.py`（§148 / D076）—— 纯 Python 的假客户端，
真 TCP + 真认证 + 真票据，服务端完全当它是正经玩家。于是在**一台电脑上**跑完了：

| 验的 | 结果 |
|---|---|
| bob 进房 | 真客户端看到模型 + 玩家列表 + 「bob 进入了房间。」+ 聊天 |
| bob 退房 | 模型消失、列表空、「bob 离开了房间。」 |
| 房主踢 bob（真的去点了那个 [X] 和「真要强制踢出吗?」）| 模型消失、「bob 被房主请出了房间。」 |
| 反过来：**房主**退房，看假客户端收到的**字节** | `0x0301 action=1 座位=0` → `0x0300 房主座位=1` → 系统提示，顺序内容全对 |
