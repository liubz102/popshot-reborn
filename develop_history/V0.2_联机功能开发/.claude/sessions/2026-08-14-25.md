# 会话 25 —— 生存模式建房后自动变夺分

日期：2026-08-14　　接手方：V0.2 会话 25

## 用户补充的关键现象

> 建房前可以选择生存模式；选择后创建、进入房间，会自动变成夺分模式，之后无法更改。

这说明会话 24 的 §202 只解释了「建房下拉框里有没有这一项」，没有解释
「进房后模式为何被重写」。先按 `CLAUDE.md` 规定读完当前进度，再沿建房 `0x0201`、
房间更新 `0x0302`、服务端回显 `0x0303` 重新取证。

## 根因

### 线日志

`logs/game_001_27799.txt` 两次复现都一样：

1. 客户端建房明确发 `args=(1,0,0)`（模式 0 = 生存）；
2. 服务端立即原样回 `0x0303 args=(1,0,0)`；
3. 客户端进房后的第一发 `0x0302` 仍是 0，服务端仍原样回 0；
4. 约 2.2~2.5 秒后，**客户端主动**发出 `args=(1,3,0)`，服务端才跟着更新为 3。

所以不是建房解析、房间存储或 `0x0303` 组包丢了字段。

### 静态 RE

房间设置回调 `0x465925` 里有会话 24 没读到的第二道门：

```text
地区/语言 == 2
&& 当前模式 == 0（生存）
&& [0x72e338] < 4
&& 我的座位 == 房主座位
=> 0x465a40 把模式强制改成 3（夺分）
=> 0x465c46 发 0x0302
```

中文客户端地区值是 2，玩家是房主；旧服务端对新号下发等级 2，于是稳定命中。
完整指令、日志行号与修复边界写入 **FINDINGS §203**。

## 改动

| 文件 | 改动 |
|---|---|
| `server/account_store.py` | `MINIMUM_PLAYER_LEVEL` **2 → 4**；注释补齐生存模式 `<4` 隐藏门。只改 `player_level()` 的出站兼容值，存档真实等级 / 经验 / 经验条不变 |
| `server/test_account_store.py` | 把原「等级不等于 1」回归强化为：真实存档仍为 1、兼容下限必须为 4、低等级登录包第一个业务 int32 必须为 4；升级到真实 2 级后客户端仍显示兼容下限 |
| `server/test_gameserver.py` | 金币包与控制通道的客户端可见等级期望同步为 4 |
| `.claude/*` | 新增 §203、D120、本会话记录；更新当前批次、测试数和 ⏳ 第 31 条 |

决定记为 **D120**。没有选择「服务端忽略 0→3」：主动切回夺分也是同一个包，无法可靠
区分；客户端本地在发包前也已经显示 3，拒收会让两边状态分叉。没有 patch 客户端二进制，
因为现有的客户端可见等级兼容层已经能最小范围解决。
