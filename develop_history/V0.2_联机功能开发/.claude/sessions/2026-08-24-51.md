# 会话 51（2026-08-24）：bug调查/12 —— 闯关换图之后心形不减、第三次死亡起不来

用户转述玩家实机报（熔岩巨龙 `Quest02`，玩家用自己的本机服务器，
日志在 `bug调查/12/logs`，2026-08-23 23:52 那一局）：

1. 第一张图死一次，右上角剩 2 颗心 —— 对。
2. 换图进 boss 房间再死一次，**应该 1 颗心，实际还是 2 颗**。
3. **在 boss 房间躲墙角被打死后无法复活。**

## 诊断：两个症状是同一个根因

`bug调查/12/logs/server.out` 里三发玩家死亡上报：

```text
23:54:15.104  死亡次数=0  -> 回 0x0406 死亡次数 -> 1        （图 1）
23:55:04.312  换图 -> 'Quest02_2'
23:57:51.649  死亡次数=1  -> 回 0x0406 死亡次数 -> 1   ★ 该是 2
23:58:48.385  死亡次数=1  -> ★★ 一个包都没回
23:59:44.355  对端关闭（卡了 56 秒之后自己退了）
```

**23:57:51 上报的是 1**：换过一张图，客户端的 `[char+0x600]` 还是 1，
根本没归零。而 `RoomQuest.begin_map_change` 一律清空 `death_counts` /
`dead_events` / `last_death_broadcast_at`，依据是注释里想当然的一句
「新角色的 `[char+0x600]` 从 0 起」。于是：

- 换图后第一次死：服务端从 0 重新数 -> 下发 1 -> 客户端把 `[char+0x600]`
  写回 1 -> **心形纹丝不动**；
- 换图后第二次死：客户端报的**还是** 1（上一步的直接后果），
  `(句柄, 报的次数)` 撞上老键 -> 判成重复上报 -> **死亡广播不发** ->
  `Character::Die()` 永远不被调用 -> **人躺着起不来**。

一处错，错两次。

## 静态复核：`0x47900a` 根本不重建角色

反汇编 `re/BigShot_22524.img`（细节见 §241）：换图先把六个座位的角色指针
存进栈上数组，卸完场景后把**同一批指针**原样挂回世界（`0x473e7c`），
还把 `[0x72e2d4]+0x3c` 起的 30 个 dword 按 `max` 合并回去。
客户端是**刻意**让每座位的账目跨图累计的 —— 闯关的三颗心本来就是一整轮的。

## 顺带查明（§241 末节）

闯关的「最大生命」是 `[vc + 座位*4 + 0x198]`，**来自关卡脚本，服务端拿不到**；
只有生存模式那 3 是客户端写死的（`0x55db69`）。所以重生看门狗那道
「还有命才补」的闸不给闯关加（D162）—— 加了就是拿 3 去猜一个未知数。

另外查明客户端有**两个**死亡计数器，都得靠我们的 `0x0406` 喂：
`[char+0x600]` 画心形，`[vc + 座位*0x2c + 0x60]`（`0x48c942` 每收一发 `+1`）
决定还能不能重生。**漏发一发两个都会歪。**

## 追加核查：对合作闯关 / 对战模式的影响（用户追问）

**合作闯关：正是目标场景之一，且已经在测。** `BattleRoom` 夹具本来就是
两人合作闯关房（`session_type=2`，alice 座位 0 + bob 座位 1），前面三条
回归本来就跑在合作房里。又补了一条走**真实 `0x0411` 换图链**的用例
（`test_each_co_op_player_keeps_his_own_death_count`）：两人各死一次 →
换图 → 各再死一次，两边下发的都必须是 2 且互不串（旧行为下红）。
每人一个句柄（座位×100000+100001），`player_handles` 是 句柄 -> 座位 的
字典，天然按座位隔离；「只认本人上报」那道门（D127）没动。

**对战：这段代码根本不执行，净变化为零。** `begin_map_change` 只有两个
调用点 —— `0x0411` 的处理器和调试控制通道的 `nextmap`。对战地图没有
「下一张图」，客户端不会发 `0x0411`。万一真换了图（手搓 `nextmap` 调试）：
旧行为下 `deaths` 会**卡住不增**（`max(1, 1) = 1`），生存模式的三条命
换图后再也扣不掉；新行为下才正确地扣 —— 是更正，不是回归。
夺分 / 计时模式客户端本来就是无限命（`0x55e0d1` 返回 `0x7fffffff`），
和这套计数无关；重生看门狗那道闸没动。

**边界情况逐条核过**：

- 半路进房：`lobby.py` `room.is_playing()` 直接挡回「此房间已开始游戏」
  -> 一局之内座位不会换人，`player_handles` 不可能指到另一个人的角色。
- `RoomQuest` 每局重建（`broadcast_start_game`），计数不跨局残留。
- 怪 / 场景物件那一份照旧全清（新加断言用例
  `test_a_map_change_still_forgets_the_monsters`）。
- 玩家的**过期重复上报**照旧被吃掉 —— `dead_events` 里玩家那几把键也留着。
