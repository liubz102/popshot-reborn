# V0.2 会话 28 —— 反射盾牌远端可见 + 同类道具审计

日期：2026-08-14

## 起点

先完整接续会话 27：当前整合基线为 751 项业务测试，旧发布批次
`20260814-154230`；道具链已经具备 `0x040b` 拾取入槽、`0x040c` 本人扣槽、
`0x040a` 全房效果广播和 `0x040d` 属性结束同步。

用户本次实机反馈的是 **10303 反射**：使用者自己能看到身上闪烁的盾牌，另一个玩家
看不到，但另一个玩家发射的子弹确实会反射。用户同时要求检查其它道具有没有同类问题。

## 定位

服务端路径没有漏包：`Conn.on_use_item()` 已把同一份 `0x040a` 发给房内所有连接；用户
观察到的真实反弹也证明远端角色已经拿到 attr=3。

解壳镜像进一步给出直接证据：

```text
005090e2  call 0x409f7d             ; 取本机座位
005090e7  cmp  [esi+0x2ac],eax      ; 特效目标座位
005090ed  jne  0x5097cd             ; 远端目标直接返回
005090f3  push 0x684b68             ; Item/Reflect/Efx/ReflectMark00.efx
```

本机属性由 AttrList 回调调用 `Character::AddAttrVisual`，远端属性由
`Character::UseItemEffect 0x508e51~0x508e65` 显式调用同一函数；两条路最终都被上面的
座位判定分开。因此根因是原版客户端表现层写死“ReflectMark 只画自己”，不是协议猜错。

完整逆向记录见 **FINDINGS §206**。

## 实现

- `hook/bshook.c` 新增 `try_patch_reflect_visual()`；
- ASProtect 解壳 / 完整性校验窗口之后，比对 `0x5090e2` 起 22 字节完整上下文；
- 只把 `0x5090ed` 的 6 字节 near JNE 换成 6 个 NOP；签名不符拒绝写入并记日志；
- 本机路径原样落入，远端角色从此也执行原版 `ReflectMark00.efx` 创建；
- 10314 全队反射最终同样映射 attr=3，故与 10303 一并修复；决定记为 **D123**。

## 同类道具审计

逐项扫描 `Character::AddAttrVisual` 的属性 1~20 跳表：反射是唯一在角色特效分支里调用
`GetMySeat` 并让远端目标直接返回的属性，没有第二件普通属性道具需要同样 NOP。

其它本机判断保留：

- 减速地雷由一个客户端发创建请求，防止每个观察者重复造世界物件；
- 恶魔效果是受害者自己的 HUD；
- 隐身本来就要让自己与观察者看到不同透明度；
- 三重射击 / 毒药 / 致命射击的弹数耗尽继续走会话 24 的 `0x040d`。

所以本轮确认并修复的同源范围是 **10303 普通反射 + 10314 全队反射**。

## 构建时顺带补回的漏合项

旧 `dist` 当时仍有一套客户端 / 服务端进程在运行，先按项目路径精确停止，避免锁住
`npgl.erl` / `relay.err`。随后冒烟又真实复现 `Path` + `PATH` 让 PowerShell 5.1
`Start-Process` 报 duplicate key。会话 27 / §205 说该问题已经修过，但当前
`tools/build-common.ps1` 实际缺代码；本轮补回 `Repair-ProcessPathCaseCollision` 后，同一宿主
立即完成两包构建和两次冒烟，见 **§207**。
