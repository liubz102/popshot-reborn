# V0.2 会话 16 —— 房主中途退出后剩下的人推不动关卡

日期：2026-08-13
入口：用户实机反馈一条 ——「合作闯关中，房主如果强制退出，剩下的人就无法推进游戏，
走到屏幕最右边也会被屏幕挡住」。

---

## 做了什么

### 1. 逆向：真凶是**怪物 AI 的控制权没交接**（写进 §180）

先排除了最直觉的猜想（「掉线的人留了个鬼影挡路」），然后顺着
`0x0414` 这个包把整条链读到底：

| 查明的 | 地址 |
|---|---|
| 控制者表 = `[GameContext + 0x244 + 句柄类别*4]`，值是座位号 | `GameContext::IsControlledByMe` = `0x491225` |
| 外层包装（怪 / Boss / 刷怪点全用它，**102 个调用点**）| `0x50d61c`（句柄 → 类别 → 比我的座位）|
| 表的初值：按「开局那一刻在座的座位」**轮转**分配，客户端自己算 | `GameContext::vf_04` = `0x48d0fa`（等待房的重写是 `0x494b9f`）|
| **闯关里的怪都在类别 20**（V0.1 实测句柄 1,100,027 → 类别 20）| §161 的 30 段公式 `0x473e65` |
| `0x0414 gspChangeControllerSlot` = **两个 int32（old, new）**，只改类别 20~25 那 6 格，然后逐个通知世界里的对象重算 | 处理器 `0x493780`，反序列化 `0x54cfbf` |
| opcode 是从**战斗包分发表**认出来的（同一张表的 `0x406` 那一格就是 §161 的死亡广播）| `0x493808` |
| `vf_E8` 只被怪 / Boss / 刷怪点重写，全是 `if (IsControlledByMe && flag) 起AI`；基类是 `ret` | `0x4ac2eb` / `0x4effc4` / `0x4ebb68` / `0x5192d5` … |

⇒ 闯关的怪和刷怪点**只由一台客户端模拟**，那台就是「座位号最小的在座玩家」
= 通常的房主。房主一走，表里指着一个空座位，每台机器都算出「不归我」——
**没有人刷怪、没有人跑怪 AI**，关卡的闸门再也不开，人走到屏幕边就被挡住。

顺手确认了两条**否定**结论（免得以后再查）：

- 掉线者的角色**已经被销毁了**：我们发的 `0x0301 action 1` 走
  `0x405f8f` = `World::Remove(句柄)` + 析构，**和 stage 无关**。
- `0x4fc8c7` 那条「全员剩余生命加起来 <= 0 就把位移清 0」的限制和本 bug 无关
  （那是全员生命耗尽的定格），别看错。

### 2. 实现（D103）

| 改了哪 | 内容 |
|---|---|
| `server/gameserver.py` | 新常量 `OP_CHANGE_CONTROLLER_SLOT = 0x0414` / `CONTROLLER_CATEGORY_FIRST` / `CONTROLLER_SLOT_COUNT`；新 `build_change_controller_slot()` |
| `RoomQuest` | 多一份**镜像**控制者表 `controllers`（6 格）+ `assign_controllers()`（照客户端公式）/ `controller_load()` / `handover_controller(..., force=)` |
| `broadcast_start_game` | 建 `RoomQuest` 时带上「这一刻在座的座位」；进 `IN_GAME` 之后**补发**加载途中走掉的人那几发交接 |
| `RoomStartGame` | 多一个 `left_while_loading` + `note_left_while_loading()`（只在 `PREPARING` 记）|
| 新 `Conn.handover_controller_slots()` | 挂在 `after_someone_left()` 上（退房 / 断线 / 被踢 / 顶号共用这一个漏斗）|
| `tools/fakeclient.py` | 收到 `0x0414` 解成人话 |

接管者取「还在座的人里**扛得最少**的那个」（并列取座位号最小），
不是无脑给新房主 —— 六人房里那样会让新房主一台机器跑两倍的怪。

### 3. 验证

- 全量测试 **560 项全过**（534 → 560，净增 26：线格式 / 轮转初值 / 交接替换 /
  最闲优先 / 并列取小 / 走的人不占格就不发 / 没人接就不发 / `force` /
  房主走 / 客人走 / 被踢 / 断线 / 待机房不发 / 结算后不发 /
  三人房大家收到同一发 / 连着走两个人收敛 / 加载途中走人记下并在
  `0x0402` **之后**补发 / 第二局忘掉上一局的记录）
- **真服务端 + 假客户端端到端**（另起端口 47811 / 27999 / 27998，
  不碰用户那台正在跑的服务端）：
  - 房主中途退出 → bob 收到 `0x0414 ★ 控制权交接 座位 0 -> 座位 1`，
    服务端记 `（现在的表 [1, 1, 1, 1, 1, 1]）`
  - carol 在**关卡加载途中**退出 → 加载期间不发，两人加载完之后才补发，
    顺序是 `0x0402` → `0x0414 座位 2 -> 座位 0`
- 重新打了一对发布包，批次 **`20260813-004253`**（两个包的批次号和
  「共用服务端代码」哈希一致；包内 `gameserver.py` 确认带着新代码）。
  本会话**没重编** hook，`bshook.dll` / `bsloader.exe` 还是会话 15 那一对
  （8/12 23:13）。
