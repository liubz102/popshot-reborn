## 一、结算：`0x0411` 改成每座位一份（D101 / §178）

### 先补 RE 依据

D082 当初选「每人只发自己那份」，唯一的理由是
「重复调 `0x4087f0` 安不安全没有 RE 依据」。这次把三处重复投递全读到底：

| 被重复调的 | 结论 |
|---|---|
| `0x4a4096` | 纯按包里的座位号 `imul 0x34` + `rep movsd 13` 写 —— 各写各的，正是我们要的 |
| 四个全局 | `0x5518b9 cmp 我的座位 / jne` 护着，别人那份走不到，钱不会串 |
| `0x4913fc` | 第一句 `cmp byte [esi+4],0 / jne 函数尾` —— 第二发起整个函数空转 |
| `0x4087f0` | ★ `0x55bc5f` 是 **swap** 不是 copy：把 `GameSession+0x404` 的累计伤害换进一个刚构造的空对象，发成 `0x0505` 再析构。**第二发起送的是空表**，不重复计数、不动别的状态 |

顺带查清两件事：

- 结算界面画每一行时（`0x4a4b45`）是**当场**去读那 13 个 dword，
  不是弹窗时快照的 ⇒ 「自己那份先发、队友那几份随后补」补得进去；
- 「生命」那一格（`vft+0xa4` = `0x49c386`）算的是
  「允许死亡次数 − 本机角色的已死次数」，**和 `0x0411` 无关** ——
  所以 `0 / 3` 里的 `3` 一直是对的，缺的只有分数。

### 改了什么

- `server/gameserver.py`：新增 `end_game_order(my_seat, seats)`；
  `send_end_game()` 下发时 `0x0411` 每座位一份，**自己那份排第一**
  （弹结算界面的是第一发，时序要和 V0.1 单人版一致）。
- `server/test_battle.py`：把钉住旧行为的
  `test_each_client_only_gets_its_own_end_game` 换成三条新用例
  （每座位一份 / 自己那份在最前 / 每一份带的是那个座位自己的分数），
  对战那条 `test_the_round_is_only_settled_once` 的断言从「1 发」
  改成「座位集合 == {0,1}」（结算两次就会变成 4 发）。
- **单机一个字节没变**（`settlement_seats()` 只有一个座位）。

**验证**：全量 **534 项全过**；两个假客户端真跑一局 ——
alice(座位0) 收 `0x0411 座位=0 → 座位=1`，bob(座位1) 收 `座位=1 → 座位=0`，
服务端记 `每人各收到 2 份 0x0309 + 2 份 0x0411（自己那份在最前）`。

## 二、GameGuard 概率性启动失败（D102 / §179）

### 找真凶

用户发回来的日志里没有报错那一次的（`bshook_*.log` 只有成功那次），
但**成功那次的日志本身就把race暴露了**：

```text
[22:14:44.539] DllMain
[22:14:47.851] HOOK  主模块范围 …          ← patch_thread 第一行
[22:14:47.851] HWBP  …（0 ms / 0 轮）已武装 ← 武装线程第一行
[22:14:47.867] MODULE base=…               ← watch_thread 第一行
[22:14:50.017] HWBP  ★DR0 命中
```

三条 `CreateThread(DllMain)` 出来的线程第一行日志**一起卡在注入后 3.3 秒**
（加载器锁），而 GameGuard 校验在那之后只有 **2.2 秒**就执行了。
`0 ms / 0 轮` 说明武装线程根本不是在等解壳，是在**等被调度**。
余量由别人机器的锁竞争决定 ⇒ 「有概率报错，重启就好」。
（`start` / `start-debug` 的差别只是 `BSHOOK_VERBOSE_LOG`，
它改变 I/O 量和线程时序 —— 「debug 不复现」是巧合，不是线索。）

本机复测同一版代码：这个延迟是 **844 / 875 毫秒**。同样的race，只是没输过。

### 改了什么

**`hook/gg_bypass.h`**：把 `0x54b0fc` 那 5 个字节的两种已知明文提上来两边共用，
新增四个命名事件的契约（INJECTED / READY / HIT / FAILED）+ `BSHOOK_GG_RETRY` +
外部轮询间隔 + 最多重来次数。

**`hook/bsloader.c`**（大改）：

- 等 `INJECTED`（DllMain 装完 VEH 就置位，不用等锁）→
  每 2ms `ReadProcessMemory(0x54b0fc)` 认签名 → `SuspendThread + SetThreadContext`
  **从进程外武装并守护 DR0**，直到 `READY`（DLL 接管）或 `HIT`。
- 整个启动包在一个尝试循环里：收到 `FAILED`、或进程在 `HIT` 之前就退出
  ⇒ 杀掉重来，最多 3 次；前几次传 `BSHOOK_GG_RETRY=1`。
- `setvbuf(_IONBF)` —— 不然 `logs\bsloader.out` 在进程活着时是空的，
  正好在最需要它的时候没有。

**`hook/bshook.c`**：

- DllMain 里置位 `INJECTED`（**必须在 `AddVectoredExceptionHandler` 成功之后**）；
- VEH 命中时**就地**置位 `HIT`（别指望被锁压着的 `watch_thread` 去报）；
- 武装线程认得「断点在我跑起来之前就已命中」（`ensure_gameguard_breakpoint`
  返回 3）—— 旧代码会空转到 13 秒预算耗尽再「兜底武装」，摆回一个永不撤销的断点；
- 武装线程开头打一行「DllMain 之后 N ms」，把加载器锁的延迟变成可观测量；
- `MessageBoxW/A` 的 detour 认出 `Game`+`Guard` 字样且 DR0 没命中过
  ⇒ 置位 `FAILED`；还能重来就**吃掉这个框**，最后一次照常弹。

**`hook/build.bat`**：它自己中了 §135 的招 —— 中文注释把**第二条** `cl`
命令行截断了（控制台先冒一句 `'链' is not recognized`）。按 D074 改成纯 ASCII。

### 验证（本机）

- **真客户端冷启动跑通**：
  `[bsloader] 目标已解壳，已从进程外武装 DR0（注入后 406 ms）` +
  `外部守护期间补写 DR0 1 次`（**壳真的清过一次**）；
  DLL 那条线程 875 ms 才被调度到，日志写
  `已武装（bsloader 已提前武装，这里只是接管守护）` → `DR0 命中` →
  `LOGIN 登录框已改造`。**提前了 469 毫秒**。
- `hook\test-watchdog.bat` **PASS**，日志里仍有
  `!! DR0 被清掉了…已补回（第 1 次）`（夹具已改成先等 DLL 的 READY 握手，
  否则会把 bsloader 的外部守护误测成 DLL 的守护）。
- **新增 `hook\test-retry.bat`** 并 **PASS**（完全非交互）：
  `GG-RETRY 2/3` → `GG-RETRY 3/3` → `GG-GIVEUP`，
  前两次 DLL 日志里有 `★★ GameGuard 绕过失败…` + `先吃掉这个框`。
