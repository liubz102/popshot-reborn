## 二、逐指令查明（§224）

`re\BigShot_22524.img` + capstone。

1. **玩家看见的数字是什么。** `0x497531` 那一段：`0x404ff6(座位)` 取角色 →
   `mov ebx,[eax+0x604]`（杀敌数）+ `vf(+0xc0)`（死亡数 `[char+0x600]`）→
   `0x5be248` 画出来。**HUD 每帧重读 `[char+0x604]`。**
2. **谁改 `[char+0x604]`。** 全镜像只有三处：构造函数 `0x4fb5fc` 清零、
   `Character::OnKill`（`0x506e8c`，`inc`）、
   `Character::OnSuicide`（`0x506eba`，`dec`，**且开头 `test ecx,ecx / jle`
   —— 已经是 0 就整个函数不做事**）。
3. **两个函数都顺手改胜负判据。** 两处都
   `mov ecx,[0x72e2dc] / call [eax+0x100]`，参数是 `(座位, ±1)`。
   槽 `+0x100`（基类表 `0x670b4c`，实现 `0x493d5c`）→ `0x48c98f`：
   `[victory + 座位*0x2c + 0x5c] += 增量`。
   而 `DeathMatchVictoryCondition::vf8`（`0x55bf20`）第 ② 条比的正是这一格
   （`lea edi,[esi+0x5c]` / 每次 `add edi,0x2c` / `cmp [edi], vf(+0x24)`）。
   ⇒ **「玩家看见的」和「客户端自己的判据」永远是同一个数。**
4. **谁调 OnKill / OnSuicide。** 两个的调用点都只有一处，都在
   `Character::Die`（`0x4ffbb7`，`Character` 虚表 `0x6846fc` 槽 `+0xdc`；
   `MyCharacter` `0x687034` 没覆盖）。而 `Character::Die` 的唯一触发点是
   **服务端下发的 `0x0406` 死亡广播**（处理器 `0x4938d2` 末尾 `call [vft+0xdc]`，
   参数就是包里 `+0x05` 那个「凶手」字节）。三选一：

   ```text
   004ffe81  call 0x404ff6        ; 凶手座位 -> 角色；座位没人(0x4045f9)就是 NULL
   004fff15  cmp [ebp+8],[ebp-0x28] / jne 0x500165   ; 凶手 == 受害者？
   004fff28  call 0x506eba                            ; ★ 自杀 -> -1
   00500165  call 0x409df1([0x72e29c]+0x18) / cmp 1   ; 是不是组队战
   0050017a  cmp esi,[ebp-0x48] / jne 0x500403        ; 队伍号（0x40462c）不同？
   00500183  call 0x506eba                            ; ★ 同队 -> -1
   00500951  call 0x506e8c                            ; 其余 -> +1
   ```

5. **顺带排掉的岔路**：
   - 「HUD 是不是靠 `0x0415` 喂的」—— 不是。`0x0415` 处理器 `0x4a3efe`
     写的是 `[ctx+座位*4+0x3b8]` 和 `[victory+座位*0x2c+0x7c]`，
     和夺分比的 `+0x5c` **不是同一格**；而且对战里客户端从不发 `0x0410`。
   - 「打死怪算不算杀敌」—— 不算。扫过全部 vftable，`+0xdc` 等于
     `0x4ffbb7` 的只有 `Character` / `MyCharacter` 两张。
   - 「凶手 0xff（怪 / 环境）」—— `movsx` 成 -1，`0x4045f9` 判负直接返 0
     → 角色指针 NULL → 加扣都不做。

⇒ 结论一句话：**服务端只会「+1 或不动」，客户端还会「-1」。**
座位 1 自杀那一次，屏幕上是 `6 - 1 = 5`，服务端数的是 6。

## 三、修了什么（D145）

`server/gameserver.py`：

- `RoomQuest.record_kill(killer, victim, *, teams=None, team_mode=False)`
  照抄上面那三条，返回值从 `bool` 改成 **`+1 / -1 / 0`**；
  扣分**下限 0**（对齐 `0x506eba` 的 `jle`）；
  `teams` 里没有凶手座位 = 凶手已退房 → 一分不动（对齐 `0x404ff6` 返回 NULL）。
- 新增 `Conn.battle_teams()` → `(队伍表, 是不是组队战)`，房间不存在时返回
  `(None, False)`（协议试探那条路照走老行为）。`check_pvp_finished` 也改用它，
  少一份重复代码。
- `on_report_hp_zero` 的记分日志改成
  `对战计分: 座位 N 杀敌数 +1 -> M` / `…… -1（自杀 / 杀队友要扣分，§224）-> M`。

★ **组队判定必须先问 `team_mode`**：个人战里 `lobby.default_team` 给所有人
发 0（为的是不越界写客户端那两格队伍数组），不分模式地比队伍号会把
**每一发击杀**都当成杀队友，一整局谁都涨不了分。
`test_a_free_for_all_kill_is_never_treated_as_a_team_kill` 把这条钉死。
