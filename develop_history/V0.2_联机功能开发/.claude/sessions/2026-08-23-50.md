# 会话 50（2026-08-23）：自动更新真机首测的两处修复

用户把 V0.2.7 传上 GitHub Release，本地测试包（`dist\PopShot-port
able-win64_V0-2-7_带服务器设置`，BUILD.ver 改 0.2.6）真机触发自动更新。
下载/校验正常，两个问题：

1. 更新中「全部」条在动、「**目前**」条全程空；
2. 下载完成后报失败「本机服务端进程结束不了」。

## 诊断

失败现场的 `logs\updater.log`（01:16 那次跑）显示两个包内 python 都被
找到并树杀，5 秒后仍判「停不掉」—— 杀对了，**判定名单错了**：

- **第一层**：`procs_stop_package_pythons` 旧代码把按名字搜到的**全部**
  python.exe（含被路径核验跳过的）拿去做存活判定 + wait_gone。机器上有
  任何别的 python.exe 存活 → 永远等不满 → 误报。
- **第二层**（修掉第一层后 e2e 立刻揭出）：树收养按 ppid 收成员，而带
  控制台的 python（`CREATE_NO_WINDOW` / 新开窗口的 start）有 **conhost.exe
  子进程**（PowerShell Win32_Process 实测确认）—— 保护进程，杀必
  ACCESS_DENIED → 进名单又是误报。PID 复用导致的错收养同理。

## 追加调查：没关的 start.bat 窗口（用户追问，结论 §237）

用户问：结束旧进程时 start.bat 的黑窗口没关怎么办。逐环节查清并实测：

- `launch.ps1` 起完一切就退出（不等游戏）；cmd 停在无条件 `pause` 攥着
  start.bat 句柄 + 包根 CWD，整个游玩期间都在。
- ★ 实测（Win10 19045）：被运行中 cmd 攥着的 .bat **可以直接
  MoveFileExW(REPLACE_EXISTING) 覆盖成功**（cmd 带 FILE_SHARE_DELETE
  打开批处理）→ 停在 pause 的窗口**不挡 apply**。Win7 未实测（有
  重试 + 改名让位 + 明确报错兜底）。
- bsloader 等游戏句柄 INFINITE；游戏被更新器强杀时 hit 早已置位 →
  判 ATTEMPT_OK 自退，不会触发 GG-RETRY 复活游戏。
- 净效果：只留一个停在 pause 的旧窗口，按任意键即消，无功能影响。
- 建议（未实施，等用户拍板，§237.4）：三个 bat 的 pause 改成只在
  失败时停，成功路径窗口自动关，下个版本起更新时天然无旧窗口。

## 第二轮：真机二连踩 + 取消重做（§238 / D160）

用户用第一轮修复版重测：依旧「结束不了」+ 取消无反应。

1. **误报真因**：python 实际杀掉了；`procs_pid_alive` 把 OpenProcess 的
   INVALID_PARAMETER（pid 已失效）也当「活着」。launch.ps1 起的服务端
   爹死透、无人攥句柄 → 必踩；e2e 假阴性（测试自己攥句柄）。修：
   KillTarget 攥句柄等 signaled + 错误码区分 + e2e 改无人攥句柄形态

2. **取消**：用户两次反馈 + 最终拍板「纯计时器、不看数据」。走过弯路：
   0.5s 接收超时会毒化慢速下载（>0.5s 到货间隙 → ReadData 12019），
   弃。终版：看门狗线程 200ms 无条件查取消 + Close 句柄撬开阻塞读；
   停进程两阶段挂 `procs_set_cancel_probe` 同样可取消。
3. **新夹具** `updater\scripts\test_cancel_ui.py`：真窗口三场景（原生
   UIA 真鼠标 / IE 固定坐标双击 / 断流挂死）全绿 —— IE 页内按钮链路
   首次端到端验证。
4. 顺带查明不改：强杀更新器留 update.lock（600s 内「已在运行」）；
   package_root 只认 exe 路径（测试必须用沙箱内拷贝）。
5. 新 exe 同步两份 dist 0.2.6 沙箱；未动 git。
