# V0.2 会话 45（2026-08-22）—— 版本号管理 + 最低客户端版本门禁全链路落地

动机（用户原话的痛点）：每次遇到 bug 拿到别人的 log，里面看不出他正在用的
版本，有时去问才发现是旧版本。决定给复活项目立自己的版本号体系：
打包带版本、客户端上报版本、服务端记版本 + 按最低版本拒绝旧客户端。

## 方案核心（§233 / D154）

客户端连游戏服时裸发的 int32 版本号 311 硬编码在 `0x54d98f` 的指令立即数里。
bshook 启动时读包根 `BUILD.ver` 把这 4 字节补丁成编码后的复活版本号 ——
**协议流布局一个位都不动**（SimpleCipher 是有状态流密码，追加任何字节都会
让流错位；补丁立即数则完全无感），中继纯字节转发天然透明，auth 通道不用碰。

编码：`major*1e6 + minor*1e3 + patch`（0.2.7 → 2007），Python / C / PowerShell
三处实现一致；保留值 311、编码下限 1000（原版小版本区间），打包时校验拒绝。

## 用户拍板的两件事

- **BUILD.ver 保留构建元数据**（buildId / 代码哈希 / 成对警告）—— D079 的
  成对核对能力不能丢；
- **初始值 0.2.7 / 0.2.7**：下一个带版本上报的包按 0.2.7 重发、门禁同时生效，
  现有已发出的（无版本上报）旧包全部会被要求升级 —— 用户明确要这个效果。

## 逆向新证据（§233 第一节）

`0x54d98f` 的完整序言从 `re/BigShot_6852.img` 提取；`c7 45 f0 37 01 00 00`
在两份脱壳镜像里**全镜像唯一**；同场确认 `[edi+0x898]=1`（连接状态）和
cipher 虚调用 `ff 50 08` 的位置 —— 补丁点选在立即数上是有字节级依据的。

## 验证

- 两套运行时全量各 **1020 项**全绿（979 基线 + test_versioning 17 +
  test_online VersionGateTests 8）。测试写真 `feed()` 加密流时踩了一个坑：
  同一个 SimpleCipher 实例先 encrypt 再 decrypt 会把状态推两次，必须两个
  同初值实例各管一边（真实链路本来就是两端各一份）；
- `hook\build.bat` 重编译零告警（bsloader.c 的历史告警与本次无关）；
- 两个包试打成功（`dist\PopShot-server_V0-2-7` 56.9 MiB、
  `dist\PopShot-portable-win64_V0-2-7` 410.1 MiB），冒烟自检全过；包根
  BUILD.ver（UTF-8 无 BOM、version 首键）+ server-ClientFilter.config 就位，
  无 BUILD.txt；包内 bshook.dll 与新编译哈希一致；用 Python 模拟 bshook 的
  C 解析视角从真实 BUILD.ver 里解出 `V0.2.7`；
- 打包出的服务端真启动过一次，横幅正确打出「版本门禁: 仅允许 V0.2.7 及以上」。

## 没验的（进待验证表 50~52）

1. **真客户端的升级弹框**：握手非零结果码 → 「再读一个 wstring + 弹框」这条
   分支逆向确认过但从未真机触发，弹框长相 / 我们传的文案显不显示都要实机看；
   兜底层已保证最坏也只是不显示提示，旧客户端一定进不了大厅；
2. bshook 真机读 BUILD.ver + 补丁 + 上报（日志应有
   `PATCH BUILD.ver 版本 V0.2.7 -> 握手版本号 2007`）；
3. 门禁热重载的真服务器场景（单测已覆盖逻辑）。

## 发版流程（从今往后）

改 `tools\build-ver.config` → `tools\build.bat` → 两个带版本号的新目录/压缩包。
hook 不用重编，服务端代码不用动；`server-ClientFilter.config` 想收紧/放松，
改服务器上那份即可，下一条连接生效，不用重启。

## 追记（同日）：启动横幅带版本号

用户补充需求：启动窗口第一行就要看到版本。三处横幅全部加上：

- `tools/launch.ps1`（客户端包 start.bat）：版本解析块从环境自检段**挪到横幅前**，
  并新增「发布包」分支 —— 没有 build-ver.config 时直接读包根 BUILD.ver 的
  `"version"` 显示。开发机输出：
  `=== 炮炮火枪手 V0.2.7 —— 启动（日志模式：normal）===`；
  版本缺失时回退无版本横幅 + 原有的黄字警告；
- `tools/server-package/serverctl.ps1`（服务端包 Windows）：start 横幅读包根
  BUILD.ver → `=== 炮炮火枪手服务端 V0.2.7 —— 启动（日志模式：…）===`；
- `tools/server-package/serverctl.sh`（Linux 侧）：同上，POSIX grep/sed 取值。

三个解析都只认第一个 `"version"` 键（和 bshook 的 C 解析同一个契约）。
已实测：sh 管道 / PS 正则对真实包内 BUILD.ver 都解出 `V0.2.7`；开发机分支
逐字复刻脚本代码跑通（横幅正确、BUILD.ver 生成正确、测试后已清理）。
serverctl.sh 保持 LF 无 CR。start-debug 横幅走同一段代码自动带版本；
stop 横幅保持原样（用户只要求启动横幅）。
